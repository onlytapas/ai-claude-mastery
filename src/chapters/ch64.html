Installing Claude Code takes one command, and signing in takes one browser click. The part most people skip is understanding what was set up: which install method, which account, which kind of credential. That knowledge is what lets you fix problems, set up a colleague's laptop, and explain to your security team how it works. If someone else installed Claude Code for you, this chapter shows you how to find out exactly what they did.

64.2Choosing an install method

There are several ways to install. They put the same program on your computer; they differ in how it gets updated.

MethodCommandUpdates
Native installer (recommended) · macOS, Linux, WSLcurl -fsSL https://claude.ai/install.sh | bashAutomatic, in the background
Native installer · Windows PowerShellirm https://claude.ai/install.ps1 | iexAutomatic
Native installer · Windows CMDcurl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmdAutomatic
Homebrew · macOS/Linuxbrew install --cask claude-codeManual: brew upgrade claude-code
WinGet · Windowswinget install Anthropic.ClaudeCodeManual: winget upgrade Anthropic.ClaudeCode
npm · any OS with Node.js 22+npm install -g @anthropic-ai/claude-codeManual: npm install -g @anthropic-ai/claude-code@latest
Linux packagesSigned apt, dnf and apk repositories (exact commands on the setup page)Through your package manager

The native installer is recommended because it keeps itself up to date. Pick Homebrew or WinGet if your company manages software that way. Use npm only if you already use Node.js and know why you want it.

In everyday life

Think of buying a phone app. The native installer is like downloading from the app store with automatic updates turned on. Homebrew, WinGet and npm are like getting the app from a company software portal: it works the same, but you (or IT) decide when to update.

What the command actually does

macOS / Linux, read left to right
curl -fsSL https://claude.ai/install.sh | bash
#  curl            download something from the internet
#  -fsSL           f: fail on errors, s: silent, S: but show errors, L: follow redirects
#  https://...     the install script's address
#  |               "pipe": hand the downloaded script to the next program
#  bash            run the script

Running a script straight from the internet is common, but it means trusting the source. That's why the address must be exactly https://claude.ai/install.sh. If you're unsure, download the script first and read it, or ask IT. Chapter 55 explains pipes in detail.

Where the native installer puts things

On macOS and Linux, the native install places the launcher at ~/.local/bin/claude and keeps downloaded versions in ~/.local/share/claude/versions/. The ~ means your home folder (Chapter 53). For the claude command to work, ~/.local/bin must be on your PATH, the list of folders your shell searches for commands (Chapter 56). The installer normally takes care of this; if you see "command not found", it didn't, or your terminal needs restarting.

You can install a specific channel or version with the native installer, for example curl -fsSL https://claude.ai/install.sh | bash -s stable. The CLI also has its own claude install subcommand, which installs the native build and accepts stable, latest or a version number. It's useful for switching an npm install to the native one.

64.3Check it worked

Terminal
claude --version     # prints the version, e.g. 2.1.319 (Claude Code)
claude doctor        # health check: install method, updates, settings problems

claude doctor runs from your normal shell and only reads; it's the first thing to try if Claude Code won't start. Inside a running session there's also /doctor, a fuller checkup that can offer to fix problems. They're different things: one is a CLI command, the other a bundled skill you type inside Claude Code.

Windows: two common mix-ups

If you see irm is not recognized, you're in CMD but used the PowerShell command. If you see The token '&&' is not a valid statement separator, you're in PowerShell but used the CMD command. Use the command that matches your shell.

64.4Updates and update channels

  • Native installs update themselves in the background. Homebrew, WinGet and Linux package installs don't; upgrade them with their own tools.
  • Update by hand any time with claude update (also claude upgrade).
  • Two channels: latest (the default, newest features) and stable (about a week behind, skipping releases with major problems). Choose in /config → Auto-update channel, or with the autoUpdatesChannel setting.
  • Turning updates off: the environment variable DISABLE_AUTOUPDATER=1 stops background updates only; DISABLE_UPDATES=1 blocks all updates. Companies sometimes set these so everyone runs an approved version.
Real-world example

A QA team pins everyone to the stable channel so a new release can't change behaviour in the middle of a regression cycle. One engineer stays on latest to try new features first and reports back. It's the same idea as testing a browser beta before rolling it out.

64.5Signing in: the options

Claude Code needs to know who's paying for the model. There are several ways to prove that, called credentials:

OptionWho it's forHow
Claude subscription (Pro, Max, Ultra, Team, Enterprise)Most people, including most company usersRun claude and follow the browser sign-in; or /login inside a session, or claude auth login
Claude Console (pay per use)Developers and teams billed through the APIclaude auth login --console. An admin must invite you.
API keyScripts and some developer setupsSet the environment variable ANTHROPIC_API_KEY
Long-lived tokenCI pipelines using a subscriptionclaude setup-token prints a one-year token; store it as CLAUDE_CODE_OAUTH_TOKEN
Amazon BedrockCompanies that buy AI through AWSCLAUDE_CODE_USE_BEDROCK=1 plus AWS credentials; /setup-bedrock wizard
Google Cloud's Agent Platform (formerly Vertex AI)Companies on Google CloudCLAUDE_CODE_USE_VERTEX=1 plus Google Cloud credentials; /setup-vertex wizard
Microsoft FoundryCompanies on AzureCLAUDE_CODE_USE_FOUNDRY=1 plus Azure credentials
Gateway / bearer tokenCompanies routing traffic through their own gatewayANTHROPIC_AUTH_TOKEN, often with ANTHROPIC_BASE_URL

If you signed in with a company email and a browser window, you're almost certainly using a Team or Enterprise subscription, possibly through your company's single sign-on.

The subscription sign-in, step by step

Runclaude in a terminal (or open the VS Code panel)
Choose"Claude account with subscription" at the prompt
BrowserA sign-in page opens. If it doesn't, press c to copy the address and paste it into a browser.
ApproveSign in (company SSO if your organisation uses it) and approve access
DoneClaude Code stores the credential securely and you're in

The credential is stored in the macOS Keychain on a Mac, or in ~/.claude/.credentials.json (readable only by you) on Linux, and %USERPROFILE%\.claude\.credentials.json on Windows. You'll be warned three days before a login expires. When it does, run /login.

The claude auth commands

Terminal
claude auth status            # who am I signed in as, and how?
claude auth status --json     # the same, as JSON (handy for scripts)
claude auth login             # sign in (add --console for Console billing, --sso for SSO)
claude auth logout            # sign out
Which credential wins when there are several?

A machine can have more than one credential at once, for example a subscription login and an old ANTHROPIC_API_KEY in your shell profile. Claude Code picks one in this order:

  1. Cloud-provider settings (CLAUDE_CODE_USE_BEDROCK, _VERTEX, _FOUNDRY)
  2. ANTHROPIC_AUTH_TOKEN
  3. ANTHROPIC_API_KEY
  4. An apiKeyHelper script set in settings
  5. CLAUDE_CODE_OAUTH_TOKEN (from claude setup-token)
  6. Your /login subscription sign-in

Your normal subscription login is last. Anything higher in the list overrides it. In an interactive session Claude Code asks you once to approve an API key it finds; in print mode (-p) it always uses it. /status shows which credential is active right now.

The API-key trap

A very common surprise: you have a perfectly good company subscription, but Claude Code says something like "This organization has been disabled" or bills a personal account. The cause is usually an old ANTHROPIC_API_KEY left in your shell profile from an earlier experiment, which overrides your subscription. Fix it with unset ANTHROPIC_API_KEY, then remove the line from your shell profile file (for Zsh, ~/.zshrc). Chapter 98 covers keys and tokens in depth.

64.6Detective work: how was my machine set up?

If a colleague installed Claude Code for you, these commands reveal what they did. All of them only read; none change anything.

QuestionCommandHow to read the answer
Where is it installed?which claude~/.local/bin/claude → native installer. A path with homebrew or Caskroom → Homebrew. A path containing node or npm → npm. Nothing printed → not on your PATH.
Which version?claude --versionA number such as 2.1.319. Compare with the latest release notes.
Is it healthy, and how does it update?claude doctorInstall method, update status and any settings problems
Who am I signed in as?claude auth status or /status in a sessionAccount email, organisation and login method (subscription, Console, API key, cloud provider)
Is an API key set in my shell?echo $ANTHROPIC_API_KEY (macOS/Linux)Blank = not set (good, if you use a subscription). Any text = a key is set. Don't paste it anywhere.
What personal configuration exists?ls -la ~/.claudeLook for settings.json, CLAUDE.md, skills/, agents/, projects/
What do my settings say?/config in a session, or open ~/.claude/settings.jsonModel, permissions, environment variables, hooks (Chapter 78)
Real-world example: what a typical audit finds

Running these on a tester's laptop typically shows something like this: which claude → /Users/sam/.local/bin/claude (native installer, auto-updating); claude auth status → signed in with the company account on a Team plan; ~/.claude/settings.json → a few permission rules a colleague added, such as always allowing npm test. That's three facts, and Sam can now explain the setup to anyone.

64.7Using Claude Code inside VS Code and JetBrains

  • VS Code: install the extension anthropic.claude-code from the marketplace (VS Code 1.94 or later; it also works in Cursor). The extension includes its own copy of Claude Code for its panel, but to type claude in VS Code's terminal you also need the standalone install from 61.2.
  • JetBrains (IntelliJ IDEA, PyCharm, WebStorm and others): install the "Claude Code" plugin from the JetBrains Marketplace and the CLI. The plugin doesn't include the CLI.

Both use the same sign-in and the same ~/.claude settings as the terminal. Chapter 70 covers the editor integrations in depth.

64.8At work: proxies, certificates and managed settings

  • Proxies: if your company routes internet traffic through a proxy, set HTTPS_PROXY (and HTTP_PROXY) in your environment. Errors such as unable to get local issuer certificate usually mean the company's security certificate needs configuring; ask IT, and see the network-config page in the docs.
  • Managed settings: IT can push settings that you can't override, such as allowed models, permission rules or approved MCP servers (Chapters 78 and 105). If a setting won't change, this is probably why.
  • Several accounts: to keep a personal and a work setup apart, run Claude Code with a different configuration folder, for example alias claude-work='CLAUDE_CONFIG_DIR=~/.claude-work claude'.

64.9Uninstalling

For a native install on macOS or Linux:

Terminal
rm -f ~/.local/bin/claude          # remove the launcher
rm -rf ~/.local/share/claude       # remove downloaded versions

For other methods, use the same tool you installed with (for example brew uninstall --cask claude-code). Your settings and history in ~/.claude stay unless you delete that folder too. rm -rf deletes permanently with no recycle bin, so double-check what you type (Chapter 54).

Audit your own install25 min · terminal
  1. Open a terminal (in VS Code: Ctrl+`). Run which claude and claude --version.an install path and a version number. Decide from 61.6 which install method was used.
  2. Run claude doctor.a health report including the install type and update status. Note any warnings.
  3. Run claude auth status.your account and login method. If it says API key when you expected a subscription, go back to the API-key trap in 61.5.
  4. Run echo $ANTHROPIC_API_KEY (macOS/Linux) or echo $env:ANTHROPIC_API_KEY (PowerShell).a blank line if you use a subscription. If a key appears, don't share it; decide whether it should be there.
  5. Run ls -la ~/.claude, then start Claude Code and ask: "Explain everything in my ~/.claude/settings.json in plain English. Don't change anything."a line-by-line explanation of the settings someone set up for you.
  6. Write a five-line "my setup" note: install method, version, update channel, account and login method, notable settings.
Common misunderstandings
"The free Claude plan includes Claude Code."
It doesn't. You need Pro, Max, Ultra, Team, Enterprise or a Console account.
"Installing the VS Code extension is enough to use claude in the terminal."
The extension uses its own built-in copy. Typing claude in a terminal needs the standalone install.
"If I'm signed in with my subscription, that's what Claude Code uses."
Not if an API key or other credential is set: those take priority. Check with /status.
"claude doctor and /doctor are the same."
claude doctor runs from the shell and only reads. /doctor runs inside a session and can offer fixes.
"Use sudo if npm complains about permissions."
Don't: Anthropic's docs warn against sudo npm install -g. Fix the npm permissions, or use the native installer.

64.10Review

Key takeaways
  • You need a paid Claude plan or a Console account; the free plan doesn't include Claude Code.
  • The native installer is recommended and updates itself; Homebrew, WinGet, npm and Linux packages update through their own tools.
  • Check an install with claude --version and claude doctor; update with claude update; choose latest or stable channels.
  • Most people sign in with a subscription through the browser. API keys, long-lived tokens and cloud providers suit scripts, CI and companies on AWS, Google Cloud or Azure.
  • Other credentials override your subscription login; /status shows which one is active.
  • which claude, claude auth status and ~/.claude reveal how any machine was set up.
