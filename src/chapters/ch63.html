Claude Code is Anthropic's AI assistant that works inside your project rather than inside a chat window. You describe a task in plain English. Claude Code reads your files, runs commands, edits code and checks the result, asking your permission along the way. It's the difference between asking a colleague for advice and asking a colleague to sit at your computer and do the work while you watch.

63.1One sentence, then the details

Anthropic describes Claude Code as an agentic coding tool. Each word matters:

WordPlain meaning
AgenticIt doesn't just answer; it takes steps on its own (reading, searching, running, editing) towards a goal you set. See agent.
CodingIt was built for software work, but anything that lives in files and can be done with commands works too: test plans, data files, scripts, reports.
ToolIt's a program you install and run, not a website. It uses Claude models (the same family you chat with) as its "brain".

If you remember one thing: the Claude app talks; Claude Code acts.

In everyday life

Imagine you need a leaking tap fixed. You can phone a plumber friend, describe the leak and follow their advice yourself. That's the Claude app: excellent advice, but your hands do the work and you copy everything across. Or the plumber can come round, look under the sink, try a fix, turn the water back on and check for drips, asking "OK if I turn the water off?" first. That's Claude Code.

Real-world example: a tester's afternoon

Priya, a QA engineer, types: "The nightly run shows three failures in the payments suite. Find out why and tell me whether it's the app or the tests." Claude Code reads the test report, opens the three test files, runs one failing test, notices a renamed button ID in a recent commit, shows Priya the evidence, and proposes a one-line locator fix. It asks before editing. Priya approves, Claude reruns the suite, and all three pass. Priya still made the important call (the change was intentional, so the test was wrong, not the app), but she skipped forty minutes of digging.

63.5What it can't do (or shouldn't)

  • It doesn't know your business. It doesn't know which behaviour is a bug and which is intended unless you tell it, or unless the requirements are written down somewhere it can read.
  • It isn't always right. Like every AI model it can be confidently wrong (Chapter 22). The difference is that it can run tests to check itself, if you ask it to.
  • It can't see what it hasn't read. Claude starts each session fresh. It only knows the files it has opened, the instructions in CLAUDE.md, and what you tell it.
  • It doesn't replace review. Every change is your responsibility. Read the diff before you commit.
  • It needs a paid plan. The free Claude plan doesn't include Claude Code (Chapter 64).

63.6The agent loop in one picture

Every task, simple or huge, runs through the same agent loop:

You ask"Make the login tests pass."
Claude thinksThe model, running in Anthropic's cloud, decides the next step: "run the tests first".
Permission checkClaude Code checks your settings. If needed, it asks you.
Tool runsOn your computer. The output is captured.
Result returnsThe output goes back to the model, which decides the next step, and so on until done.

Two facts follow, and they're worth repeating to anyone who worries about AI touching their computer:

  1. The thinking happens in the cloud; the doing happens on your machine. Claude Code sends the model your request and the text of what it has read or run. It doesn't upload your whole disk.
  2. Every action passes a checkpoint you control. That's the permission system.

Chapter 66 walks through this loop step by step, including what is sent where.

63.7The safety model in one paragraph

Claude Code can read files freely, but changing files and running commands are governed by a permission mode and your own allow/deny rules. In Manual mode it asks before every edit or command. In Accept edits mode it edits files freely but still asks before most commands. In Plan mode it only investigates and proposes. In Auto mode it acts without asking while a separate background safety check reviews each action and blocks risky ones. Since version 2.1.283, new interactive sessions in the terminal and VS Code start in Auto mode. You can switch at any time with Shift+Tab, and deny rules (for example "never read .env") are enforced in every mode. Chapter 67 explains each mode and when to use it.

Know your starting mode

If someone else set up your machine, you may have been running in Auto mode without realising. That's usually fine for everyday work, but switch to Plan or Manual for anything sensitive, such as changes to shared configuration or production data. The status bar at the bottom of the session shows the current mode, for example ⏵⏵ auto mode on or ⏸ plan mode on.

63.8Who uses it, and why testers should care

Developers

Write features, fix bugs, refactor, review pull requests, explain unfamiliar code.

Testers and QA engineers

Write and maintain automated tests, triage failures, generate test data, read logs, draft bug reports, connect to Jira and browsers through MCP (Part XII).

Analysts and others

Clean data files, write scripts that save repetitive work, turn messy notes into structured documents, explore a codebase to answer "how does this work?".

For QA in particular, Claude Code removes the biggest barrier to automation: the hours of setup, boilerplate and debugging that stand between "I know what to test" and "it runs in CI". Your testing judgement becomes the valuable part, and Claude handles much of the typing. Part XV is all about this.

Is Claude Code a model, an app or a framework?

It's a harness: a program that wraps a model with tools, permissions, memory files and a user interface. The model (for example Claude Opus 5.5) is the same one available through the API. Claude Code adds:

  • a system prompt that teaches the model how to work as a coding agent;
  • built-in tools (read, edit, search, shell, web, subagents) and support for MCP tools;
  • context management: loading CLAUDE.md, compacting long conversations, saving sessions;
  • the permission system and settings;
  • extension points: skills, hooks, subagents and plugins (Part X).

Anthropic also offers the same engine as a library, the Claude Agent SDK, so developers can build their own agents on it (Chapter 110). And claude -p ("print mode") runs Claude Code without the interactive screen, for scripts and CI pipelines.

Common misunderstandings
"Claude Code is only for programmers."
It's for anyone whose work lives in files and commands. Testers, analysts and technical writers use it every day.
"It uploads my whole project to the cloud."
Only what it reads or runs is sent to the model, as text. Cloud sessions are different: they deliberately work on a copy of your GitHub repository.
"It's a different AI from the Claude chat app."
It uses the same Claude models and the same account. The difference is the tools and permissions around the model.
"If it says the tests pass, they pass."
Ask it to show the test output, and check that the tests can actually fail (Chapter 121).
"Auto mode means no safety."
Auto mode still runs a separate safety check on each action, and your deny rules always apply. It means fewer interruptions, not no checks.
