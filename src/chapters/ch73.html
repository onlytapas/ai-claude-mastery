People say "run the command" about five quite different things: a slash command typed inside Claude Code, a terminal command typed into your normal shell, a flag added to the claude command when you start it, a keyboard shortcut pressed while Claude Code is open, and a special symbol such as @ or ! at the start of what you type. Each lives in a different place and works at a different time. Once you can tell them apart, most "it didn't work" moments disappear.

73.1Two places you can be typing

Everything in this chapter depends on one question: where is your cursor right now? There are only two places.

Your normal terminal (the shell)

The prompt usually ends in $ or %, for example alex@mac ~/shop-app %. Anything you type here is run by your computer's terminal shell (bash or zsh). This is where you start Claude Code.

Inside a Claude Code session

After you run claude, the screen changes. You see Claude Code's input box with a > prompt and a status line underneath. Anything you type here goes to Claude Code, not to the shell.

In everyday life

Think of a building and a meeting room inside it. In the corridor (the shell) you can walk to any room and tell the receptionist which room to open and how to set it up (claude --model opus). Once you're inside the meeting room (the Claude Code session), you talk to the person in the room, and the room has its own buttons and its own way of doing things (/model, Shift+Tab). Shouting room-instructions in the corridor, or corridor-instructions in the room, gets you nowhere.

There's also a sixth thing people call a "command", and it isn't typed by you at all: the shell commands Claude runs for you through its Bash tool (70.8). Keep it separate in your head, because it's the one that asks for permission.

73.3Kind 1: slash commands

A slash command is an instruction to Claude Code itself, typed inside a session. It controls the session rather than asking Claude a question: switch model, clear the conversation, check usage, start a review.

Inside a Claude Code session
> /model                 # opens the model picker
> /compact keep the test failures   # text after the name becomes its argument
> /context               # shows what is filling the context window

Rules worth knowing, from Anthropic's command documentation:

  • Only at the start. A slash command is recognised only at the start of a message. please /clear is just text.
  • Arguments come after the name. Anything after /compact is passed to it.
  • Busy Claude means a queue. If you send a command while Claude is working, it waits until the turn ends. A few, such as /status and /usage, run immediately.
  • Not everyone sees the same list. Your platform, plan and installed extras change what appears when you type /.

Three kinds of slash command

KindWhat it isExamples
Built-in commandBehaviour coded into Claude Code/clear, /model, /context, /mcp
Bundled skillDetailed instructions shipped with Claude Code; Claude then does the work with its normal tools/code-review (alias /review), /simplify, /doctor, /update-config
Your own or a plugin'sSkills you or your team wrote, or that came with a plugin; prompts exposed by an MCP server can appear here too/bug-report (from Chapter 80)

You type all three the same way. The difference matters when something behaves unexpectedly: a skill is guided by instructions, so its results can vary a little each time, while a built-in command always does the same thing. The full list is in Chapter 74.

73.4Kind 2: terminal commands

A terminal command is a program you run from your normal shell. Many have nothing to do with Claude (git status, npm test). The claude program also has its own subcommands, which do a job and then return you to the shell without opening a session:

In your normal terminal
claude --version        # prints the installed version, e.g. 2.1.319 (Claude Code)
claude doctor           # health check of your installation
claude mcp list         # lists configured MCP servers
claude auth status      # shows whether you're signed in
claude update           # checks for and installs updates

Notice the pattern: claude + a word (mcp, auth, doctor). That word is a subcommand. Some subcommands have their own subcommands: claude mcp add, claude mcp list. The full list is in Chapter 75.

Real-world example

A teammate says "Claude can't see Jira". The quickest check is a terminal command, before even opening a session: claude mcp list shows whether the Jira server is configured and whether it's connected. Inside a session, the equivalent is the slash command /mcp. Same information, two different places.

73.5Kind 3: CLI flags

A flag (also called an option) changes how the claude command runs. Flags start with one dash and a letter (-c) or two dashes and a word (--continue). Many have both forms, which mean the same thing.

In your normal terminal
claude --model opus                 # start a session on the Opus model
claude -c                           # continue the most recent conversation in this folder
claude --permission-mode plan       # start in plan mode
claude -p "summarise README.md"     # print mode: answer once and exit

Flags take effect once, when the session starts. To change the model halfway through a session you don't restart with a flag; you use the slash command /model. Some settings exist in both forms for exactly this reason:

You want to…Before starting (flag)During the session (slash command or shortcut)
Choose the modelclaude --model sonnet/model
Set effortclaude --effort high/effort
Start in plan modeclaude --permission-mode plan/plan or Shift+Tab
Pick up an old conversationclaude -r or claude -c/resume
Allow another folderclaude --add-dir ../api-tests/add-dir
Reading a command line like a sentence

Take claude mcp add --transport http jira https://example.com/mcp. Read it left to right:

  1. claude: the program.
  2. mcp add: the subcommand ("add an MCP server").
  3. --transport http: a flag with a value ("use HTTP").
  4. jira: the first argument (the name you're giving the server).
  5. https://example.com/mcp: the second argument (where it lives).

Flags usually come after the subcommand and before or between arguments. Words in <angle brackets> in documentation are required; words in [square brackets] are optional. claude --help and claude mcp add --help show the exact pattern for your version.

73.6Kind 4: keyboard shortcuts

Shortcuts are keys you press while a session is open. You don't type them as text and you don't press Enter. They act instantly.

PressWhat happens
Shift+TabCycles permission modes (Manual, Accept edits, Plan, and Auto when available)
EscStops Claude mid-turn, keeping the work done so far
Esc EscOn an empty prompt, opens the rewind menu; with text, clears the draft
Ctrl+CInterrupts; with nothing running, first clears input, a second press exits
Ctrl+RSearches your earlier prompts
? on an empty promptShows the shortcut help panel

The complete list, including multi-line input, history, background tasks and custom key bindings, is in Chapter 76.

73.7Kind 5: input symbols

Some characters have a special meaning when you type them in the Claude Code input box. They change what the rest of your message means.

SymbolWhereMeaningExample

In everyday life

In an email, "@Priya" tags a person and "Re:" marks a reply. The symbol at the front changes what the message does. Claude Code's /, @ and ! work the same way.

73.8The sixth kind: commands Claude runs for you

When you ask "run the login tests and tell me what failed", Claude decides to run a shell command such as npx playwright test login. It uses its Bash tool to do that on your computer. You don't type the command; Claude proposes it, and depending on your permission mode, you may be asked to approve it.

You ask"Run the login tests"
Claude proposesnpx playwright test login
Permission checkAllowed, asked, or denied by your mode and rules
It runsOn your machine, in the project folder
ResultOutput goes back to Claude

! npm test (you)

You typed it, so you've decided. It runs straight away. Claude sees the output and responds.

"Run the tests" (Claude)

Claude chooses the exact command. You see it before it runs (unless your mode or rules auto-approve it). Read it the way you'd read a test step.

Common misunderstandings
Typing /model in the normal terminal
The shell thinks /model is a file path. Slash commands only work inside a session.
Typing claude --model opus inside a session
Inside a session that's just a message to Claude. Use /model there.
Putting flags after the prompt text
Write claude --model opus "explain this repo", not claude "explain this repo --model opus". Inside quotes, --model is just part of the text.
Starting a message with # to save a memory
That shortcut was removed. Ask Claude to add the rule to CLAUDE.md, or run /memory.
Thinking ! and "ask Claude to run it" are the same
! runs exactly what you typed, immediately. Asking Claude lets it choose the command, which you then review.
Expecting every slash command from a colleague's screen
Lists differ by version, plan, platform and installed skills and plugins. Type / to see yours.

73.10Review

Key takeaways
  • First ask where your cursor is: the normal shell, or inside a Claude Code session.
  • Slash commands (/model) work inside a session; terminal commands (claude mcp list) and flags (--model) work in the shell.
  • Flags take effect once at start-up; slash commands and shortcuts change things mid-session.
  • Keyboard shortcuts act instantly; input symbols (/, @, !) change what your message means. # is no longer special.
  • Commands Claude runs through its Bash tool are proposed by Claude and checked by your permission mode.
