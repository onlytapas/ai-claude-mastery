A multimodal model works with more than one kind of input or output: text, images, audio or video. The trick is to turn each kind into tokens the same Transformer can read. Images are cut into small square patches, and each patch becomes a token-like vector. Claude can read images and PDFs, including screenshots, charts and scanned pages, but it cannot create images, and it has known weak spots such as exact counting and tiny text. For testers, screenshots are a powerful input, as long as you check the output and remove anything private first.

21.1What "multimodal" means

A modality is a kind of data: text, images, audio, video. Early language models were text in, text out. Multimodal models accept or produce other kinds too. It helps to separate two directions, because they are very different skills and often different models.

DirectionWhat it doesExamples
Understanding (input)Takes an image, document, sound or video and answers questions about it in text"What error is shown in this screenshot?" · "Summarise this scanned contract" · speech-to-text
Generation (output)Creates a new image, sound or video from a descriptionImage generators, text-to-speech voices, video generators
Verified 9 Nov 2026 · what Claude does

Anthropic's vision documentation says Claude "is an image understanding model only. It can interpret and analyze images, but it cannot generate, produce, edit, manipulate, or create images." Claude can write code that draws things, such as an SVG diagram, a chart in an Artifact (Chapter 48) or a Matplotlib script, and it can create Word, Excel, PowerPoint and PDF files in the apps (Chapter 46). That is text output that a program turns into a picture, not image generation.

In everyday life

Being able to read a map and being able to draw one are different skills. A good navigator can study a map and tell you the fastest route without being able to draw a map themselves. Claude is the navigator: excellent at reading images, not a painter. Image generators are the painters.

21.2How a model "sees"

A Transformer (Chapter 16) reads a sequence of vectors. For text, those come from tokens. For images, the image is turned into a sequence of vectors too. The usual approach has three steps.

1. Cut into patchesThe image is split into a grid of small squares
2. Vision encoderA neural network turns each patch into a vector that captures what's in it and its context
3. ProjectThe vectors are mapped into the same "space" as the text tokens
4. One sequenceImage vectors and text tokens are read together by the language model

The vision encoder is usually a Vision Transformer: the same attention idea applied to patches instead of words (Dosovitskiy et al., 2020). Many encoders are pre-trained on huge collections of images paired with captions, learning to put a picture and its description close together in embedding space, the idea behind OpenAI's CLIP (2021). That's why a model can connect "red error banner" in your question with red pixels at the top of a screenshot.

What Anthropic publishes about Claude

Anthropic's documentation says Claude "processes images in patches instead of pixels. Each patch is a 28×28-pixel block of the image, referred to as a visual token." Anthropic does not publish the full internal design of Claude's vision system, so the flow above describes the common approach in the field, not a confirmed description of Claude.

Under the hood: why patches, and why image size matters

Treating each pixel as a token would be hopeless: a 1920×1080 screenshot has over two million pixels, and attention cost grows with the square of sequence length. Grouping pixels into 28×28 patches cuts that to about 2,700 visual tokens. Each patch is flattened into a list of numbers (28 × 28 × 3 colour channels), multiplied by learned weights to make a vector, and given a position so the model knows where it came from, much like positional encoding for text.

The consequence for you is that the patch grid sets the level of detail. Text that's only a few pixels high falls inside one patch with lots of other detail and becomes hard to read. And if an image is larger than the model's limit, it is scaled down before patching, which shrinks small text further. Cropping to the area that matters often helps more than sending a bigger image.

21.5Limits: where vision goes wrong

Anthropic's documentation lists these limitations. Treat them as test conditions.

Limitation (Anthropic's wording, summarised)What it means in practice
Counting: approximate, especially "with large numbers of small objects""How many rows are in this table screenshot?" may be off by a few. Ask for the data as text, or have code count

Vision can hallucinate too

When text in an image is unclear, a model may "read" something plausible that isn't there, such as an error code with one digit wrong. This is the same hallucination problem as in text (Chapter 22). Two defences: ask Claude to say when it can't read something, and copy exact error text yourself when it matters.

21.6Audio, speech and video

Audio and speech

Speech handling usually has three parts: speech-to-text (turning spoken words into text), a language model working on that text, and text-to-speech (reading the reply aloud). Some newer systems process audio more directly, but the pipeline idea is the easiest way to understand them. OpenAI's Whisper (2022) is a well-known open speech-to-text model, trained on 680,000 hours of audio according to its paper.

Verified 9 Nov 2026 · Claude and voice

The Claude apps have a voice mode, in beta, on all plans. Claude Code has voice dictation that you turn on with /voice (it needs a claude.ai account), then hold or tap the space bar to speak. The Messages API documentation we checked for this chapter describes text, image and PDF input; we found no audio input there. If you need Claude to work with a recording, such as a support call, transcribe it first and send the text.

Video

Video is a sequence of images plus, often, sound. Models that "watch" video typically sample frames, for example one or two per second, and treat each as an image, which gets expensive fast. Claude does not accept video files. To ask Claude about a screen recording of a bug, extract a few key frames (for example with the free tool ffmpeg) and send them as images in order, with a sentence describing what happens between them.

Generation elsewhere in the industry

Other companies offer generation models, for example Google's Imagen and Nano Banana for images and Veo for video, and xAI's Grok Imagine for images and video (Chapter 28, Chapter 30). Most modern image generators are based on diffusion models, which start from random noise and remove it step by step, guided by your text, until a picture appears. For testers, generated images can be useful test data (for example, sample product photos for an upload test), but check your organisation's policy first.

Under the hood: diffusion in one paragraph

During training, a diffusion model sees real images with increasing amounts of random noise added, and learns to predict the noise so it can remove it. To generate, you start with pure noise and repeatedly ask the model "what noise should I remove to move towards an image matching this caption?". After many small steps, an image emerges. The caption guides each step through a text encoder, often trained the CLIP way. The 2020 paper by Ho, Jain and Abbeel ("Denoising Diffusion Probabilistic Models") made the approach practical. This is a completely different process from how Claude reads images, which is why understanding and generating are separate skills.

21.7Cost and privacy of screenshots

Cost

Images are tokens, so they cost money and context space. Using Anthropic's formula, a full-HD 1920×1080 screenshot is about 2,691 visual tokens on Claude 4.7 and later. Anthropic's own worked example: on Opus 5.5 at $4 per million input tokens, a 4K screenshot costs about $19 per thousand images. In a long Claude Code session, twenty screenshots can add 50,000 tokens to the window (Chapter 20). Crop, and send only what's needed.

Privacy

Screenshots capture more than you notice: customer names in a table, email addresses, account numbers, internal URLs, tokens in a browser's address bar, other open tabs, a chat notification in the corner.

CaptureOnly the window or region you need
InspectLook at every corner before sending

Data handling

Anthropic's vision FAQ says Anthropic "does not use uploaded images to train models" and points to its privacy policy and API data-retention pages for details. How long data is kept, and settings for consumer accounts, depend on your plan and your organisation's agreement: see Chapter 42 and Chapter 50. Whatever the policy, the safest screenshot is one taken in a test environment with synthetic data (Chapter 13).

Opinion · common practice in QA teams

Many QA leads set a simple rule: "no production screenshots in AI tools, ever; staging with test data only." It is stricter than some vendor policies require, but easy to follow and audit. Teams that need production evidence typically redact first and record what was shared. Decide your team's rule before someone pastes a customer record.

image_tokens.py (Python 3, standard library only)
"""Estimate how many visual tokens Claude will use for a screenshot.

Rule from Anthropic's vision docs: an image costs
ceil(width / 28) * ceil(height / 28) visual tokens, and images over the
model's long-edge or token limit are scaled down (keeping the aspect ratio)
before processing. This script searches for that scaled size, so treat the
result as an estimate and check real usage in the API response.
"""
import math
import sys

TIERS = {
    "high": (2576, 4784),      # Claude 4.7 and later models
    "standard": (1568, 1568),  # all other models
}


def tokens(w, h):
    return math.ceil(w / 28) * math.ceil(h / 28)


def fit(w, h, tier):
    max_edge, max_tokens = TIERS[tier]
    if max(w, h) <= max_edge and tokens(w, h) <= max_tokens:
        return w, h
    best = (1, 1)
    lo, hi = 1, min(w, max_edge if w >= h else w)
    while lo <= hi:
        nw = (lo + hi) // 2
        nh = max(1, round(h * nw / w))
        if max(nw, nh) <= max_edge and tokens(nw, nh) <= max_tokens:
            best = (nw, nh)
            lo = nw + 1
        else:
            hi = nw - 1
    return best


def main():
    sizes = [(200, 200), (1000, 1000), (1920, 1080), (2000, 1500), (3840, 2160)]
    if len(sys.argv) == 3:
        sizes = [(int(sys.argv[1]), int(sys.argv[2]))]
    price_opus = 4.00  # USD per million input tokens, Opus 5.5 (verified 9 Nov 2026)
    print(f"{'image':>11} | {'high-res tier':>22} | {'standard tier':>22}")
    for w, h in sizes:
        row = []
        for tier in ("high", "standard"):
            nw, nh = fit(w, h, tier)
            row.append(f"{nw}x{nh} = {tokens(nw, nh):,} tok")
        print(f"{w:>5}x{h:<5} | {row[0]:>22} | {row[1]:>22}")
    w, h = sizes[-1]
    t = tokens(*fit(w, h, "high"))
    print(f"\n1,000 screenshots of {w}x{h} on Opus 5.5 cost about "
          f"${t * 1000 * price_opus / 1_000_000:.2f} in input tokens.")


if __name__ == "__main__":
    main()

"""Send a screenshot to Claude and get a structured bug-report draft."""
import base64
import json
import os
import sys
import urllib.error
import urllib.request

TYPES = {".png": "image/png", ".jpg": "image/jpeg", ".jpeg": "image/jpeg",
         ".gif": "image/gif", ".webp": "image/webp"}
PROMPT = (
    "You are helping a software tester. Look at this screenshot and write a "
    "bug-report draft with these headings: Summary, What is visible, "
    "Likely problem, Questions to confirm. Quote any error text exactly. "
    "If text is too small or unclear to read, say so instead of guessing."
)


def main():
    if len(sys.argv) != 2:
        sys.exit("Usage: python3 describe_screenshot.py path/to/screenshot.png")
    path = sys.argv[1]
    ext = os.path.splitext(path)[1].lower()
    if ext not in TYPES:
        sys.exit(f"Unsupported file type {ext}. Use PNG, JPEG, GIF or WebP.")
    key = os.environ.get("ANTHROPIC_API_KEY")
    if not key:
        sys.exit("Set ANTHROPIC_API_KEY first (see Chapter 98).")
    with open(path, "rb") as f:
        data = base64.standard_b64encode(f.read()).decode("ascii")
    body = {
        "model": "claude-sonnet-5-5",
        "max_tokens": 4000,
        "output_config": {"effort": "low"},
        "messages": [{
            "role": "user",
            "content": [
                {"type": "image",
                 "source": {"type": "base64", "media_type": TYPES[ext], "data": data}},
                {"type": "text", "text": PROMPT},
            ],
        }],
    }
    req = urllib.request.Request(
        "https://api.anthropic.com/v1/messages",
        data=json.dumps(body).encode("utf-8"),
        headers={"x-api-key": key, "anthropic-version": "2026-10-21",
                 "content-type": "application/json"},
    )
    try:
        with urllib.request.urlopen(req, timeout=300) as resp:
            reply = json.load(resp)
    except urllib.error.HTTPError as err:
        sys.exit(f"HTTP {err.code}: {err.read().decode('utf-8')}")
    for block in reply.get("content", []):
        if block.get("type") == "text":
            print(block["text"])
    print(f"\n[input tokens: {reply['usage']['input_tokens']}, "
          f"output tokens: {reply['usage']['output_tokens']}]")


if __name__ == "__main__":
    main()
Troubleshooting

Ctrl+V pastes nothing in Claude Code: copy the image again (not the file) or give the file path instead. "Unsupported file type": convert to PNG or JPEG. HTTP 400 about image size: the file is over 10 MB or 8000 px; resize it. HTTP 401: check the API key. The draft invents error text: crop tighter, make the text bigger, and keep the "say so instead of guessing" instruction. No API access: steps 1–5 need only Claude Code or claude.ai.

Common misunderstandings
"Claude can make images if I ask nicely."
Claude understands images but doesn't generate them. It can write code (SVG, charts, diagrams) that draws them.
"A bigger, sharper screenshot is always better."
Images over the limit are scaled down, and big images cost more tokens. Crop to what matters.
"If Claude read the number from the chart, it's exact."
Chart reading is estimation, and counting is approximate. Use the underlying data for exact values.
"Claude can watch my screen recording."
Not as video. Extract key frames and send them as images, or describe the steps.
"Vision answers can't be hallucinated; it's looking right at it."
Unclear text, small images and rotated scans can produce confident misreadings. Verify quoted text.
"It's only a screenshot, so privacy doesn't apply."
Screenshots often contain personal data and secrets. Redact, or use test data.

claude_lab.py (shared helper; Python 3, standard library only)
"""Shared helpers for the Chapter 21 lab: image blocks, one API call, JSON parsing.

Standard library only. Pass dry_run=True to skip the network: the request is
built and summarised, and a fake reply (clearly labelled) is returned instead.
"""
import base64
import json
import math
import os
import struct
import sys
import urllib.error
import urllib.request

API_URL = "https://api.anthropic.com/v1/messages"
API_VERSION = "2026-10-21"          # no temperature: version 2026-10-21 rejects it
MODEL = "claude-sonnet-5-5"
TYPES = {".png": "image/png", ".jpg": "image/jpeg", ".jpeg": "image/jpeg",
         ".gif": "image/gif", ".webp": "image/webp"}
MAX_BYTES = 10 * 1024 * 1024        # API limit per image (base64-encoded)


def png_size(path):
    """Return (width, height) of a PNG from its header, or None for other files."""
    with open(path, "rb") as f:
        head = f.read(24)
    if head[:8] != b"\x89PNG\r\n\x1a\n":
        return None
    return struct.unpack(">II", head[16:24])


def visual_tokens(path):
    """Rough estimate using Anthropic's rule (before any downscaling)."""
    size = png_size(path)
    if not size:
        return None
    return math.ceil(size[0] / 28) * math.ceil(size[1] / 28)


def image_block(path):
    """Turn an image file into a Messages API image content block."""
    ext = os.path.splitext(path)[1].lower()
    if ext not in TYPES:
        sys.exit(f"{path}: unsupported type {ext}. Use PNG, JPEG, GIF or WebP.")
    with open(path, "rb") as f:
        data = base64.standard_b64encode(f.read()).decode("ascii")
    if len(data) > MAX_BYTES:
        sys.exit(f"{path}: over 10 MB once encoded. Crop or resize it.")
    return {"type": "image",
            "source": {"type": "base64", "media_type": TYPES[ext], "data": data}}


def summarise(body):
    """Print what would be sent, without the image bytes."""
    print(f"[dry run] model={body['model']} max_tokens={body['max_tokens']}")
    for block in body["messages"][0]["content"]:
        if block["type"] == "image":
            kb = len(block["source"]["data"]) / 1024
            print(f"[dry run]   image block, {block['source']['media_type']}, "
                  f"{kb:,.0f} KB base64")
        else:
            first_line = block["text"].splitlines()[0][:70]
            print(f"[dry run]   text block: {first_line!r}")


def ask_claude(content, max_tokens=2000, dry_run=False, fake_reply=""):
    """Send one user message (a list of content blocks) and return Claude's text."""
    body = {
        "model": MODEL,
        "max_tokens": max_tokens,
        "output_config": {"effort": "low"},
        "messages": [{"role": "user", "content": content}],
    }
    if dry_run:
        summarise(body)
        print("[dry run] no API call made; using a FAKE reply written into the script")
        return fake_reply
    key = os.environ.get("ANTHROPIC_API_KEY")
    if not key:
        sys.exit("Set ANTHROPIC_API_KEY first, or add --dry-run to test offline.")
    req = urllib.request.Request(
        API_URL,
        data=json.dumps(body).encode("utf-8"),
        headers={"Authorization": f"Bearer {key}",
                 "anthropic-version": API_VERSION,
                 "content-type": "application/json"},
    )
    try:
        with urllib.request.urlopen(req, timeout=300) as resp:
            reply = json.load(resp)
    except urllib.error.HTTPError as err:
        sys.exit(f"HTTP {err.code}: {err.read().decode('utf-8')}")
    except urllib.error.URLError as err:
        sys.exit(f"Network error: {err.reason}")
    if reply.get("stop_reason") == "max_tokens":
        print("Warning: reply was cut off (max_tokens). Raise max_tokens.",
              file=sys.stderr)
    usage = reply.get("usage", {})
    print(f"[input tokens: {usage.get('input_tokens')}, "
          f"output tokens: {usage.get('output_tokens')}]", file=sys.stderr)
    return "".join(b["text"] for b in reply.get("content", [])
                   if b.get("type") == "text")


def parse_json(text):
    """Parse JSON from a reply, tolerating a ```json fence around it."""
    text = text.strip()
    if text.startswith("```"):
        text = text.split("\n", 1)[1].rsplit("```", 1)[0]
    try:
        return json.loads(text)
    except json.JSONDecodeError as err:
        sys.exit(f"Reply was not valid JSON ({err}). Reply was:\n{text}")
Why ask for JSON?

Asking for "ONLY a JSON object with these keys" gives you data a program can check, sort and send on to Jira or a spreadsheet. The scripts still check the reply, because a model can occasionally leave out a key or add a sentence. For stricter guarantees, the API also offers structured output with a JSON schema (Chapter 43); the plain prompt keeps this lab short.

"""Exercise 1: turn application screenshots into structured bug details (JSON).

Usage:  python3 bug_extract.py shot1.png [shot2.png ...] [--dry-run]
Writes bugs.json and prints a short table.
"""
import json
import sys

from claude_lab import ask_claude, image_block, parse_json, visual_tokens

PROMPT = """You are helping a software tester triage a bug from a screenshot.
Reply with ONLY a JSON object, no other text, with exactly these keys:
  "page": the page or screen name as shown (or "unknown"),
  "element": the UI element that looks wrong,
  "problem": one sentence describing what is wrong, quoting visible error text exactly,
  "severity_guess": one of "blocker", "major", "minor", "cosmetic",
  "unreadable": a list of any text too small or unclear to read (empty list if none).
If the screenshot shows no visible problem, set "problem" to "none visible"."""

KEYS = ["page", "element", "problem", "severity_guess", "unreadable"]
SEVERITIES = {"blocker", "major", "minor", "cosmetic"}

FAKE = json.dumps({
    "page": "Checkout - Payment",
    "element": "Pay now button",
    "problem": "Error banner says 'Payment service unavailable (code 503)'.",
    "severity_guess": "major",
    "unreadable": [],
})


def check(bug):
    """Return a list of problems with Claude's JSON, so bad replies are visible."""
    issues = [f"missing key {k!r}" for k in KEYS if k not in bug]
    if bug.get("severity_guess") not in SEVERITIES:
        issues.append(f"unexpected severity {bug.get('severity_guess')!r}")
    return issues


def main():
    dry_run = "--dry-run" in sys.argv
    paths = [a for a in sys.argv[1:] if a != "--dry-run"]
    if not paths:
        sys.exit("Usage: python3 bug_extract.py shot1.png [shot2.png ...] [--dry-run]")
    results = []
    for path in paths:
        print(f"\n== {path} (about {visual_tokens(path) or '?'} visual tokens)")
        content = [image_block(path), {"type": "text", "text": PROMPT}]
        bug = parse_json(ask_claude(content, max_tokens=1500,
                                    dry_run=dry_run, fake_reply=FAKE))
        bug["file"] = path
        bug["checks"] = check(bug)
        results.append(bug)
    with open("bugs.json", "w", encoding="utf-8") as f:
        json.dump(results, f, indent=2)
    print(f"\n{'file':<18} {'severity':<9} problem")
    for bug in results:
        flag = "  CHECK: " + "; ".join(bug["checks"]) if bug["checks"] else ""
        print(f"{bug['file'][:18]:<18} {str(bug.get('severity_guess')):<9} "
              f"{bug.get('problem', '')[:60]}{flag}")
    print("\nSaved bugs.json. Severity is a guess: a person decides the real one.")


if __name__ == "__main__":
    main()

Exercise 2: a meeting recording to action items

Claude's API accepts text, images and PDFs, but not audio: there is no audio content block in the Messages API reference (checked 9 November 2026, consistent with 21.6). So this exercise is a two-stage pipeline. First, a free speech-to-text model turns the recording into text on your own computer. Then Claude turns the text into decisions and action items.

For stage one we use faster-whisper, an open-source (MIT licence) re-implementation of OpenAI's Whisper model that runs well on an ordinary laptop CPU. Its README says it needs Python 3.9 or later and does not need FFmpeg installed, because it decodes audio with a bundled library. OpenAI's original openai-whisper package is the alternative (pip install -U openai-whisper), but it needs ffmpeg installed separately.

Consent and privacy

Only record meetings when everyone present has agreed, and follow your company's rules on recording. A transcript holds names, opinions and sometimes customer details. The transcription step stays on your machine; the Claude step sends the text to Anthropic, so the same policy questions as screenshots apply (21.7). For practice, use a recording made for the purpose.

transcribe.py (needs: pip install faster-whisper)
"""Exercise 2, step A: transcribe a meeting recording locally with faster-whisper.

Setup:  pip install faster-whisper   (Python 3.9+; no separate ffmpeg needed)
Usage:  python3 transcribe.py meeting.m4a [model]     model defaults to "base"
Writes transcript.txt. The audio never leaves your computer; the first run
downloads the model files once from Hugging Face.
"""
import sys

from faster_whisper import WhisperModel


def main():
    if len(sys.argv) not in (2, 3):
        sys.exit("Usage: python3 transcribe.py meeting.m4a [tiny|base|small|medium]")
    audio = sys.argv[1]
    size = sys.argv[2] if len(sys.argv) == 3 else "base"
    model = WhisperModel(size, device="cpu", compute_type="int8")
    segments, info = model.transcribe(audio, beam_size=5)
    print(f"Detected language {info.language} "
          f"(probability {info.language_probability:.2f})")
    lines = []
    for seg in segments:            # transcription happens as you loop
        line = f"[{seg.start:6.1f}s] {seg.text.strip()}"
        print(line)
        lines.append(line)
    with open("transcript.txt", "w", encoding="utf-8") as f:
        f.write("\n".join(lines) + "\n")
    print(f"\nSaved transcript.txt ({len(lines)} segments).")


if __name__ == "__main__":
    main()

Exercise 3: a screen recording to a user journey

Claude doesn't accept video (21.6), so you turn the recording into still frames first. Frame sampling means keeping one frame every so often instead of all 30 or 60 per second. The free command-line tool ffmpeg does it with its fps filter. Install it with brew install ffmpeg (macOS), sudo apt update && sudo apt install ffmpeg (Ubuntu/Debian) or choco install ffmpeg / scoop install ffmpeg (Windows), the commands listed in the Whisper README.

Terminal: one frame every 2 seconds, 1280 px wide
mkdir -p frames
ffmpeg -i recording.mp4 -vf "fps=1/2,scale=1280:-2" frames/frame_%03d.png
# fps=1/2       keep one frame every 2 seconds (use fps=1 for every second)
# scale=1280:-2 resize to 1280 px wide; -2 keeps the aspect ratio with an even height
# frame_%03d    names the files frame_001.png, frame_002.png, ...

The width matters for cost: a 1280×720 frame is about 1,196 visual tokens, against 2,691 for full HD (21.7), and text in most web apps is still readable at that size. A 12-second recording at fps=1/2 gives 6 frames.

"""Exercise 3: describe a user journey from ordered frames and flag visual regressions.

Usage:  python3 journey.py frames/ [--baseline good.png] [--max 8] [--dry-run]
Frames are sent in filename order (frame_001.png, frame_002.png, ...).
"""
import argparse
import glob
import json
import os
import sys

from claude_lab import TYPES, ask_claude, image_block, parse_json, visual_tokens

PROMPT = """The images labelled Frame 1..{n} are screenshots taken in order from
a screen recording of one user journey in a web app.{baseline_note}
Reply with ONLY a JSON object with these keys:
  "journey": list of objects with "frame" (number) and "step" (what the user is doing),
  "visual_issues": list of objects with "frame", "element", "issue" and
                   "confidence" ("high", "medium" or "low"): overlapping or cut-off
                   text, misaligned or missing elements, broken images, wrong colours,
                   layout that changes unexpectedly between frames,
  "summary": one sentence.
Report only what you can see. If unsure, use confidence "low"."""

BASELINE_NOTE = """
The image labelled Baseline is the same screen from the last good release.
Compare the matching frame with it and report differences as visual issues."""

FAKE = json.dumps({
    "journey": [{"frame": 1, "step": "Opens the login page"},
                {"frame": 2, "step": "Signs in and lands on the dashboard"},
                {"frame": 3, "step": "Opens the basket"}],
    "visual_issues": [{"frame": 3, "element": "Checkout button",
                       "issue": "Button overlaps the order total text",
                       "confidence": "medium"}],
    "summary": "Login to basket works, but the basket layout looks broken.",
})


def main():
    p = argparse.ArgumentParser()
    p.add_argument("frames_dir")
    p.add_argument("--baseline", help="screenshot of the same screen from a good release")
    p.add_argument("--max", type=int, default=8, help="most frames to send (cost control)")
    p.add_argument("--dry-run", action="store_true")
    a = p.parse_args()
    frames = sorted(f for f in glob.glob(os.path.join(a.frames_dir, "*"))
                    if os.path.splitext(f)[1].lower() in TYPES)
    if not frames:
        sys.exit(f"No PNG/JPEG/GIF/WebP images in {a.frames_dir}")
    if len(frames) > a.max:            # keep an even spread across the recording
        step = len(frames) / a.max
        frames = [frames[int(i * step)] for i in range(a.max)]
    content, total = [], 0
    if a.baseline:
        content += [{"type": "text", "text": "Baseline:"}, image_block(a.baseline)]
        total += visual_tokens(a.baseline) or 0
    for i, path in enumerate(frames, 1):
        content += [{"type": "text", "text": f"Frame {i}:"}, image_block(path)]
        total += visual_tokens(path) or 0
        print(f"Frame {i}: {path}")
    print(f"About {total:,} visual tokens for {len(frames)} frames")
    note = BASELINE_NOTE if a.baseline else ""
    content.append({"type": "text",
                    "text": PROMPT.format(n=len(frames), baseline_note=note)})
    result = parse_json(ask_claude(content, max_tokens=3000,
                                   dry_run=a.dry_run, fake_reply=FAKE))
    print("\nJourney:")
    for s in result.get("journey", []):
        print(f"  {s.get('frame')}. {s.get('step')}")
    print("Possible visual issues (confirm with a pixel diff or by eye):")
    for v in result.get("visual_issues", []) or [{"issue": "none reported"}]:
        print(f"  frame {v.get('frame', '-')} [{v.get('confidence', '-')}] "
              f"{v.get('element', '')}: {v.get('issue')}")
    print(f"Summary: {result.get('summary')}")
    with open("journey.json", "w", encoding="utf-8") as f:
        json.dump(result, f, indent=2)
    print("\nSaved journey.json")


if __name__ == "__main__":
    main()

Troubleshooting: exercise 3

"ffmpeg: command not found": install it (above) and open a new terminal. No frames, or "No such file": check the video's name and that the frames folder exists. Too many frames: use fps=1/5 for one every 5 seconds, or rely on --max. Steps described in the wrong order: make sure file names sort correctly (%03d gives 001, 002…). HTTP 413 or a size error: too much data in one request; send fewer or smaller frames. Claude reports issues that aren't there: low-confidence items are often guesses; check the frame before filing anything.

Common misunderstandings in this lab
"I can send the meeting recording straight to Claude."
Not through the API: it takes text, images and PDFs. Transcribe first, then send the text.
"The dry run proves the prompt works."
It proves your files, encoding and request building work. Only a live run shows what Claude actually answers.
"Claude's severity guess can go straight into Jira."
It's a starting point for triage. A person who knows the product decides.

21.9Review

Key takeaways
  • Multimodal means more than one kind of data. Understanding (reading images, audio) and generation (making them) are different skills, often different models.
  • Models "see" by cutting images into patches and turning each into a vector the language model reads alongside text. For Claude, a patch is 28×28 pixels.
  • Claude reads JPEG, PNG, GIF and WebP images and PDFs (text plus page images); it does not generate images, and it does not accept video.
  • Known limits: approximate counting and positions, trouble with tiny, blurry or rotated images, no identification of people.
  • Screenshots are excellent for bug drafts, comparisons and test ideas, but verify quoted text and use proper tools for pixel-level checks.
  • Images cost tokens (about 2,700 for a full-HD screenshot on current models) and can carry private data. Crop and redact.
  • To build with audio or video, convert first: transcribe audio locally (for example with faster-whisper) and send the text; sample video into frames with ffmpeg and send them as labelled images.
