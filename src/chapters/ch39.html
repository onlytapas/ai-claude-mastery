Claude has gone through about two dozen releases in under four years. The first Claude (March 2023) was a single chat model with a cheaper "Instant" sibling. Claude 3 (March 2024) introduced the three tiers you still see today: Haiku (fast), Sonnet (balanced) and Opus (most capable). Later generations added visible thinking, tool use, computer use and coding agents, grew the context window to a million tokens, and in June 2026 added a new top tier, Fable. Old models are retired on a published schedule, so anything you build on Claude must track model versions the way you track library versions.

39.1Reading Claude's names

Before the timeline, learn to read the names. Since Claude 3, every model name has two parts: a tier and a generation number.

TierSinceMeaning
HaikuClaude 3 (Mar 2024)Smallest and fastest; cheapest; good for high-volume, simple tasks
SonnetClaude 3 (Mar 2024)The balance of speed, cost and intelligence
OpusClaude 3 (Mar 2024)The most capable generally available tier until 2026
FableClaude Fable 5 (Jun 2026)A new top tier above Opus, for demanding reasoning and long-horizon agent work
MythosMythos Preview (Apr 2026)The same underlying model as Fable with some safeguards lifted; verified organisations only (Chapter 38)

The number is the generation: 3, 3.5, 3.7, 4, 4.1 … 5, 5.1, 5.5. A higher number within a tier is newer. Different tiers do not always share a number at the same moment: in mid-October 2026 the newest models were Fable 5.1, Opus 5.5, Sonnet 5.5 and Haiku 5.5.

In everyday life

Think of a car maker. The tier is the model line (city car, family car, executive car, and now a flagship above them); the number is the model year. "2026 family car" and "2024 executive car" are both real cars you can still buy for a while, but the dealer will eventually stop servicing the old ones. That last part is deprecation, covered in 39.5.

Three naming styles for model IDs

When you call the API, you use a model ID, an exact string. Its format has changed over time, which matters when you search old code:

EraStyleExample
Claude 1 and 2 (2023)Name and version number with a dotclaude-2.1
Claude 3 to 3.7 (2024 to early 2025)Generation first, then tier, then a dateclaude-3-5-sonnet-20240620
Claude 4 onwardTier first, then generation; dated IDs until 4.5, undated from 4.6claude-opus-5-5

From the 4.6 generation onward, model IDs carry no date and each one is a pinned snapshot: claude-opus-5-5 always means the same model, and the ID doubles as its alias.

  2. 13 Mar 2024Claude 3 Haiku available through the API and to Claude Pro subscribers.

Two dates to treat with care

Claude 3.5 Sonnet: the announcement page as fetched shows 21 June 2024, but the model ID is claude-3-5-sonnet-20240620, which implies 20 June. This book says "June 2024". Claude 3.5 Haiku: the October post said it would arrive "later this month"; the exact availability date was not confirmed.

Two things changed the way people worked. First, the mid-tier Sonnet became the everyday workhorse because it was good enough for most jobs at a fraction of Opus's cost. Second, the upgraded 3.5 Sonnet in October was the same name with a new ID, which confused many teams: "Claude 3.5 Sonnet" meant two different models depending on the date suffix. This is one reason undated, pinned IDs arrived later.

Real-world example: the silent upgrade question

A QA team's nightly job used an alias pointing at "the latest 3.5 Sonnet". In October 2024 the alias moved to the upgraded model, and a set of snapshot-style tests that compared Claude's bug summaries word for word started failing. Nothing was broken: the model had changed. The fix was to pin the exact ID in CI and update it on purpose, with a review of the differences (Chapter 36).

Under the hood: why a tokenizer change matters for cost tests

Prices are per token (Chapter 14). If a newer tokenizer splits the same text into about 30% more tokens, the same prompt costs more tokens on Opus 4.7 and later than on Opus 4.6, even at the same price per token. It also changes how much text fits in a context window and how close you get to max_tokens.

So when you compare generations in a cost test, compare cost per task (from the usage the API reports), not token counts or list prices alone. A model with a lower price per token can still cost more per task if it uses more tokens, and vice versa.

39.5Deprecation and retirement

Anthropic does not keep every model running forever. A model moves through stages:

ActiveCurrent and recommended
LegacyStill available, but newer models exist
DeprecatedA retirement date is announced; migrate now
RetiredAPI requests to it no longer work

Deprecation is the warning; retirement is the switch-off. Each current model's documentation also states an earliest retirement date: for the 5.5 family and Fable 5.1, "not before" one year after release (for example, Opus 5.5 not before 22 September 2027).

Act now if you use Sonnet 4.5

Claude Sonnet 4.5 retires on 30 November 2026, three weeks after this chapter's review date. Any script, CI job or integration still calling it will start failing then. The lab below finds such references.

Retired is not deleted

Anthropic has committed to preserve the weights of publicly released models for at least the lifetime of the company (Chapter 38). A retired model is switched off for API use, not destroyed. That does not help your code, though: requests to a retired model ID still fail.

Under the hood: why models get retired at all

Every model available through the API needs dedicated hardware capacity, monitoring, safety classifiers and support. Keeping dozens of old models running ties up chips that could serve newer, usually cheaper and better models. Published deprecation dates are a compromise: customers get warning and time to migrate, and Anthropic can free up capacity.

For testers, the important consequence is that a model version is a dependency with an expiry date, just like a browser version or an operating system. Your test plan for any AI feature should include "what happens when we change model?" (Chapter 36 covers regression testing across models).

"""model_audit.py - find Claude model IDs in a project and report their status.

Status table: Anthropic model deprecations page, checked 9 November 2026.
Re-check https://platform.claude.com/docs/en/about-claude/model-deprecations
before you rely on it: this table will go out of date.
"""
import re
import sys
from pathlib import Path

# (family, version) -> (status, note)
STATUS = {
    ("instant", "1"): ("RETIRED", "retired 6 Nov 2024"),
    ("claude", "1"): ("RETIRED", "retired 6 Nov 2024"),
    ("claude", "2"): ("RETIRED", "retired 21 Jul 2025"),
    ("claude", "2.1"): ("RETIRED", "retired 21 Jul 2025"),
    ("sonnet", "3"): ("RETIRED", "retired 21 Jul 2025"),
    ("opus", "3"): ("RETIRED", "retired 5 Jan 2026"),
    ("haiku", "3"): ("RETIRED", "retired 20 Apr 2026"),
    ("sonnet", "3.5"): ("RETIRED", "retired 28 Oct 2025"),
    ("haiku", "3.5"): ("RETIRED", "retired 19 Feb 2026"),
    ("sonnet", "3.7"): ("RETIRED", "retired 19 Feb 2026"),
    ("opus", "4"): ("RETIRED", "retired 15 Jun 2026"),
    ("sonnet", "4"): ("RETIRED", "retired 15 Jun 2026"),
    ("opus", "4.1"): ("RETIRED", "retired 5 Aug 2026"),
    ("sonnet", "4.5"): ("DEPRECATED", "retires 30 Nov 2026 - migrate now"),
    ("haiku", "4.5"): ("LEGACY", "still available; plan a move"),
    ("opus", "4.5"): ("LEGACY", "still available; plan a move"),
    ("opus", "4.6"): ("LEGACY", "still available; plan a move"),
    ("sonnet", "4.6"): ("LEGACY", "still available; plan a move"),
    ("opus", "4.7"): ("LEGACY", "still available; plan a move"),
    ("opus", "4.8"): ("LEGACY", "still available; plan a move"),
    ("fable", "5"): ("LEGACY", "still available; plan a move"),
    ("sonnet", "5"): ("LEGACY", "still available; plan a move"),
    ("opus", "5"): ("LEGACY", "still available; plan a move"),
    ("fable", "5.1"): ("CURRENT", "not retired before 1 Sep 2027"),
    ("opus", "5.5"): ("CURRENT", "not retired before 22 Sep 2027"),
    ("sonnet", "5.5"): ("CURRENT", "not retired before 28 Sep 2027"),
    ("haiku", "5.5"): ("CURRENT", "not retired before 7 Oct 2027"),
}

# Three naming styles Anthropic has used over the years:
#   claude-2.1, claude-instant-1.2            (2023)
#   claude-3-5-sonnet-20240620                (Claude 3 to 3.7: number first, then family)
#   claude-opus-4-1-20250805, claude-opus-5-5 (Claude 4 onward: family first)
OLD = re.compile(r"\bclaude-(instant-)?(\d)(?:\.(\d))?(?![-.\w])")
MID = re.compile(r"\bclaude-(\d)(?:-(\d))?-(opus|sonnet|haiku)\b")
NEW = re.compile(r"\bclaude-(opus|sonnet|haiku|fable|mythos)-(\d)(?:-(\d)(?!\d))?")


def find_ids(text):
    """Yield (matched_text, family, version) for every model ID in text."""
    for m in MID.finditer(text):
        version = m.group(1) + ("." + m.group(2) if m.group(2) else "")
        yield m.group(0), m.group(3), version
    for m in NEW.finditer(text):
        version = m.group(2) + ("." + m.group(3) if m.group(3) else "")
        yield m.group(0), m.group(1), version
    for m in OLD.finditer(text):
        family = "instant" if m.group(1) else "claude"
        version = m.group(2)
        if m.group(3) and not (family == "claude" and m.group(2) == "2" and m.group(3) == "0"):
            version += "." + m.group(3)
        if family == "instant":
            version = m.group(2)  # all Instant 1.x share one status
        yield m.group(0), family, version


def main(folder):
    suffixes = {".py", ".js", ".ts", ".json", ".yml", ".yaml", ".env", ".toml", ".md", ".txt"}
    worst = 0
    found = 0
    for path in sorted(Path(folder).rglob("*")):
        if not path.is_file() or path.suffix not in suffixes:
            continue
        if any(part in {"node_modules", ".git", ".venv"} for part in path.parts):
            continue
        lines = path.read_text(encoding="utf-8", errors="ignore").splitlines()
        for n, line in enumerate(lines, start=1):
            for text, family, version in find_ids(line):
                found += 1
                status, note = STATUS.get((family, version), ("UNKNOWN", "check the models overview page"))
                if family == "mythos":
                    status, note = "RESTRICTED", "verified organisations only"
                print(f"{status:<11} {path}:{n}  {text}  ({note})")
                if status in {"RETIRED", "DEPRECATED"}:
                    worst = 1
    print(f"\n{found} model ID(s) found.", "Action needed." if worst else "Nothing retired or deprecated.")
    return worst


if __name__ == "__main__":
    sys.exit(main(sys.argv[1] if len(sys.argv) > 1 else "."))

Common misunderstandings
"Opus is always the most capable Claude."
Since June 2026, Fable sits above Opus. Anthropic still recommends starting with Opus 5.5 for most workloads (Chapter 40).
"A bigger version number is always better at everything."
Usually newer is better overall, but behaviour, cost per task and token counts change. Test your own tasks when you upgrade.
"Claude 3.5 Sonnet is one model."
There were two, from June and October 2024, with different IDs. Both are now retired.
"Deprecated means it has stopped working."
Deprecated means a retirement date is set. It stops working at retirement.
"Fable is just Opus renamed."
Fable is a separate tier above Opus, with its own price and behaviour, and the same underlying model as Mythos.

39.6Review

Key takeaways
  • Claude launched on 14 March 2023; Claude 2 (July 2023) opened claude.ai to the public; Claude 2.1 brought 200K context.
  • Claude 3 (March 2024) introduced Haiku, Sonnet and Opus. Fable became a new top tier in June 2026.
  • 3.5 Sonnet brought Artifacts; the October 2024 release added computer use; 3.7 Sonnet (Feb 2025) was the first hybrid reasoning model and arrived with Claude Code.
  • The current models (Nov 2026) are Fable 5.1, Opus 5.5, Sonnet 5.5 and Haiku 5.5, all with 1M-token context and adaptive thinking.
  • Model IDs changed style three times; from 4.6 they are undated, pinned snapshots.
  • Models go active, legacy, deprecated, retired. Sonnet 4.5 retires on 30 November 2026.
  • Treat model versions as dependencies with expiry dates: pin them, scan for them, and retest when you change them.
