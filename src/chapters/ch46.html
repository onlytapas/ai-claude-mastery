Before you start: You should be able to start a chat and pick a model (Chapter 43) and write a clear prompt (Chapter 44). It helps to know what a context window is (Chapter 20). For the lab you need a claude.ai account (the Free plan works) and a text editor.

You can hand Claude documents, images and data files instead of pasting text. Claude reads them in different ways: a PDF can be read for both words and pictures, a Word file is mostly read as text, an image is "seen" by the model, and a spreadsheet is usually opened by Claude writing and running small programs in a private sandbox. The same sandbox lets Claude hand back real files: a Word report, an Excel workbook, a slide deck or a PDF. Knowing which path your file takes tells you how far to trust the answer and how to check it. And because everything you upload leaves your computer, the first question is always: am I allowed to share this?

46.1Why files instead of copy and paste

You could paste the text of a test plan into the message box. Uploading the file is usually better for three reasons. First, it keeps structure: tables, headings and page numbers survive, so Claude can say "on page 4, table 2". Second, some content can't be pasted at all, like a screenshot or a chart in a PDF. Third, with spreadsheets Claude can run real calculations over every row rather than estimating from what it sees.

The everyday flow is simple: in a chat, use the attach control (a paperclip or "+" button next to the message box at the time of writing), drag a file into the window, or paste an image from your clipboard. Then ask your question about it. The exact buttons move between app versions, so treat any UI location in this chapter as liable to change.

In everyday life

Pasting text is like reading a document aloud to a colleague over the phone. Uploading the file is like handing them the printed copy: they can see the tables, flip to page 12 and point at the chart. Handing over a spreadsheet with code execution turned on is like giving them the actual file on a laptop with Excel open, so they can sort and filter rather than eyeball.

Two help articles, two numbers

On 9 November 2026 the upload article said 500 MB per file in a chat, while the file-creation article said 30 MB for uploads and downloads. They may describe different paths (reading a file into the conversation versus putting it in the sandbox), or one may be out of date. In practice, keep files small and split anything big. If an upload fails, the limit you hit is the one that applies to you today.

A size limit is not the only limit. Everything Claude reads goes into its context window, which is measured in tokens. A 900-page PDF read as text can fill most of the window, leaving less room for your conversation, and it also uses your plan's usage allowance faster. The pricing page says it plainly: how fast you reach a limit "depends on the model you use, how long your chats are, and how large your files are".

Under the hood: three ways a file reaches the model

Text extraction. For DOCX, TXT, HTML and similar, the app pulls out the words and gives them to the model as text. Layout, colours and embedded pictures are lost. A test plan in Word reads fine; a Word document that is mostly screenshots reads as nearly empty.

Visual reading. For images, and for PDF pages within the visual limit, the page is turned into image input as well. A vision component converts the picture into visual tokens that the language model attends to alongside your words (Chapter 21 covers multimodal models). This is why Claude can describe a chart in a PDF report.

Code in a sandbox. With code execution on, the file is placed in a private computing environment. Claude writes Python (or JavaScript), runs it, reads the output and continues. The file itself may never be loaded into the context window in full: Claude reads the parts it needs through code. That is how it can handle a spreadsheet with tens of thousands of rows that would never fit as plain text.

46.3PDFs and documents: specs, test plans and reports

For QA work, documents are the daily bread: requirement specs, test plans, release notes, vendor test reports, audit evidence. Good prompts point Claude at a specific job and ask it to show where it found things.

Prompt: review a requirements PDF
The attached PDF is the requirements spec for the new checkout flow.
1. List every requirement that has no clear acceptance criterion.
2. List requirements that contradict each other.
3. For each item, quote the sentence and give the page number.
Do not invent requirements that are not in the document.
If something is ambiguous, say so rather than guessing.
Real-world example

A tester receives a 60-page vendor specification two days before sprint planning. She uploads it and asks for untestable requirements with page references. Claude flags "the page should load quickly" (no number) and two sections that disagree on the password length. She checks each quote against the PDF, then raises three questions in the Jira story before planning instead of during testing.

Quote and check

Asking for quotes and page numbers is the single best habit with documents. It turns a vague summary into claims you can verify in seconds, and it makes hallucination easy to spot: if the quoted sentence isn't on that page, you know not to trust that item.

Remember the 100-page line. A 300-page PDF is read as text only, so a question about a diagram on page 210 may get a confident but wrong answer. Split long PDFs or extract the pages you care about.

46.4Images and screenshots for bugs

Screenshots are where Claude's vision becomes useful for testers. You can paste a screenshot straight into the chat and ask Claude to:

  • write a clear bug report from a screenshot plus your notes (title, steps, expected, actual);
  • compare two screenshots (before and after a release) and list visible differences;
  • read an error dialog or a stack trace captured as an image;
  • spot obvious layout or accessibility problems, such as low-contrast text or truncated labels;
  • turn a whiteboard photo of a test strategy into a tidy list.
Prompt: bug report from a screenshot
Screenshot attached: the order confirmation page on staging, Safari 18, iPhone viewport.
What I did: added 2 items, applied code SAVE10, paid with the test Visa card.
Write a Jira bug report with: Title, Environment, Steps to reproduce,
Expected result, Actual result, Severity suggestion with reason.
Only describe what is visible in the screenshot or stated by me.
CaptureScreenshot with the problem visible
RedactBlur names, emails, tokens
DescribeAdd steps and environment in words
AskRequest a structured report
VerifyCheck every line against reality
Vision has limits

Claude can misread tiny text, mis-count items in a dense table and miss off-by-one-pixel layout shifts. It cannot measure exact colours or pixel positions from a picture reliably. For true visual regression, use a tool built for it (Chapter 123), and use Claude to explain and write up what the tool finds.

A screenshot only shows what was on screen. Claude doesn't know the steps you took, the test data or the build number unless you tell it. The "Describe" step in the flow above is the one people skip, and it's the one that makes the report useful.

46.5Spreadsheets and CSV analysis

A CSV file is a plain-text table: one row per line, columns separated by commas. Test tools export results this way all the time. Excel files (XLSX) hold the same kind of table plus formatting, formulas and several sheets.

With the code execution capability on, Claude doesn't guess at your data. It loads the file in the sandbox with Python, runs calculations and reports results, often with a chart. You can usually expand the steps to see the code it ran. Without code execution, Claude can still read a small CSV as text, but its sums and averages are then the model's mental arithmetic, which is much less reliable on large tables.

Good questions for data

"What is the pass rate per suite, excluding skipped tests?" "Which tests changed status between runs?" "Plot the ten slowest tests." "Group failures by error message and count them." "Which columns have missing values?"

Questions to handle with care

"Why did these tests fail?" (the data may not say). "Is the release ready?" (a judgement for people). "Predict next week's failure rate" (a small dataset can't support it). Ask Claude to separate what the data shows from what it is guessing.

Real-world example

A QA lead exports a month of nightly CI results to CSV and asks for tests that alternated between pass and fail with no code change. Claude computes the list in Python, plots a timeline, and labels these as flaky candidates rather than proven flaky tests. The lead takes the top five to the team's stabilisation backlog.

Under the hood: how to check Claude's numbers

Treat Claude's analysis like a junior colleague's spreadsheet: probably right, worth a spot check. Three cheap checks catch most problems:

  1. Row count. Ask "How many rows did you load, and how many columns?" If it doesn't match the file, something went wrong at load time (often a bad header row or a different delimiter).
  2. One known number. Work out one figure yourself with a filter in Excel, and compare.
  3. Definitions. Ask how a metric was computed. "Pass rate" with and without skipped tests can differ a lot, as the lab shows.

Ask Claude to show the code it ran. Even if you can't write Python, you can usually read a line like df[df.status != "skip"] and see that skipped rows were excluded.

46.6Creating files: Word, Excel, PowerPoint and PDF

Claude can also hand files back. According to the help centre, it can create and edit Excel (.xlsx), PowerPoint (.pptx), Word (.docx) and PDF files, and can also produce things like Python scripts, PNG charts, and plain text files such as .csv, .md and .html. The feature launched on 9 September 2025 and is available on all plans, including Free, on the web, desktop and mobile apps.

It works through the same sandbox: Claude writes code that builds the file, runs it, and gives you a download. Anthropic's ready-made Skills for docx, xlsx, pptx and pdf hold the know-how for producing well-formed files (Chapter 80 explains Skills in depth). You don't need to call them by name; asking for "a Word document" or "an Excel workbook with a summary sheet" is enough.

Prompt: a release test summary as Word and Excel
Using the attached test-run CSV, create two files:
1. release-summary.docx: one page. Heading "Release 4.2 test summary",
   a short paragraph, a table of pass rate per suite (excluding skipped),
   and a bullet list of failing tests.

Ask for formulas, not just values

If you want to keep using a spreadsheet, ask Claude to use real Excel formulas. Pasted numbers look the same but go stale the moment the raw data changes. Open the file and click a cell to confirm.

Security warning from Anthropic

The help centre warns that instructions hidden in a file or web page could trick Claude into running untrusted code in the sandbox, or into sending data from your conversation to a third party. This is prompt injection (Chapter 131). Keep network access as narrow as you can, watch what Claude does with files from outside your organisation, and stop it if it starts reaching for data you didn't expect.

Files Claude creates are often also shown as artifacts beside the chat. Chapter 48 covers artifacts, including documents and slides you can export to Word, PowerPoint and PDF.

46.7Privacy: what happens to what you upload

Uploading a file sends its contents to Anthropic's servers so the model can read it. Before you drag anything in, ask three questions.

  1. Am I allowed to? Your company's AI policy decides which data may go into which tool. Many companies allow a Team or Enterprise workspace and forbid personal accounts for work data.
  2. Which account am I on? Anthropic's data-usage documentation says consumer accounts (Free, Pro, Max and Ultra) have a setting that decides whether chats may be used to train future models, with a 5-year retention period if you allow it and 30 days if you don't. Commercial accounts (Team, Enterprise, API) are not used for training by default and have a standard 30-day retention period, with options such as custom retention on Enterprise. Check your current settings at the privacy controls page, and see Chapter 42 for organisation options and Chapter 132 for privacy in depth.
  3. Do I need the real data? Usually not. Replace names, emails, card numbers and tokens with fake values first. This is data masking, and for test work it rarely changes the answer.
Screenshots leak

Screenshots are the easiest way to leak data by accident: a customer's address in a form, an access token in a browser's address bar, a colleague's chat message in a notification. Crop and blur before you paste. The same applies to log files, which often contain session IDs and email addresses.

Incognito is not a privacy shield for your company

Incognito chats (Chapter 50) are not saved to your chat history or memory. They still send the file to Anthropic to be processed. They don't make a file you weren't allowed to share acceptable to share.

Opinion · common guidance from security teams

Many security teams recommend a simple rule for testers: "synthetic data by default, masked data when needed, real customer data never in a chat tool unless your data-protection officer has approved that exact use." It is stricter than the tools require, and that is the point.

Common misunderstandings
"If Claude accepted the file, it read all of it, including the pictures."
Only PDFs up to 100 pages and images get visual reading. Word files and long PDFs are read as text, so embedded screenshots and charts may be invisible to Claude.
"Claude's spreadsheet totals are always exact."
With code execution they are calculated by real code and are usually right, but the definition (for example, whether skips count) and the loading step can still be wrong. Without code execution, they are mental arithmetic. Spot-check one number.
"Incognito means I can upload confidential files."
Incognito affects history and memory, not whether the data leaves your machine. Company policy and your account type decide what you may upload.
"File creation needs a paid plan."
The help centre lists it on all plans, including Free. It does need the capability turned on, and on Team and Enterprise an owner decides.

46.8Review

Key takeaways
  • Claude accepts documents (PDF, DOCX, TXT and more), data (CSV, XLSX) and images (JPEG, PNG, GIF, WebP), up to 20 files per chat. Check the help centre for current size limits, which differ between articles.
  • PDFs up to 100 pages are read for text and visuals; 101 to 1000 pages for text only. Other documents are text-only.
  • With code execution on, Claude analyses spreadsheets by running real code in a sandbox; ask it to show the code and check one number yourself.
  • Claude creates Word, Excel, PowerPoint and PDF files through the same sandbox, controlled by the "Code execution and file creation" capability, which owners control on Team and Enterprise.
  • Screenshots make good bug reports when you add steps and environment in words, and redact anything sensitive.
  • Before uploading: is it allowed, which account am I on, and can I use masked or synthetic data instead?
Check yourself

You upload a 350-page PDF and ask about a chart on page 220. What should you expect?

Between 101 and 1000 pages, only text is processed. Uploads are rejected only above 1000 pages.

Why is it better to have code execution on when analysing a large CSV?

The sandbox runs Python on the actual data. It doesn't change where the data goes.

A Word test plan full of embedded screenshots gets a thin summary from Claude. The most likely reason is:

Export it to PDF (under 100 pages) or attach the key screenshots as images.

On a Team plan, you can't find the setting to create files. Who can change that?

On Team and Enterprise, owners turn capabilities on or off for the organisation.

Which habit best protects against invented details when summarising a long spec?

Quotes with locations turn claims into something you can verify in seconds.

Assignment

Take a real (or masked) export from your team's test tool: a CSV of last week's runs, or a test-plan PDF. Write a short "file-handling card" for your team: which file types you use, which account people should use for them, what must be masked first, and three prompts that worked well (one summary, one analysis with numbers you verified, one file creation). Share it in your team channel and ask one colleague to try a prompt and report back.

Teach it

"You can give Claude files instead of pasting text. PDFs up to 100 pages are read for words and pictures, Word files only for words, and screenshots are 'seen' directly. For spreadsheets, turn on code execution: Claude then runs real code over the data, and can even hand you back an Excel or Word file. Always ask it to show its working and check one number. And before uploading anything, ask whether you're allowed to, which account you're on, and whether fake data would do."
