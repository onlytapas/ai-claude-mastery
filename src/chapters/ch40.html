As of 9 November 2026, Anthropic offers four current Claude models. Fable 5.1 is the most capable and the most expensive. Opus 5.5 is the one Anthropic tells most people to start with. Sonnet 5.5 is faster and cheaper, and Haiku 5.5 is the fastest and cheapest by far. All four can read up to a million tokens at once. Choosing well means starting with Opus 5.5, measuring how well it does on your task, and then moving up to Fable or down to Sonnet or Haiku based on evidence rather than habit.

40.1The lineup in one picture

Claude comes in named tiers. A tier is a size level within the family. Larger tiers usually think harder and get more right on difficult work, but they are slower and cost more per token. Since June 2026 there have been four tiers rather than three, because Anthropic added Fable above Opus.

In everyday life

Think of a consultancy with four grades of staff. The senior partner (Fable) takes the hardest, longest engagements and charges the most. The principal consultant (Opus) handles most serious client work well and is who you usually ask first. The consultant (Sonnet) is quick and capable for routine projects. The analyst (Haiku) clears huge volumes of simple, well-defined tasks at a tiny fraction of the cost. You wouldn't send the partner to sort the post, and you wouldn't send the analyst to negotiate the merger.

40.2What Fable is (and what Mythos is)

"Fable" is the newest name in the family and the one people most often misunderstand. It is not a rename of Opus. It is a new tier that sits above Opus.

When Anthropic launched Claude Fable 5 on 9 June 2026, it described it as "a Mythos-class model that we've made safe for general use", and as its most capable generally available model. Fable 5.1 followed on 1 September 2026.

To understand that sentence you need to know about Mythos. In April 2026 Anthropic previewed a very capable model called Claude Mythos Preview, but only to invited partners in a cybersecurity programme called Project Glasswing (Chapter 38). Its abilities, especially in finding software vulnerabilities, were judged too risky for open release. Fable is the same underlying model as Mythos, released with extra safeguards. Anthropic's documentation says Mythos is "the same underlying model" as Fable "with the safeguards lifted in some areas". Mythos 5.1 has the same specifications and prices as Fable 5.1, but only organisations verified through programmes such as the Cyber Verification Program can use it.

One underlying modelVery capable, including at security work
Fable 5.1General release, with safety classifiers switched on
Mythos 5.1Same model, some safeguards lifted, verified organisations only

The safeguards are classifiers: separate checking systems that watch for requests in sensitive areas (cybersecurity, biology and chemistry, and attempts to copy the model's skills by distillation). When a classifier flags a request, Claude doesn't simply refuse. The request is answered by the next-most-capable model instead. At Fable 5's launch that fallback was Opus 4.8, and Anthropic said more than 95% of sessions involved no fallback at all.

Real-world example

A security tester asks Fable to analyse a deliberately vulnerable demo app for injection flaws. Part of the request trips the cybersecurity classifier. The answer still arrives, but from the fallback model, so it may be less thorough than Fable would have been. If your team's real job is security testing and you keep hitting this, the official route is a verification programme, not prompt tricks. For ordinary functional and API testing you will rarely notice the classifiers.

Under the hood: how Fable differs in the API

The Fable 5.1 model page lists a few behaviours that differ from the other tiers (checked 9 November 2026):

  • Thinking is always on. Fable uses adaptive thinking on every request: it decides how much to reason before answering. You cannot switch it off.
  • Default effort is high, compared with medium for Opus 5.5.
  • Forcing a specific tool returns an error. In the API you can normally tell Claude "you must call this tool now" (forced tool use). On Fable 5.1 that returns an error, so code written for other models may need a small change.
  • Cache reads are cheaper relative to input: 0.025 times the base input price ($0.25 per million tokens), against 0.05 times for Opus and Sonnet 5.5. Prompt caching is covered in Chapter 90.

Fable also arrived with a plan change worth knowing. Fable 5 was included in Pro, Max, Team and seat-based Enterprise plans only until 22 June 2026; after that it needed usage credits on most plans. As of November 2026 the pricing page says Max includes Fable "up to half your weekly limit", and Pro reaches it only through usage credits. Chapter 42 covers plans.

40.3The numbers that matter, in plain words

Context window: 1 million tokens for all four

The context window is how much text the model can consider at once: your instructions, the conversation so far, attached files and its own reply. One million tokens is very roughly a few thousand pages of ordinary prose. In QA terms you can paste a long requirements document, a full test plan and a large log file into one request. Chapter 20 explains why "fits in the window" does not mean "used equally well": quality can drop when the window is crowded, so a tidy, relevant context still beats a huge one.

Tokens are not words

Claude models from 4.7 onward use a newer tokenizer that Anthropic says produces "approximately 30% more tokens for the same text". If you compare costs with an old spreadsheet built on Claude 4.5 or earlier, the same document now counts as more tokens. See Chapter 14.

Maximum output: 128K tokens

This is the most the model can write in one reply to a normal request. It is far more than you need for a bug report or a set of test cases. For very large generation jobs, Opus 5.5, Sonnet 5.5 and Haiku 5.5 can write up to 300K tokens per reply through the Message Batches API with a beta setting. Fable 5.1's documented limit is 128K.

Price: input, output and discounts

You pay separately for what you send (input) and what Claude writes (output). Output costs five times input on every current model. Two discounts matter for QA work:

  • Batch processing: the Message Batches API is 50% cheaper. You submit many requests together and collect the answers later (most batches finish within an hour). Ideal for overnight jobs such as classifying yesterday's test failures.
  • Prompt caching: if many requests start with the same long text (a style guide, a test-case template), the repeated part can be read from a cache at a small fraction of the input price.

Haiku 5.5 has two prices. Prompts up to 100K tokens cost $0.10 in and $0.50 out per million. Above 100K they cost five times as much ($0.50 / $2.50). That is still cheap, but it means Haiku is at its best on short, frequent requests.

Thinking costs output tokens

Fable 5.1 and Opus 5.5 always think before answering, and the others can. Thinking tokens are billed as output tokens. A short visible answer can still carry a lot of hidden reasoning cost, especially at high effort. Measure real usage from the API's usage figures rather than estimating from the length of the reply.

Effort and thinking

An effort level tells Claude how hard to work: how much to think, how thoroughly to check, how many tool calls to make. The levels are low, medium, high, xhigh and max. Higher effort usually means better answers on hard problems, at the cost of time and tokens. Chapter 19 explains the idea.

Defaults differ by model and by product. In the Claude API, Fable 5.1 and Sonnet 5.5 default to high, while Opus 5.5 and Haiku 5.5 default to medium. Claude Code's own documentation says it runs Opus 5.5, Sonnet 5.5 and Haiku 5.5 at medium by default. So the same model can behave a little differently in two products simply because effort is set differently. If results surprise you, check the effort before blaming the model.

Under the hood: "extended thinking" versus "adaptive thinking"

Older Claude models used extended thinking: you switched thinking on and set a fixed token budget for it (budget_tokens). Anthropic deprecated that manual mode on Opus 4.6 and Sonnet 4.6, and later models don't accept it. Current models use adaptive thinking: the model decides how much to think, guided by the effort level. Sonnet 5.5 also offers a between_tools option that skips up-front thinking and reasons only between tool calls, which can speed up agent loops. If you have old code that sets budget_tokens, it needs updating before you switch to a 5.x model.

40.4Anthropic's advice: start with Opus 5.5

Anthropic's models overview gives a clear default. Start with Opus 5.5 "for most workloads". Move to Fable 5.1 only when your evaluations show that Opus 5.5, even at a higher effort level, still falls short.

The reasoning is practical. Fable costs two and a half times as much as Opus per token, is slower, and refuses forced tool use. Opus 5.5 is strong enough for most professional work. And raising Opus's effort is a cheap first lever: you may get the quality you need without changing model at all.

Opinion · common practice among teams that run evals

Many engineering teams argue that the "move down" step matters more than the "move up" step. In their experience, most bulk jobs (labelling, extraction, routing) work fine on a smaller model, and the savings pay for the time spent testing. This is a widely held view, not a guarantee: only your own eval set can tell you whether it holds for your task.

Speed options

If you need Opus quality but faster replies, Anthropic offers a fast mode for Opus 5.5 on the Claude API, and Claude Code has a matching /fast toggle. Check the pricing page for what fast mode costs before switching it on for a big job.

Real-world example

A QA lead wants every overnight CI failure summarised and labelled "product bug", "test bug" or "environment" before stand-up. On a sample of 100 past failures with known answers (illustrative), she runs Opus 5.5, Sonnet 5.5 and Haiku 5.5. If Haiku scores close to Opus on this narrow task, she picks Haiku with the Batch API and spot-checks a few labels each morning. She records the scores and the date, because a model update could change the result.

Choosing inside the products

  • Claude apps (web, desktop, mobile): pick a model from the model selector in the chat box. Which models you see depends on your plan; the Free plan offers Sonnet and Haiku only. Chapter 43 shows where the controls are.
  • Claude Code: use /model to switch, or start with claude --model sonnet. Aliases such as opus, sonnet, haiku and fable resolve to the current model of each tier on the Anthropic API. The default alias resolves to Opus 5.5 on Pro, Max, Ultra, Team, Enterprise and the API. Chapter 68 covers model and effort settings in depth.
  • Claude API: put the exact ID, such as claude-sonnet-5-5, in the model field. From the 4.6 generation onward, IDs carry no date and each points to a fixed snapshot.
Cloud platforms may differ

On Amazon Bedrock, Google Cloud and Microsoft Foundry, Claude Code's aliases can resolve to older models (for example, sonnet resolving to Sonnet 4.5), and partners set their own prices. If your company reaches Claude through a cloud provider, pin full model names and check that provider's price list.

Older models you may still meet

Several earlier models are still available as "legacy" models, including Fable 5, Opus 5, Opus 4.8, Sonnet 5, Sonnet 4.6 and Haiku 4.5. Existing integrations often still point at them. Some are priced differently from their successors: Opus 5 is $5 / $25 per million tokens, more than Opus 5.5's $4 / $20, and Haiku 4.5 is $1 / $5, ten times Haiku 5.5's short-prompt price. Moving to the current model can be both better and cheaper, but test first. Sonnet 4.5 is deprecated and retires on 30 November 2026, so anything still using it needs moving now. Chapter 39 has the full history of retirements.

    model_cost.py
    # model_cost.py - estimate the API cost of one QA job on each current Claude model.
# Prices: USD per million tokens, from platform.claude.com pricing, checked 9 Nov 2026.
# Re-check the pricing page before relying on these numbers.

PRICES = {
    # name: (input per MTok, output per MTok)
    "Fable 5.1":  (10.00, 50.00),
    "Opus 5.5":   (4.00, 20.00),
    "Sonnet 5.5": (2.00, 10.00),
    "Haiku 5.5":  (0.10, 0.50),   # prompts up to 100K tokens
}
HAIKU_LONG = (0.50, 2.50)          # Haiku 5.5 prompts over 100K tokens

def cost(model, input_tokens, output_tokens, batch=False):
    price_in, price_out = PRICES[model]
    if model == "Haiku 5.5" and input_tokens > 100_000:
        price_in, price_out = HAIKU_LONG
    dollars = input_tokens / 1_000_000 * price_in + output_tokens / 1_000_000 * price_out
    return dollars * 0.5 if batch else dollars

# Illustrative job: triage 2,000 bug reports.
# Each request: about 1,500 input tokens (instructions + report), 200 output tokens.
JOBS = 2000
IN_PER_JOB = 1500
OUT_PER_JOB = 200

print(f"Job: {JOBS} requests, {IN_PER_JOB} input + {OUT_PER_JOB} output tokens each (illustrative)")
print(f"{'Model':<12}{'Normal':>10}{'Batch':>10}")
for model in PRICES:
    normal = cost(model, IN_PER_JOB, OUT_PER_JOB) * JOBS
    batch = cost(model, IN_PER_JOB, OUT_PER_JOB, batch=True) * JOBS
    print(f"{model:<12}{normal:>10.2f}{batch:>10.2f}")

Common misunderstandings
"Fable is the new name for Opus."
Fable is a separate, higher tier. Opus 5.5 still exists and is the recommended starting point.
"Always use the best model; it's safer."
The most capable model is slower, costs more, and is not always more accurate on simple tasks. Anthropic itself says to start with Opus 5.5 and move up only when evals show a need.
"A bigger context window means it reads everything equally well."
All four accept a million tokens, but crowded context can reduce quality. Send what is relevant.
"The price is per word."
It is per token, input and output priced separately, with thinking billed as output. Newer models also count more tokens for the same text.
"Haiku is a toy."
Haiku 5.5 is designed for real production work in classification, extraction and routing, where speed and volume matter.
"The same model always behaves the same everywhere."
Default effort differs between the API and Claude Code, and cloud platforms may map aliases to older models.

40.6Review

Key takeaways
  • As of 9 November 2026 there are four current models: Fable 5.1, Opus 5.5, Sonnet 5.5 and Haiku 5.5. All have a 1M-token context window and 128K-token maximum output.
  • Fable is a new top tier above Opus: the Mythos-class model with safety classifiers. Mythos is the same model with some safeguards lifted, for verified organisations only.
  • Prices per million tokens (input/output): Fable $10/$50, Opus $4/$20, Sonnet $2/$10, Haiku $0.10/$0.50 for prompts up to 100K tokens. Batch is half price.
  • Anthropic says to start with Opus 5.5 and use Fable 5.1 only when Opus at higher effort still falls short.
  • Choose with your own eval set, try cheaper models for bulk work, and write down the date and results of every decision.

Assignment

Pick one recurring AI task your team does or wants to do (for example, drafting test cases from stories, or labelling CI failures). Build a sample of 20 cases with answers you trust. Run them on Opus 5.5 and on at least one cheaper model, and score the results. Use the lab script to estimate the monthly cost of each. Write a one-page decision record: task, models tried, scores, cost, the model you chose, the date, and when you will re-test.

Teach it
