Your shell is not just a place to type commands. It carries settings (environment variables) that every program you start can read, such as which test environment to use or where to look for programs. Every program you start becomes a process with its own number, which you can list, watch and stop. Every file carries permissions that say who may read it, change it or run it. And curl lets you talk to any web server or API straight from the terminal. Together, these explain most "it works on my machine" mysteries.

56.1Environment variables

A variable is a name with a value attached, like TEST_ENV=staging. An environment variable is one that the shell passes on to every program it starts. Programs read them for settings: which browser to use, which server to test, which API key to send. Names are usually in CAPITALS by convention.

To read a variable, put $ in front of its name. echo prints whatever you give it:

Terminal
echo $HOME
echo $SHELL
echo $USER
Output (on one Mac; yours shows your own user name)
/Users/alex
/bin/zsh
alex

HOME is your home folder (the ~ from Chapter 53), SHELL is your login shell, and USER is your account name. To see all of them, run env (or printenv). It prints one NAME=value per line, usually dozens; pipe it into sort or grep to find what you want: env | grep -i proxy.

Setting, exporting and removing

CommandWhat it does
TEST_ENV=stagingCreate a shell variable. No spaces around =. Only this shell can see it.
export TEST_ENVTurn it into an environment variable, so programs started from this shell inherit it
export TEST_ENV=stagingBoth steps at once (the usual form)
TEST_ENV=uat npx playwright testSet it for that one command only; the shell itself is unchanged afterwards
unset TEST_ENVRemove it

The difference between a shell variable and an exported one is the most common source of confusion, so here is the proof. zsh -c "…" starts a new, separate shell (a child) that runs one command and exits:

Terminal
TEST_ENV=staging
zsh -c 'echo "child sees: ($TEST_ENV)"'
export TEST_ENV
zsh -c 'echo "child sees: ($TEST_ENV)"'
unset TEST_ENV
echo "after unset: ($TEST_ENV)"
Output
child sees: ()
child sees: (staging)
after unset: ()

Before export, the child saw nothing. After it, the child inherited the value. The single quotes stop our shell expanding $TEST_ENV, so the child does it. An unset or unknown variable is simply empty; there's no error.

In everyday life

A shell variable is a sticky note on your own monitor. Exporting it is photocopying the note and stapling it to every task you hand to someone else. They get a copy as it was at that moment. If they scribble on their copy, your note doesn't change, and a child process can never change its parent's variables.

Real-world example: one suite, many environments

A Playwright config can read process.env.BASE_URL, and a pytest fixture can read os.environ["BASE_URL"]. The same test code then runs against any environment: BASE_URL=https://staging.example.test npx playwright test locally, and CI sets BASE_URL for each stage. Secrets such as API tokens are passed the same way, so they never appear in the code (Chapter 98 covers keys and secrets).

Secrets in the terminal

Typing export API_TOKEN=abc123 saves that line in your shell history file. Prefer reading secrets from a password manager or a .env file that is listed in .gitignore, and never paste the output of env into a ticket, chat or AI prompt without removing secrets first.

SystemNotes
LinuxIdentical in Bash and zsh.
Windows PowerShellRead with $env:HOME or $env:USERPROFILE; set for the session with $env:TEST_ENV = "staging"; list with Get-ChildItem env:. In Command Prompt: set TEST_ENV=staging and %TEST_ENV%. Permanent ones are set in System Properties → Environment Variables.

56.2PATH and which

When you type python3, how does the shell know where that program is? It checks PATH, an environment variable holding a list of folders separated by colons. The shell looks in each folder, in order, and runs the first match it finds. The output is hard to read as one long line, so swap the colons for new lines with tr ("translate characters"):

Terminal
echo $PATH | tr ":" "\n"
Output (shortened, from one Mac)
/Users/alex/.local/bin
/usr/local/bin
/usr/bin
/bin
/usr/sbin
/sbin

which tells you which file will run. which -a lists every match on the PATH, in order:

Terminal
which git curl
which -a python3
type ls
Output
/usr/bin/git
/usr/bin/curl
/usr/local/bin/python3
/usr/bin/python3
ls is /bin/ls

This Mac has two python3 programs. Because /usr/local/bin comes earlier in PATH, that one wins. This is the classic cause of "I installed it but the old version still runs" or "it works in my terminal but not in CI". type is the more complete version: it also tells you when a name is an alias, a shell function or a built-in command rather than a file.

If no folder on PATH contains the name, you get the message you'll see more than any other:

Output
zsh: command not found: nosuchtool

It means "not installed" or "installed in a folder that isn't on PATH". Installers often print a line telling you to add their folder.

Adding a folder to PATH

Terminal
export PATH="$HOME/.local/bin:$PATH"   # put the new folder FIRST, keep the old list after it

The $PATH at the end keeps everything that was already there. Forgetting it (writing export PATH="$HOME/.local/bin") replaces the whole list, and suddenly even ls is "command not found". If that happens, just close the terminal window and open a new one: the change only lived in that session.

Under the hood: why the order is a security matter

Because the first match wins, anyone who can write to a folder early in your PATH can make a program called git or ls that runs instead of the real one. That's why the current folder (.) is deliberately not on PATH on macOS and Linux, and why you must type ./run-tests.sh rather than run-tests.sh to run a script in the current folder. Only add folders you own and trust.

SystemNotes
LinuxSame idea. Some minimal systems lack which; command -v git works everywhere.
WindowsPATH entries are separated by ;. PowerShell: $env:Path -split ";" to list, Get-Command git instead of which. Command Prompt: where git.

56.3Making settings permanent: .zshrc

Everything you export disappears when you close the window. To keep a setting, put the line in your shell's start-up file, which the shell runs every time a new interactive terminal opens.

ShellMain start-up fileNotes
zsh (macOS default since 2019)~/.zshrc~/.zprofile runs for login shells, and is where Homebrew's installer suggests adding its line
Bash (default on most Linux)~/.bashrc~/.bash_profile or ~/.profile for login shells
PowerShellthe file named by $PROFILECreate it with New-Item -Force $PROFILE if it doesn't exist

The leading dot makes these hidden files, so use ls -a ~ to see them. To add a line safely:

Terminal
cp ~/.zshrc ~/.zshrc.backup 2> /dev/null   # keep a copy (no error if the file doesn't exist yet)
nano ~/.zshrc                              # add your line at the end, Ctrl+O to save, Ctrl+X to exit
source ~/.zshrc                            # re-read it in this window

Lines you might add:

~/.zshrc (additions)
export PATH="$HOME/.local/bin:$PATH"
export TEST_ENV=staging
alias qa='cd ~/qa-practice'      # an alias is a short nickname for a longer command

source runs the file in the current shell, so the changes apply straight away. Opening a new terminal window does the same. If something breaks after an edit, restore the copy with cp ~/.zshrc.backup ~/.zshrc and open a new window.

Why CI doesn't see your settings

CI runners don't run your personal .zshrc. Anything your tests need (variables, PATH entries) must be set in the pipeline configuration. When a test passes locally but fails in CI with "command not found" or a missing variable, compare env on both.

56.4Processes: ps, top and kill

A process is a program that is currently running. Open the same app twice and you have two processes. Each gets a unique number, its process ID or PID, and each knows its parent: the process that started it. Your terminal's shell is a process, and every command you run from it is a child process.

ps: a snapshot

Terminal
ps

On its own, ps ("process status") lists processes belonging to your terminals, with four columns: PID, TTY (which terminal), TIME (CPU time used so far) and CMD (the command). To see everything on the machine, use the traditional options:

Terminal
ps aux | head -3                  # a = all users, u = user-friendly columns, x = include background processes
ps aux | grep -i chrome           # find a particular program
pgrep -l node                     # shortcut: PIDs and names of processes called node
Column in ps auxMeaning
USERWho owns the process
PIDIts process ID
%CPU, %MEMShare of processor and memory it's using
STATState: R running, S sleeping (waiting), T stopped, Z zombie (finished but not yet cleaned up)
STARTED, TIMEWhen it started; total CPU time used
COMMANDThe full command line, often very long

top: a live view

top shows processes continuously, refreshing every second or so, with a summary of CPU and memory at the top. Press q to quit. On macOS, top -o cpu sorts by CPU and top -o mem by memory; inside Linux top, press P or M. Many people install htop, a friendlier version (brew install htop on macOS). macOS also has Activity Monitor, the graphical equivalent.

Real-world example: the runaway browser

After an interrupted Playwright run your laptop is slow. ps aux | grep -i chrom shows a dozen headless Chromium processes still alive. Their PIDs are in the second column, and you can stop them with kill. Leftover browsers, test servers still holding a port and stuck node processes are everyday QA debugging.

kill: ask a process to stop

Despite its name, kill sends a signal, a small message from the operating system, to a process by PID.

CommandSignalEffect
kill 4321TERM (15)Polite request to finish. The program can tidy up first. Try this first.
Ctrl+C in the terminalINT (2)Interrupt the program running in the foreground
kill -9 4321KILL (9)Forced stop. The program gets no chance to save or clean up. Last resort.
pkill -f playwrightTERMSignal every process whose command line contains "playwright". Check first with pgrep -fl playwright.

You can only signal your own processes unless you use sudo. If kill succeeds it prints nothing (and exit code 0); a wrong PID gives "No such process".

SystemNotes
Linuxps aux, kill, pgrep, pkill are the same. For a one-off top snapshot: top -b -n 1 | head.
WindowsPowerShell: Get-Process (alias ps), Get-Process chrome, Stop-Process -Id 4321. Command Prompt: tasklist and taskkill /PID 4321. Task Manager is the graphical view.

56.5Background jobs: &, jobs, fg and bg

Normally a command runs in the foreground: you wait until it finishes before you get the prompt back. Some commands, such as a local web server your tests need, never finish on their own. Put & at the end to run it as a background job and get your prompt straight back.

Terminal
sleep 300 &      # sleep just waits for 300 seconds: a safe stand-in for a server
jobs
Output
[1] 78216
[1]  + running    sleep 300

[1] is the job number (this shell's own short label) and 78216 is the PID (the system-wide number; yours will differ). jobs lists the jobs started from this shell; the + marks the current one.

Command or keyWhat it does
command &Start in the background
jobsList this shell's jobs (jobs -l adds PIDs)
fg or fg %1Bring job 1 to the foreground (then Ctrl+C stops it)
Ctrl+ZPause (suspend) the foreground program and return to the prompt
bgLet the paused job carry on in the background
kill %1Send TERM to job 1 (the % means job number, not PID)
$!The PID of the most recent background job, handy in scripts

A background job still writes its output to your terminal, which can scramble what you're typing. Redirect it: npm run dev > server.log 2>&1 &. Background jobs usually stop when you close the terminal window.

Start servernpm run dev > server.log 2>&1 &
Waituntil it answers (curl, section 56.7)
Run testsnpx playwright test
Clean upkill %1

npm run dev is the conventional script name in many JavaScript projects; use whatever starts your app. Playwright can also start and stop a server for you through the webServer option in its config.

56.6File permissions, chmod and sudo

macOS and Linux record, for every file, who owns it and what each kind of user may do with it. ls -l shows this as the first column:

Terminal
ls -l hi.sh
ls -ld logs
Output
-rw-r--r--  1 alex  staff  21 Nov  9 14:42 hi.sh
drwxr-xr-x  4 alex  staff  128 Nov  9 14:42 logs

(-d shows the folder itself rather than its contents. On macOS you may also see an @ after the permissions, meaning the file has extra attributes, such as "downloaded from the internet"; ignore it for now.) The ten characters break down like this:

PositionCharacters in -rw-r--r--Meaning
1-Type: - file, d directory, l link
2–4rw-User (owner, here alex): read, write, no execute
5–7r--Group (here staff): read only
8–10r--Others (everyone else): read only

r = read, w = write (change or delete), x = execute (run it as a program; for a folder, enter it). - means "not allowed". These are the file permissions.

chmod: change mode

The file hi.sh is a tiny script. Without the x permission it can't be run:

Terminal
./hi.sh
echo $?
chmod +x hi.sh
ls -l hi.sh
./hi.sh
Output
zsh: permission denied: ./hi.sh
126
-rwxr-xr-x  1 alex  staff  21 Nov  9 14:42 hi.sh
hello

Exit code 126 is the shell's way of saying "found it, but couldn't run it". chmod +x added execute for everyone, and then it ran. chmod takes two styles of instruction:

Symbolic

who (u user, g group, o others, a all) + action (+ add, - remove, = set exactly) + what (r, w, x).

chmod u+x run.sh lets only you run it. chmod go-w notes.txt stops group and others changing it.

Numeric

Three digits for user, group, others. Each digit adds up read = 4, write = 2, execute = 1.

755 = rwxr-xr-x (scripts and folders). 644 = rw-r--r-- (normal files). 600 = rw------- (private files such as keys).

Don't "fix" errors with chmod 777

777 gives everyone on the machine permission to change and run the file. It makes "permission denied" go away and creates a security hole. Grant the smallest permission that works, usually u+x for a script or 600 for a file holding a secret.

sudo: run one command as the administrator

sudo ("superuser do") runs a single command with administrator (root) rights after asking for your password. Root can read, change and delete anything, so sudo switches off the safety net that permissions give you.

  • Use it only when you understand why the command needs it, such as installing into a system folder when the instructions say so.
  • Never paste a sudo command from a website, chat or AI answer that you can't explain line by line.
  • Don't use it to work around "permission denied" in your own folders. If a tool wants sudo for something in your home folder, ownership is probably wrong; fix the cause instead. For example, npm's documentation fixes "permission denied" errors on global installs with a Node version manager or a folder you own, not with sudo (Chapter 58).
  • Your password is not shown as you type it, not even as dots. That's normal. Your account must be an administrator to use sudo.
SystemNotes
LinuxSame rwx model and chmod; groups vary by distribution. sudo is standard (your user must be in the sudo or wheel group).
WindowsUses access control lists instead (icacls shows them) and has no execute bit; PowerShell scripts are controlled by an execution policy (Chapter 57). The equivalent of sudo is "Run as administrator"; recent Windows 11 builds also offer a sudo command that you switch on in Settings. Inside WSL, Linux rules apply.

56.7curl and wget: the web from the terminal

curl sends a request to a URL and prints the reply. It's installed on macOS, most Linux systems and Windows 10 and 11. For testers it's the fastest way to check whether an environment is up, see a status code, or reproduce an API bug without opening Postman. (Chapter 85 explains HTTP, status codes and JSON.)

Terminal
curl -s "https://httpbin.org/get?env=staging"
Output (origin removed)
{
  "args": {
    "env": "staging"
  },
  "headers": {
    "Accept": "*/*",
    "Host": "httpbin.org",
    "User-Agent": "curl/8.7.1"
  },
  "method": "GET",
  "url": "https://httpbin.org/get?env=staging"
}

httpbin.org is a free public service that echoes back what you send, which makes it ideal for practice. Quote URLs: in zsh an unquoted ? is a wildcard and the command fails with no matches found.

OptionMeaning
-sSilent: hide the progress meter
-SWith -s, still show error messages
-IFetch only the headers (a HEAD request); the first line shows the status, e.g. HTTP/2 200
-iInclude the response headers before the body
-o FILE / -OSave the body to FILE / to a file named like the URL
-LFollow redirects
-X POSTUse another method (POST, PUT, DELETE)
-H "Name: value"Add a request header
-d 'DATA'Send a request body (implies POST)
-w "%{http_code}\n"Print chosen details after the transfer, such as the status code or %{time_total}
-fFail: exit with a non-zero code on HTTP errors (400 and above)
Terminal
curl -s -o /dev/null -w "%{http_code}\n" https://example.com
curl -s -o /dev/null -w "%{http_code} %{time_total}s\n" https://httpbin.org/status/404
curl -s -X POST -H "Content-Type: application/json" \
     -d '{"test":"login_valid","status":"PASS"}' https://httpbin.org/post
Output (first two lines; the POST reply echoes your JSON back)
200
404 0.835841s

The first two lines are a smoke test in one line each: throw the body away (-o /dev/null) and print only the status code and time. The backslash \ at the end of a line continues the command on the next line. With an authentication header, never type the token itself; use a variable: -H "Authorization: Bearer $API_TOKEN".

Exit codes from curl

Without -f, curl exits 0 even for a 404 or 500 page, because the transfer itself worked. With -f it fails. curl documents exit code 22 for this; our Mac's curl 8.7.1 returned 22 over HTTP/1.1 (--http1.1) but 56 over HTTP/2. In scripts, test for "not zero" rather than one exact number. A host that doesn't exist gives exit code 6, "Could not resolve host".

wget

wget is a download tool, standard on many Linux systems but not installed on macOS (brew install wget adds it). wget URL saves the file into the current folder; wget -O name URL chooses the file name; -q makes it quiet. It isn't on our test Mac, so no output is shown; on macOS curl -L -O URL does the same job.

Common misunderstandings
"I set the variable, so my tests will see it."
Only if it's exported (or set on the same command line). A plain NAME=value stays inside your shell.
"I added it to .zshrc but it doesn't work."
Already-open windows haven't re-read the file. Run source ~/.zshrc or open a new window. On Linux with Bash, the file is ~/.bashrc.
"kill -9 is the normal way to stop things."
It's the last resort. Plain kill lets the program clean up temporary files and close connections.
"Permission denied means I need sudo."
Usually it means a script lacks x, or you're writing somewhere you shouldn't. Read the message and fix the cause.
"curl's exit code tells me the page worked."
Without -f, a 500 error page is still a successful transfer. Use -f or check %{http_code}.

56.8Review

Key takeaways
  • NAME=value sets a shell variable; export passes it to child programs; NAME=value command sets it for one command; env lists them.
  • PATH is the ordered list of folders searched for commands; the first match wins. which -a and type show what will run.
  • Permanent settings go in ~/.zshrc (macOS) or ~/.bashrc (Linux). Back up before editing; source to reload.
  • Every running program is a process with a PID. ps aux lists, top watches, kill asks politely, kill -9 forces.
  • & runs in the background; jobs, fg, bg, Ctrl+Z and kill %1 manage jobs.
  • rwx for user, group and others; chmod u+x makes a script runnable; avoid 777; use sudo only when you understand why.
  • curl -s -o /dev/null -w "%{http_code}" is a one-line smoke test; add -f to make HTTP errors fail.
Check yourself

You run BASE_URL=https://uat.example.test on its own line, then npx playwright test. The tests don't see BASE_URL. Why?

Use export BASE_URL=…, or put it on the same line as the command.

which -a node prints two paths. Which one runs when you type node?

The shell searches PATH in order and stops at the first match.

What does chmod 600 token.txt do?

6 = read (4) + write (2) for the user; 0 for group and others.

A leftover test server is still running. What should you try first?

Plain kill sends TERM, letting it shut down cleanly. Keep -9 for processes that ignore it.

Why add -f to curl in a health-check script?

Without -f, curl exits 0 whenever the transfer works, even if the server returned an error page. -L follows redirects.
