Everything you can type before Claude Code opens is part of its command-line interface, or CLI. You type claude, optionally followed by a subcommand (like mcp or update), flags (like --model opus) and a prompt. Flags change how a session starts; subcommands do a different job altogether without opening a chat. This chapter lists them all, checked against the installed program and Anthropic's documentation, so you never have to guess.

Which version this describes

Everything here was checked on 9 November 2026 against Claude Code 2.1.319: the output of claude --help and each subcommand's --help on a real installation, plus the official CLI reference at code.claude.com/docs/en/cli-reference. Claude Code updates often. Run claude --version to see yours, and claude --help to see what your version offers.

75.1How to read a usage line

Every command-line program describes itself with a "usage line". Here is Claude Code's, exactly as claude --help prints it:

From claude --help
Usage: claude [options] [command] [prompt]

Read it left to right like a sentence with optional parts:

PartWhat it meansExample
claudeThe program you are runningclaude
[options]Flags that change behaviour. Square brackets mean "optional".--model sonnet
[command]A subcommand: a separate job such as managing MCP serversmcp list
[prompt]Text to send as your first message"explain this repo"
<name>Angle brackets mean "required; replace with a real value"claude attach <id> → claude attach 7f3a
a|bA vertical bar means "one of these"--output-format text|json|stream-json
..."You can give more than one"--add-dir ../api ../web

Short and long flags

Many flags have a short form (one dash, one letter) and a long form (two dashes, a word). They do the same thing. -p and --print are identical; so are -c and --continue. Long forms are easier to read in scripts; short forms are quicker to type.

Flags that take a value

Some flags are switches (on if present): --verbose. Others need a value after them: --model opus or --model=opus. A few take an optional value, shown as [value]: --resume alone opens a picker, while --resume my-session resumes that session.

Quoting

Your shell (Chapter 52) splits what you type at spaces. Anything with spaces or special characters must be in quotes, or the shell will break it apart before Claude Code sees it:

# Wrong: the shell sees three separate words
claude -p summarise the failures

# Right: one prompt
claude -p "summarise the failures"

# Tool rules contain brackets and asterisks, so quote each one
claude --allowedTools "Bash(npx playwright test *)" "Read"
In everyday life

Think of ordering at a coffee shop. "Coffee" is the program. "Large, oat milk" are the options. "To take away" is like a subcommand that changes the whole transaction. And "with a note that says 'happy birthday'" is the prompt. You can leave out the extras and still get a coffee.

Real-world example

A CI job needs to fail early if nobody is signed in. claude auth status --text prints a readable status and exits with 1 when signed out, so the next line of the script can stop the job with a clear message instead of a confusing error later.

Easy to mix up
--system-prompt vs --append-system-prompt
The first replaces Claude Code's built-in instructions (it loses its knowledge of how to use its tools well). The second adds to them. Almost always use append.
--tools vs --allowedTools
--tools decides which tools exist at all. --allowedTools decides which existing tools run without asking.
--bare vs --safe-mode
Both switch customisations off. --bare is for scripts: lean, predictable, API-key sign-in only. --safe-mode is for troubleshooting a broken setup while signing in normally.
--cloud vs --remote-control
--cloud runs the session on Anthropic's servers. --remote-control keeps it on your computer and lets you steer it from your phone or browser.

75.5Environment variables

An environment variable is a named setting your shell passes to every program it starts (Chapter 56). Set one for a single command by putting it in front (MCP_TIMEOUT=10000 claude), for the whole shell with export, or for Claude Code only in the "env" block of a settings file (Chapter 78). These are the ones ordinary users and CI pipelines need; the official list at code.claude.com/docs/en/env-vars has many more.

Which sign-in wins when several are set?

Claude Code checks credentials in a fixed order and uses the first it finds: cloud-provider variables (Bedrock, Agent Platform, Foundry), then ANTHROPIC_AUTH_TOKEN, then ANTHROPIC_API_KEY, then an apiKeyHelper script, then CLAUDE_CODE_OAUTH_TOKEN, then other Anthropic profile credentials, and finally your normal /login subscription sign-in. This is why an old API key in your shell profile can silently take over from your subscription. Run /status in a session, or claude auth status in the shell, to see which one is active.

75.6Recipes for QA work

These combinations come up again and again in testing. Each uses only flags from the tables above.

1. Summarise test failures in CI, safely

claude -p "Read test-results/junit.xml and summarise failures by likely cause as a Markdown table" \
  --allowedTools "Read" \
  --permission-prompts none \
  --max-budget-usd 1 \
  > failure-summary.md

Only reading is allowed; anything else that would need permission is denied automatically; spending stops at one US dollar; the answer goes into a file the pipeline can post or attach.

2. Get machine-readable output a script can trust

claude -p "Classify each failing test in results.xml as product-bug, test-bug or flaky" \
  --output-format json \
  --json-schema '{"type":"object","properties":{"tests":{"type":"array","items":{"type":"object","properties":{"name":{"type":"string"},"verdict":{"type":"string","enum":["product-bug","test-bug","flaky"]}},"required":["name","verdict"]}}},"required":["tests"]}'

The schema forces a predictable shape (a list of tests, each with one of three verdicts), which a later pipeline step can read without guessing.

3. Reproducible runs: same behaviour on every machine

claude --bare -p "Run npx playwright test and report the result" \
  --append-system-prompt-file ci-instructions.md \
  --mcp-config ci-mcp.json --strict-mcp-config \
  --allowedTools "Bash(npx playwright test *)" "Read"

--bare ignores whatever CLAUDE.md, hooks and plugins happen to be on the machine; you pass the instructions and MCP servers explicitly, so the run behaves the same everywhere. Remember that --bare signs in only with ANTHROPIC_API_KEY or an apiKeyHelper.

4. Lock down what can run

claude --permission-mode dontAsk \
  --allowedTools "Read" "Grep" "Bash(npm test *)" \
  --disallowedTools "Bash(git push *)" "WebFetch"

dontAsk denies anything that isn't pre-approved. Deny rules win over everything else.

5. Two test tasks in parallel, without collisions

claude --bg -w api-tests "Add negative tests for POST /orders"
claude --bg -w ui-tests  "Fix the flaky checkout test"
claude agents          # watch both; Enter to attach, ← to detach

Each background session works in its own git worktree, so the two never edit the same files.

6. Try a different model on the same question

claude -c --fork-session --model fable "Re-examine the root cause of the payment test failure"

Continues the last conversation in a new session with a different model, leaving the original conversation untouched for comparison.

Explore your own CLI25 min · terminal
  1. Run claude --version.a version number such as 2.1.319 (Claude Code). If yours is newer, some flags may have changed; trust your own help output.
  2. Run claude --help | less and find three flags in this chapter's tables. Press q to leave.the same flags with the same descriptions.
  3. Run claude auth status --text, then echo $?.your sign-in method, then 0 (signed in). The second command prints the previous command's exit code.
  4. In a practice folder, run claude -p "In one sentence, what is in this folder?" --allowedTools "Read" "Glob" --output-format json.a JSON object containing the answer, plus details such as cost and duration.
  5. Run the same prompt with --permission-prompts none --tools "".an answer saying it can't look at the folder, because no tools exist. You've just seen how flags shape what Claude can do.
  6. Run claude mcp list and claude plugin list.your configured MCP servers and installed plugins (possibly none).
Common misunderstandings
"If it's not in --help, it doesn't exist."
Anthropic's documentation says plainly that --help doesn't list every flag. --max-turns and --system-prompt-file are documented but not shown.
"Flags and slash commands are the same thing."
Flags go on the command line before a session starts (claude --model opus). Slash commands are typed inside a session (/model opus). Chapter 73 explains all five kinds.
"-p works exactly like an interactive session."
Print mode skips the folder-trust question, starts in default rather than auto mode, silently ignores broken settings files and uses an API key if one is set. Test your CI commands before relying on them.
"--dangerously-skip-permissions is fine on my laptop."
It removes every safety check. Use it only inside a disposable, isolated container or virtual machine.

Key takeaways
  • Usage lines read like sentences: [optional], <required>, a|b for choices, ... for repeats. Quote anything with spaces or special characters.
  • Subcommands do separate jobs (auth, mcp, plugin, update, doctor, background-session tools); flags shape how a session starts.
  • Many flags only work with -p: output formats, --json-schema, --max-budget-usd, --max-turns, --permission-prompts.
  • For CI, combine least-privilege tools, a spending cap, structured output and, for reproducibility, --bare.
  • Environment variables set sign-in, models, MCP limits, proxies and updates. An old ANTHROPIC_API_KEY can silently override your subscription.
  • This reference matches 2.1.319. Your own claude --help is the final word for your version.
Check yourself

In the usage line claude attach <id|name>, what do the angle brackets and the bar mean?

Angle brackets mean "required, replace with a real value"; the bar means "one of these".

Which flag only works together with -p?

Spending caps, output formats and JSON schemas are print-mode features for scripts.

A nightly CI run should behave the same on every build machine regardless of local CLAUDE.md files or plugins. Which flag helps most?

--bare skips local customisations and makes you pass context explicitly. --safe-mode is for troubleshooting.

You want Claude to read files but never even have the Bash tool available. Which flag removes Bash entirely?

--tools decides which tools exist. --allowedTools only decides which run without asking; Bash would still exist and could prompt.

Claude Code suddenly says your organisation is disabled, though your subscription is active. What's the most likely cause?

API keys take priority over subscription sign-in. unset ANTHROPIC_API_KEY and remove it from your shell profile.
