  • The special input symbols: /, @, !, : and ?
  • How to type multi-line prompts in any terminal

Before you start: Chapter 73 explains the difference between shortcuts, symbols, slash commands and flags. This chapter is a reference: search it when you need it rather than reading it start to finish.

Claude Code is driven mostly by plain language, but a small set of keys makes you much faster and safer: Esc to stop, Shift+Tab to change permission mode, Esc Esc to rewind, Ctrl+R to find an old prompt, and @ and ! at the start of what you type. Learn those first; look up the rest here. Press ? on an empty prompt at any time to see the list inside Claude Code itself.

Version and platform

Everything here was checked against Claude Code 2.1.319 and Anthropic's interactive-mode and keybindings documentation on 9 November 2026. Shortcuts can differ by operating system, terminal app and version. On macOS, most Alt shortcuts need your terminal's "Option as Meta" setting turned on (73.9). Your installed version is the final authority: press ?.

Shell mode in detail
  • Commands typed after ! don't need Claude's permission check: you typed them, so you've already decided.
  • If you've turned on sandboxing, commands you type in shell mode normally run outside the sandbox, because the sandbox applies to commands Claude runs.
  • Long commands can be backgrounded with Ctrl+B.
  • Press Tab to autocomplete from your earlier ! commands in this project; type a path containing / to get file suggestions.
  • Claude responds to the output automatically, which uses your allowance like a normal prompt. The respondToBashCommands setting set to false adds the output without a reply.

76.4Permission prompts

When Claude asks to run a command or edit a file, the dialog has its own keys:

KeysEffect
EnterConfirm the highlighted option
EscDecline (the same as "No" without a comment)
↑ / ↓Move between options
TabWith Yes or No focused, add a comment (for example "No, run only the login tests")
Shift+TabOn a file permission prompt: close an open comment field; otherwise choose the option that allows the action for the rest of the session, when offered
Real-world example: a QA habit

Claude proposes npx playwright test for the whole suite, but you only want the checkout tests. Instead of Esc and retyping, press Tab on "No" and write "only run tests/checkout". Claude gets the reason along with the refusal and adjusts.

76.7Changing shortcuts

You can rebind keys. Run /keybindings to create or open ~/.claude/keybindings.json. Changes apply straight away, without restarting.

The file holds a list of binding blocks. Each block names a context (where the keys apply, such as Chat for the main input or Global for everywhere) and maps keys to actions written as namespace:action. Setting a key to null removes its binding.

~/.claude/keybindings.json, the example from Anthropic's documentation
{
  "$schema": "https://www.schemastore.org/claude-code-keybindings.json",
  "$docs": "https://code.claude.com/docs/en/keybindings",
  "bindings": [
    {
      "context": "Chat",
      "bindings": {
        "ctrl+e": "chat:externalEditor",   // Ctrl+E opens your text editor
        "ctrl+s": null                     // Ctrl+S does nothing now
      }
    }
  ]
}

The comments are explanations for this book; JSON files can't contain comments, so leave them out in the real file. One especially useful action is command:<name>, which runs a slash command. For example, "meta+g": "command:compact" in a Chat block makes Meta+G run /compact.

A few action namesDefault key

app:toggleTranscriptCtrl+O

chat:cycleModeShift+Tab

76.8In VS Code and other surfaces

The VS Code extension, the desktop app and Claude Code on the web have their own interfaces, so not every terminal shortcut applies there. In the VS Code extension, Option+K (Mac) or Alt+K inserts an @-mention of the code you've selected, such as @file.ts#5-10. For the other surfaces, see Chapter 70.

Common misunderstandings
"Ctrl+L clears the conversation."
It only redraws the screen. Use /clear to start fresh.
"Ctrl+_ undoes Claude's edit."
It undoes your typing in the input box. To undo Claude's changes, use rewind (Esc Esc or /rewind).
"Ctrl+T shows background tasks."
It shows Claude's to-do checklist. Background shells and subagents are in /tasks.
"Alt shortcuts are broken on my Mac."
Turn on "Option as Meta" in your terminal's settings.
"Starting with # saves a memory."
Not any more; that was removed in version 2.0.70.

76.10Review

Key takeaways
  • Learn ten first: Esc, Esc Esc, Shift+Tab, Ctrl+C, Ctrl+R, Ctrl+O, a newline key, @, ! and ?.
  • \ + Enter and Ctrl+J give a new line in any terminal.
  • Ctrl+L redraws; /clear clears. Rewind undoes Claude's changes; Ctrl+_ undoes your typing.
  • Shortcuts can be changed in ~/.claude/keybindings.json via /keybindings.
  • Platform matters: Option as Meta on macOS, Alt+V on Windows, double Ctrl+B in tmux.
Check yourself

Your screen looks garbled. Which key fixes it without losing anything?

Ctrl+L redraws and keeps everything. /clear starts a new conversation; Ctrl+D exits.

Claude edited three files the wrong way. How do you undo the edits?

Rewind restores code and conversation from an earlier point. Ctrl+_ undoes only your typing; Ctrl+Z suspends the program.

Which works for a new line in every terminal without set-up?

Ctrl+J (and \ + Enter) work everywhere. The others depend on the terminal or settings.

A long test run is blocking you. What sends it to the background?

Ctrl+B backgrounds it. Ctrl+T shows the task checklist; Esc interrupts.

Where do custom keyboard shortcuts live?

Changes there apply immediately, without a restart.
