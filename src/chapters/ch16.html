Before you start: Chapter 6 (the story of attention and the 2017 Transformer), Chapter 11 (neurons, weights and layers), Chapter 14 (tokens and token IDs) and Chapter 15 (embeddings). You need school maths: multiplying, adding, and the idea of "e to the power of". Every calculation is shown.

A Transformer turns your text into tokens, and each token into a list of numbers. It then passes those lists through a stack of identical blocks. In every block, each token first looks at the earlier tokens and gathers what is relevant (attention), then thinks about what it gathered on its own (the feed-forward network). After the last block, the model scores every token in its vocabulary and turns the scores into probabilities for the next token. It picks one, adds it to the text, and repeats. That loop is how Claude, GPT and Gemini write every word.

16.1The whole journey in one picture

The Transformer is the design inside almost every modern large language model. Before looking at any part closely, here is the whole route your prompt takes. Keep this picture in mind; every later section zooms into one box.

The Transformer language model as a loop. Percentages are illustrative.
In everyday life

Think of a bug-triage meeting. Each person (a token) arrives with a sticky note describing themselves. Round after round, everyone glances at the people whose notes are relevant to them and updates their own note with what they learned (attention), then quietly thinks it over (feed-forward). After many rounds, the last person's note is rich enough to answer one question: "what word comes next?"

Two facts about this picture matter for everything else:

  • Every token travels as a list of numbers, a vector. Each block takes in one vector per token and hands back one vector per token, the same size. Only the contents change.
  • The model only ever predicts one token at a time. A 500-word answer is 500-plus trips round the loop.

16.2Step 1: tokens become vectors

From Chapter 14 you know the tokenizer chops text into tokens and gives each a token ID. A number like 4821 says nothing about meaning, so the first thing the model does is swap each ID for a learned vector: its embedding (Chapter 15).

The swap is a simple lookup in a big table with one row per vocabulary entry. If the vocabulary has 50,000 tokens and each vector has 512 numbers, the table holds 50,000 × 512 = 25.6 million parameters, all learned in training.

TokenToken ID (illustrative)Row looked up in the embedding table (first 4 of 512 numbers, illustrative)
"The"464[0.12, −0.48, 0.05, 0.91, …]
" login"17,250[−0.33, 0.27, 0.80, −0.11, …]
" test"1,332[−0.29, 0.31, 0.62, 0.04, …]

The length of these vectors is called the model width (written dmodel). The 2017 Transformer used 512. GPT-3 used 12,288. Wider vectors can carry more information about each token, at more cost.

Same word, same starting vector

At this stage "bug" in "found a bug in checkout" and "bug" in "a bug flew in" get the identical vector, because the lookup knows nothing about context. Making them different is exactly the job of the blocks that follow.

16.3Step 2: telling the model the order

Here is a surprise. The attention step you'll meet next treats its input as a bag of tokens: shuffle them and each token would gather exactly the same information. Yet "the test blocked the release" and "the release blocked the test" mean different things. So the model must be told where each token sits. This is called positional encoding.

In everyday life

Imagine printing a test plan, cutting it into words and dropping them in a box. You'd still know which words were there, but not the order. Writing a page and line number on the back of every slip lets you rebuild it. Positional encoding is that number on the back.

MethodHow it works, in plain wordsWho used it
Fixed sine wavesEach position gets a fixed pattern of wave values, added to the token's vector. Nearby positions get similar patterns.The original 2017 Transformer
Learned positionsA second lookup table with one learned vector per position (position 0, 1, 2 …), added to the token's vector.BERT, GPT-2, GPT-3
Rotary (RoPE)Instead of adding anything at the start, each block rotates the query and key vectors (16.5) by an angle that depends on position, so attention scores depend on how far apart two tokens are.Many recent open-weight models, for example Meta's Llama family
Under the hood: the sine-wave formula

In "Attention Is All You Need", position pos gets a vector whose even-numbered entries are sin(pos / 100002i/d) and odd-numbered entries are cos of the same thing, where i counts pairs of entries and d is the model width. Early entries wiggle fast (they tell position 3 from position 4), later entries change slowly (they tell position 30 from position 3,000). It is like a clock with a seconds hand, a minute hand and an hour hand: together they pin down the exact time.

Rotary position embedding (Su et al., 2021) rotates pairs of numbers in each query and key. When you then compare a query with a key, the rotation angles partly cancel, leaving only the difference in positions. That gives the model a natural sense of "three tokens back", which helps with long texts. Anthropic has not published which method Claude uses.

16.4Step 3: self-attention, the idea

Now the heart of the Transformer. Self-attention lets every token gather information from the other tokens that matter to it, and update its own vector with what it finds.

Take a sentence from a bug report: "The test failed because it timed out". When the model reaches "it", the vector for "it" is just a generic pronoun. To be useful it needs to absorb something of "test". Attention does that: "it" scores how relevant each earlier token is, then takes a weighted blend of their information.

Where "it" looks. Weights are illustrative, not measured from a real model.

Three properties make this powerful:

  1. Distance doesn't matter. A token 5,000 tokens back can be reached in one step, as easily as the one next door. Older designs (RNNs, Chapter 6) had to pass information along a chain and forgot.
  2. All tokens are processed at once. Every token's attention can be computed in parallel, which suits GPUs perfectly. That's why Transformers could be trained on far more text.
  3. Relevance is learned, not programmed. No one writes a rule "pronouns look at nouns". Training adjusts the weights until useful patterns appear.
Real-world example

You paste a 40-step test log into Claude and ask "why did step 37 fail?". The tokens around step 37 can attend directly to the setup in step 2 that created a stale session token. That direct line from any token to any earlier token is why modern models can connect a symptom to a cause far away in a long document.

16.5Queries, keys and values: a worked example

How does a token decide what's relevant? Each token's vector is turned into three new, shorter vectors, by multiplying it by three learned weight tables (matrices called WQ, WK and WV):

VectorPlain meaningLibrary analogy
Query (Q)"What am I looking for?"The question you type into the library catalogue
Key (K)"What do I offer? Here's my label."The label on each book's catalogue card
Value (V)"If you pick me, here's the information I hand over."The contents of the book itself

A token compares its query with every key. Good matches get high scores. The scores become weights, and the token takes that weighted mix of the values. Splitting "label" (key) from "contents" (value) matters: what makes a token findable is not always what it should pass on.

The mini example

Three tokens, "login", "test", "failed", with vectors only 2 numbers long so we can do it by hand. Suppose training has already produced these query, key and value vectors (the numbers are illustrative). We'll work out the new vector for "failed", which can look at itself and the two tokens before it.

TokenKeyValue
login(1, 0)(1, 0)
test(1, 1)(0, 2)
failed(0, 1)(1, 1)

The query of "failed" is (2, 1). Now four steps.

  1. Score each key with a dot product (multiply matching positions and add): login: 2×1 + 1×0 = 2; test: 2×1 + 1×1 = 3; failed: 2×0 + 1×1 = 1.
  2. Scale. Divide by the square root of the vector length (√2 ≈ 1.414): 1.414, 2.121, 0.707. (Why? See 16.6.)
  3. Softmax turns the scores into weights that are positive and add up to 1: raise e (≈ 2.718) to each score, giving 4.11, 8.34 and 2.03, total 14.48; divide each by the total: 0.28, 0.58, 0.14.
  4. Blend the values using those weights: 0.28×(1, 0) + 0.58×(0, 2) + 0.14×(1, 1) = (0.42, 1.29).
One attention step by hand. "failed" draws most of its new information from "test". Numbers are illustrative.

The result: "failed" now carries mostly information from "test". In a real model this happens for every token at once, with vectors of 64 to 128 numbers per head, and the weight tables that produce queries, keys and values are learned during training.

Under the hood: the formula, in matrix form

Stack every token's query into a matrix Q (one row per token), likewise K and V. Then the whole layer's attention is one line, from the 2017 paper:

Scaled dot-product attention
Attention(Q, K, V) = softmax( Q · Kᵀ / √dk ) · V

Q·Kᵀ gives a table of scores: row i, column j is "how much token i wants token j". Softmax runs along each row. Multiplying by V blends the values. Because it is all matrix multiplication, a GPU can compute it for thousands of tokens in parallel.

One cost follows directly: the score table has one cell for every pair of tokens. Double the text and you get four times the cells. That is a big reason long context windows (Chapter 20) took years of engineering to make practical.

The causal mask: no peeking ahead

A model that writes left to right must not cheat during training by looking at the word it's meant to predict. So each token may only attend to itself and earlier tokens. Before softmax, every score for a later token is set to minus infinity, which softmax turns into a weight of exactly 0. This is called a causal mask. 16.6Softmax: from scores to weights

Softmax appears twice in a Transformer: inside every attention step, and at the very end to produce next-token probabilities. It does one job: take any list of numbers, positive or negative, and turn it into positive numbers that add up to 1, keeping the order (the biggest score gets the biggest share).

Scores1.41, 2.12, 0.71
Raise e to each4.11, 8.34, 2.03 (all positive)
Divide by the total÷ 14.48
Weights0.28, 0.58, 0.14 (sum 1)

Because it uses powers of e, softmax exaggerates differences: a score only 0.7 higher gets roughly twice the weight. That is why attention tends to focus on a few tokens rather than spreading evenly.

Under the hood: why divide by √dk?

A dot product adds up one product per number in the vector. With 128 numbers instead of 2, scores naturally become much larger, purely because there are more terms. Large scores push softmax to extremes: almost all the weight on one token and almost none elsewhere. That makes training unstable, because tiny changes in the weights produce almost no change in the output (the gradients, Chapter 12, become very small). Dividing by the square root of the key length dk keeps scores in a sensible range whatever the vector size. In the lab you will remove the scaling and watch the weights snap to 0.00 and 0.50.

16.7Multi-head attention: several kinds of looking at once

One attention step can only blend one kind of relevance. But a token needs several at once: "which noun does 'it' refer to?", "what's the verb of this clause?", "what was the previous line of this log?". So a Transformer runs several attention calculations side by side, each with its own query, key and value weights. Each is called a head, and the whole arrangement is multi-head attention.

Heads in parallel. Sizes are from the 2017 base model; head "jobs" are examples of patterns researchers have found, not assigned roles.

In the original base Transformer, the 512-number vector was split across 8 heads of 64 numbers each, so multi-head attention costs about the same as one big head. GPT-3's largest model used 96 heads of 128 numbers each.

Nobody assigns the jobs

Heads aren't told what to do. Training discovers useful patterns. Interpretability researchers, including Anthropic's (Chapter 38), have found heads that, for instance, copy a pattern seen earlier in the text ("induction heads"). Many heads have no tidy human description.

16.8The feed-forward network: thinking it over

Attention moves information between tokens. The second half of each block works on each token on its own: a small two-layer neural network (Chapter 11), called the feed-forward network, applied separately to every token's vector with the same weights.

Inone token's vector (512 numbers)
Expandmultiply by a weight matrix → 2,048 numbers, then an activation function such as ReLU
Shrinkmultiply by a second matrix → back to 512
Outan update for that token
In everyday life

After the triage meeting's discussion round (attention), everyone goes back to their desk and thinks: "Given what I heard, what do I now know?" They consult their own experience, not each other. That private thinking is the feed-forward step.

Most of a large model's parameters live here: with the usual four-times expansion, each feed-forward network has about twice as many weights as the attention in the same block. Research suggests these layers act partly as a store of learned associations, for example linking "capital of France" to "Paris" (Geva et al., 2021).

16.9Residual connections and layer normalisation

Two plain-looking additions make deep stacks of blocks trainable at all.

Residual connection

Each sub-step's output is added to its input instead of replacing it: new vector = old vector + update. A residual connection means a block only has to learn a change, and information (and the training signal) can flow straight through dozens of blocks without fading. The idea comes from image networks (He et al., 2015).

Layer normalisation

Before each sub-step, layer normalisation rescales each token's vector so its numbers have an average of 0 and a typical size of 1 (then applies learned adjustments). It stops values drifting larger and larger as they pass through many blocks, which keeps training stable.

One block of a decoder-only Transformer (the "pre-norm" layout used by GPT-2 and most later models). Read from the bottom up.
Under the hood: pre-norm, post-norm and the residual stream

The 2017 paper put layer normalisation after each add ("post-norm"). GPT-2 (2019) moved it to the input of each sub-step ("pre-norm"), as drawn above, which trains more reliably in very deep models. Many recent models use a simpler variant called RMSNorm, and replace ReLU with smoother activations such as GELU or SwiGLU.

Because every sub-step only adds to the running vector, interpretability researchers describe the vector as a residual stream: a shared channel running from the bottom of the model to the top, which each attention and feed-forward step reads from and writes into. Anthropic's 2021 "Mathematical Framework for Transformer Circuits" popularised this view, and its 2024 "Scaling Monosemanticity" work found interpretable features in the residual stream of Claude 3 Sonnet (Chapter 38).

16.10Stacking blocks

One block is not enough. A model stacks many identical-shaped blocks (each with its own learned weights), and the output of one is the input of the next. These are the model's layers.

Blocks stacked along the residual stream. The labels under each block are a rough tendency reported by researchers, not a fixed rule.

Roughly, earlier blocks tend to handle local, surface patterns and later ones more abstract meaning and the specific prediction, but the division is fuzzy. Here are published sizes for some well-documented models:

Under the hood: where 175 billion parameters come from

In one block of width d: the query, key, value and output matrices of attention are each d × d, so 4d². The feed-forward network expands to 4d and back: d × 4d + 4d × d = 8d². Total about 12d² per block (ignoring small items such as biases and norms).

For GPT-3: 12 × 12,288² × 96 blocks ≈ 173.9 billion. The token embedding table adds 50,257 × 12,288 ≈ 0.6 billion. Total ≈ 174.6 billion, matching the published 175 billion. Note that two-thirds of each block's parameters are in the feed-forward network.

16.11The output layer: next-token probabilities

After the last block, the vector at the last position holds everything the model has worked out about what should come next. The output layer turns it into a prediction in two moves:

  1. Score every token in the vocabulary. A final layer norm, then one big matrix multiplication produces one raw score per vocabulary token, tens of thousands of them. These raw scores are called logits. (Many models reuse the embedding table for this, which is called weight tying.)
  2. Softmax turns the logits into probabilities that add up to 1.
After "The login test", the next token is… (illustrative logits 3.0, 2.2, 1.6, 1.1, 0.9, −4.0 put through softmax)
failed50.8%

Illustrative numbers: a real vocabulary has tens of thousands of entries, most with tiny probabilities. "banana" is under 0.1%.

Then a token is chosen: the most likely one, or a random draw weighted by these probabilities. How that choice is made (sampling, and the setting called temperature) is covered in Chapter 17. The chosen token is appended and the loop runs again.

Real-world example

This loop is why Claude's answers stream onto your screen word by word, and why output tokens take longer to produce than input tokens are to read. Your whole prompt can be processed in parallel in one pass. The answer must be produced one token after another, because each token depends on the one before. It also explains run-to-run variation (Chapter 125): if a token is drawn at random from the probabilities, two runs can take different paths from the very first word.

Under the hood: the KV cache

Generating token 1,001 would naively mean recomputing attention for tokens 1 to 1,000 again. But with a causal mask, earlier tokens never change when later ones are added, so their keys and values can be kept in memory and reused. This store is the KV cache. Each new token only computes its own query, key and value and attends to the cache. The cache grows with the length of the text, which is one reason very long contexts need lots of fast GPU memory (Chapter 25). The API's prompt caching feature (Chapter 90) is a related idea: reusing work on a prompt prefix that repeats across requests.

16.12Encoder, decoder and decoder-only

The 2017 Transformer was built for translation and had two halves. Later models kept one half or the other.

Decoder-only won for general-purpose models because one simple objective, "predict the next token", works on any text, and translation, summarisation or Q&A can all be phrased as continuing a text. Anthropic has not published Claude's detailed architecture. It describes Claude as a large language model, and its interpretability papers study Claude's layers and residual stream, consistent with the decoder-style Transformer described here. Treat finer details (exact sizes, positional method, any mixture-of-experts design) as unknown.

Opinion · researchers' debate

Some researchers argue the Transformer will eventually be replaced by designs whose cost grows more slowly with text length, such as state-space models. Others argue that improvements will keep coming inside the Transformer family (better attention variants, mixture-of-experts layers). As of late 2026 the leading published frontier models are still described as Transformer-based. This is a live debate, not a settled fact.

    # attention.py - one attention head, by hand, in plain Python (no libraries)
import math

tokens = ["the", "login", "test", "failed"]

# Toy 4-number embeddings (illustrative; a real model learns these)
X = [
    [1.0, 0.0, 0.0, 0.5],   # the
    [0.0, 1.0, 1.0, 0.0],   # login
    [0.0, 1.0, 0.0, 1.0],   # test
    [1.0, 0.0, 1.0, 1.0],   # failed
]

# Toy projection matrices (4 numbers in, 2 numbers out)
W_Q = [[1, 0], [0, 1], [1, 0], [0, 1]]
W_K = [[0, 1], [1, 0], [0, 1], [1, 0]]
W_V = [[1, 0], [0, 1], [0, 1], [1, 0]]

def matmul(A, B):
    return [[sum(a * b for a, b in zip(row, col)) for col in zip(*B)] for row in A]

def softmax(xs):
    m = max(xs)
    exps = [math.exp(x - m) for x in xs]
    total = sum(exps)
    return [e / total for e in exps]

Q, K, V = matmul(X, W_Q), matmul(X, W_K), matmul(X, W_V)
d_k = len(K[0])

print("Attention weights (row = token looking, column = token looked at)")
print(" " * 8 + "".join(f"{t:>8}" for t in tokens))
outputs = []
for i, q in enumerate(Q):
    scores = []
    for j, k in enumerate(K):
        if j > i:                       # causal mask: no peeking at later tokens
            scores.append(float("-inf"))
        else:
            scores.append(sum(a * b for a, b in zip(q, k)) / math.sqrt(d_k))
    weights = softmax(scores)
    out = [sum(w * v[c] for w, v in zip(weights, V)) for c in range(len(V[0]))]
    outputs.append(out)
    print(f"{tokens[i]:>8}" + "".join(f"{w:8.2f}" for w in weights))

print()
for t, o in zip(tokens, outputs):
    print(f"new vector for {t!r:9} = [{o[0]:.2f}, {o[1]:.2f}]")

Common misunderstandings
"Attention means the model is paying attention like a person does."
It is a weighted average with learned weights. The name is a metaphor. It has no awareness and no single focus.
"Attention weights explain why the model gave its answer."
They show where information was blended in one head of one layer. With dozens of layers and heads, plus feed-forward networks, a single attention map is a weak explanation. Interpretability research (Chapter 38) uses much richer tools.
"The model reads the whole prompt and writes the whole answer at once."
It reads the prompt in parallel, but it writes one token at a time, feeding each token back in.
"Each layer is a different kind of thing."
In a standard Transformer every block has the same shape (attention, then feed-forward, with residuals and norms). Only the learned numbers differ.
"Bigger context is free."
Standard attention compares every pair of tokens, and the KV cache grows with length. Long contexts cost real compute and memory, and quality can still drop in very long inputs (Chapter 20).

16.13Review

Key takeaways
  • Text → tokens → embedding vectors (+ position) → N identical-shaped blocks → output layer → probabilities → choose a token → repeat.
  • Attention alone ignores word order, so position information is added (sine waves, learned positions or rotary embeddings).
  • Self-attention: each token's query is compared with every visible key; scores are scaled by √dk, softmaxed into weights, and used to blend the values.
  • The causal mask stops a token seeing later tokens; that's what lets a decoder be trained to predict the next token.
  • Multi-head attention runs several attention patterns in parallel; the feed-forward network then processes each token alone and holds most of the parameters.
  • Residual connections (add, don't replace) and layer normalisation make deep stacks trainable.
  • Encoder-only (BERT) understands, encoder–decoder (original, T5) maps text to text, decoder-only (GPT and most chat models) generates. Claude's exact architecture is not published.
Check yourself

Why does a Transformer need positional encoding?

Without position information, "the test blocked the release" and "the release blocked the test" would look the same to attention. Stopping future-peeking is the causal mask's job.

A token's query is (1, 2). Two visible keys are A = (2, 0) and B = (0, 2). Before scaling, which key scores higher?

Dot products: A = 1×2 + 2×0 = 2; B = 1×0 + 2×2 = 4. So B gets more weight after softmax.

What does softmax guarantee about its outputs?

Softmax keeps the order of the scores but turns them into a probability-like distribution. Very large score gaps make it close to one-hot, but never exactly.

In a standard Transformer block, which part works on each token separately, without looking at other tokens?

Attention moves information between tokens; the feed-forward network then processes each token's vector on its own, using the same weights for every position.

Which layout do GPT-style chat models use?

Decoder-only models generate left to right. BERT is encoder-only; the original 2017 model and T5 are encoder–decoder.

Teach it

"A Transformer turns each word piece into a list of numbers and adds a note of its position. Then it runs a stack of identical blocks. In each block, every token asks a question, the query, and compares it with every earlier token's label, the key. The best matches get the most weight, and the token takes a weighted blend of their information, the values. That's attention. Then each token thinks over what it gathered with a small neural network. Results are added on top of what was there, so nothing is lost. After the last block the model scores every token in its vocabulary, picks one, appends it, and starts again. That's how Claude writes, one token at a time."
