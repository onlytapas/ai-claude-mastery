On its own, Claude Code can read files, edit them and run commands on your computer. MCP servers give it extra tools: a real browser, your Jira tickets, GitHub pull requests, a database. You add a server once with claude mcp add, choose who it's for (just you, your team or all your projects), sign in if needed, and from then on Claude can use that server's tools in any session, always within your permission rules.

83.1What a server gives you

An MCP server is a small program, either on your machine or on the internet, that offers Claude a set of named tools. Once it's connected:

  • Tools appear to Claude alongside its built-in tools. A Playwright server adds tools such as "navigate to a page" and "click"; a GitHub server adds tools to read pull requests and create issues. Claude decides when to use them.
  • Resources (if the server offers them) can be pulled into the conversation with @, like files.
  • Prompts (if the server offers them) become slash commands.
In everyday life

Claude Code is like a skilled new hire on their first day: they can read, write and use the computer in front of them. Adding an MCP server is like handing them a badge for another system. One badge opens Jira, another opens GitHub, another lets them drive a test browser. You decide which badges they get, and the security desk (your permission rules) still checks what they do with them.

83.2Local and remote servers

Servers talk to Claude Code in one of two main ways, called transports:

stdio (local)HTTP (remote)
Where it runsA program Claude Code starts on your computerA service on the internet or your company network
Typical examplesPlaywright (drives a browser on your machine), file or database toolsGitHub, Atlassian (Jira and Confluence), Sentry, Notion
How you sign inUsually environment variables such as an API key (-e)OAuth in the browser, or a token in a header (--header)
Transport flag--transport stdio (the default)--transport http

A third transport, SSE, still exists for older servers but is deprecated; recent versions of Claude Code automatically fall back to SSE when an HTTP connection needs it. WebSocket servers can only be added from JSON (80.6).

83.3The claude mcp add command

You run this in a normal terminal (not inside a Claude session). Its shape, from the installed help (version 2.1.319):

Syntax
claude mcp add [options] <name> <commandOrUrl> [args...]
OptionMeaning
-t, --transportstdio, sse or http. Defaults to stdio.
-s, --scopelocal, project or user. Defaults to local (80.4).
-e, --env KEY=valueEnvironment variable passed to a local (stdio) server, often an API key
-H, --header "Name: value"HTTP header sent to a remote server, often Authorization: Bearer …
--client-id, --client-secret, --callback-portFor remote servers whose OAuth sign-in needs a pre-registered app. --client-secret prompts you for the secret (or reads MCP_CLIENT_SECRET), so it isn't typed onto the command line.

A local server

For stdio servers, put the options before the name, then --, then the command that starts the server. The -- tells Claude Code "everything after this belongs to the server's own command".

# Playwright's official browser server, started with npx (needs Node.js)
claude mcp add playwright -- npx @playwright/mcp@latest

# a local server that needs an API key in its environment
claude mcp add my-server -e API_KEY=xxx -- npx my-mcp-server

A remote server

# remote server that signs in with OAuth later (no secret on the command line)
claude mcp add --transport http sentry https://mcp.sentry.dev/mcp

# remote server that takes a token in a header
claude mcp add --transport http github https://api.githubcopilot.com/mcp/ \
  --header "Authorization: Bearer YOUR_GITHUB_PAT"
It doesn't check your credentials

According to Anthropic's docs, claude mcp add saves the configuration without testing the credentials, so even a placeholder is accepted. You only find out it's wrong when the server fails to connect. Always check with /mcp or claude mcp list afterwards (80.7).

83.4Scopes: who the server is for

Every server is added at a scope, which decides who can use it and where it's saved.

ScopeAvailable inStored inUse it for
local (default)This project, only you~/.claude.json, under this project's pathTrying a server out, or servers with your personal credentials
projectThis project, everyone who clones it.mcp.json at the project root (commit it)Servers the whole team should share, such as Playwright for the test repo
userAll your projects, only you~/.claude.jsonPersonal tools you want everywhere

If the same name is defined in several places, Claude Code uses this order: local, then project, then user, then servers from plugins, then claude.ai connectors. If the same name points to different endpoints in different scopes, claude mcp list and /mcp show a warning; remove the one you don't want with claude mcp remove <name> --scope <scope>.

83.5The team file: .mcp.json

Project-scoped servers live in .mcp.json at the root of the repository. You can create it with claude mcp add --scope project … or write it by hand.

.mcp.json for a test repository
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest"]
    },
    "github": {
      "type": "http",
      "url": "https://api.githubcopilot.com/mcp/",
      "headers": { "Authorization": "Bearer ${GITHUB_PAT}" }
    }
  }
}

Notice ${GITHUB_PAT}. Never commit a real token. Claude Code expands environment variables written as ${VAR}, or ${VAR:-default} to give a fallback, inside command, args, env, url and headers. Each teammate sets GITHUB_PAT on their own machine (Chapter 98 shows safe ways to do that), and the file stays secret-free.

Rules of the file format
  • An entry with no type is treated as stdio, so it needs a command.
  • An entry with a url but no type is an error. Write "type": "http" ("streamable-http" is accepted as another name for it).
  • If a ${VAR} isn't set and has no default, the server still loads with the text unexpanded, and claude mcp list and /mcp warn you about the missing variable.
  • Claude Code warns about hidden leading or trailing spaces in values, a common result of pasting a token with a trailing newline. It doesn't trim them, so fix the file.
  • Some names are reserved for built-in servers (for example workspace, claude-in-chrome and computer-use) and are rejected or skipped.
  • A "timeout" field in milliseconds sets a per-server limit for each tool call (80.9).

Approving project servers

Because anyone can commit an .mcp.json, Claude Code doesn't run project servers automatically. The first time you start an interactive session in that project, it asks you to approve them. Until then, claude mcp list shows them as ⏸ Pending approval. Approvals are tied to trusting the workspace: a freshly cloned repository can't approve its own servers by committing settings. If you change your mind, claude mcp reset-project-choices clears your approvals and rejections for that project.

Real-world example: a QA view

This approval step is a security control you'd test for. A malicious pull request that adds an .mcp.json entry pointing at an untrusted server shouldn't be able to run it on a reviewer's laptop without that person agreeing. Chapter 105 covers MCP security in depth.

83.7Inside a session: /mcp

Inside Claude Code, type /mcp to see every server, whether it's connected (✓) or failing (✘), and the tools it offers. From the same command you can:

  • Sign in to a remote server that uses OAuth: choose it and follow the browser flow. Tokens are stored securely and refreshed automatically.
  • Reconnect a server: /mcp reconnect <server> or /mcp reconnect all.
  • Turn servers off and on for the session: /mcp disable <server>, /mcp enable <server> (or all).

If a remote server's row shows ✘, the details usually include the HTTP status it returned. A 401 almost always means a missing, expired or wrong token.

Sign-in only works interactively

OAuth needs a person and a browser, so it can't happen in a non-interactive claude -p run. Sign in once interactively (or with claude mcp login), and later runs reuse the stored credentials.

83.8Permissions for MCP tools

MCP tools go through the same permission system as built-in tools (Chapter 78). Each tool has a name in the form mcp__<server>__<tool>.

RuleMatches
mcp__playwright or mcp__playwright__*Every tool of the server named playwright
mcp__github__create_issueJust that one tool (the exact tool names come from the server; /mcp lists them)
mcp__claude_ai_<server>__<tool>Tools of a claude.ai connector
mcp__plugin_<plugin>_<server>__*Tools of a server that came with a plugin
.claude/settings.json: let Playwright run freely, but always ask before anything else
{
  "permissions": {
    "allow": ["mcp__playwright__*"],
    "ask":   ["mcp__github__*"]
  }
}

Remember the rules from Chapter 78: deny beats ask, ask beats allow, and server names containing dots or spaces turn into underscores in rule names.

83.9Timeouts and output limits

LimitDefaultHow to change it
Server start-up time30 secondsEnvironment variable MCP_TIMEOUT, in milliseconds, e.g. MCP_TIMEOUT=10000 claude
Time per tool callVery long unless set"timeout" (milliseconds) on the server's .mcp.json entry, or the MCP_TOOL_TIMEOUT variable for all servers
Warning on large tool outputAbove 10,000 tokensFixed
Maximum tool output25,000 tokensMAX_MCP_OUTPUT_TOKENS, e.g. export MAX_MCP_OUTPUT_TOKENS=50000
Long text resultsOver 50,000 characters are saved to a file instead of pasted into contextSet by the server for its own tools

The output limits protect your context window (Chapter 20): a single Jira search or browser snapshot can otherwise flood it. If a tool keeps hitting the limit, ask for less ("only the first 20 issues", "just the error text") before raising the limit.

83.10Worked example: a test repository's MCP setup

Here's a typical QA setup, done in a terminal inside the test repository.

1. Playwright for the whole team (local, project scope)
claude mcp add --scope project playwright -- npx @playwright/mcp@latest
2. GitHub with your own token (remote, local scope so the token stays yours)
# create a fine-grained personal access token in GitHub first (Chapter 98)
claude mcp add --transport http github https://api.githubcopilot.com/mcp/ \
  --header "Authorization: Bearer $GITHUB_PAT"
3. Atlassian (Jira and Confluence) with OAuth sign-in
# endpoint as listed in Atlassian's getting-started guide on 9 Nov 2026; check it there first
claude mcp add --transport http atlassian https://mcp.atlassian.com/v2/mcp
# then, inside claude:  /mcp  → choose atlassian → sign in in the browser
4. Check everything
claude mcp list
# inside a session:
/mcp

Now you can ask things like: "Read PROJ-412 in Jira, open the checkout page in the browser, try the three acceptance criteria and tell me which ones fail. Then draft a GitHub issue for any failure, but ask me before creating it." Chapters 101–103 cover each of these connections in detail, and Chapter 106 builds a complete workflow.

Your company may manage this for you

Organisations can supply MCP servers through managed settings, and administrators can restrict which servers are allowed. If a server you expect is missing, or one you add is blocked, ask whoever manages your Claude setup before working around it.

Common misunderstandings
"I'll put the token straight into .mcp.json; it's only our team repo."
Anything committed spreads to every clone and every fork and stays in git history. Use ${VAR} and keep the secret in each person's environment.
"The add command worked, so the server works."
It only saves configuration. Check with claude mcp list or /mcp.
"Forgetting the --."
For stdio servers, everything after -- is the server's own command. Without it, the server's flags can be mistaken for Claude Code's.
"Project servers should just start when I clone the repo."
They need your approval first, on purpose, so an untrusted repository can't run code on your machine.
"An MCP server is safe because Claude Code asks permission."
Permission prompts help, but the server itself is software running with your access. Only install servers you trust (Chapter 105).

83.11Review

Key takeaways
  • claude mcp add [options] <name> <commandOrUrl> [args...] adds a server; stdio servers take -- command, remote ones --transport http URL.
  • Scopes: local (default, you, this project), project (.mcp.json, shared), user (you, everywhere).
  • Keep secrets out of .mcp.json with ${VAR} expansion; project servers need approval before they run.
  • Check and sign in with claude mcp list, /mcp and claude mcp login; a 401 usually means a bad token.
  • MCP tools are named mcp__server__tool and obey normal allow, ask and deny rules.
  • Defaults: 30 s start-up, a warning above 10,000 tokens of output, a cap at 25,000 (MAX_MCP_OUTPUT_TOKENS).
Check yourself

You want every tester who clones the repo to get the Playwright server. Which scope?

Project scope writes it to .mcp.json at the repo root, which you commit.

What's the safest way to give a remote server your GitHub token in a shared .mcp.json?

Claude Code expands ${VAR} in headers, so the committed file never contains the secret.

In /mcp the GitHub server shows ✘ with status 401. Most likely cause?

401 means "unauthorised": the server didn't accept the credentials.

Which permission rule allows every tool of the server named playwright?

MCP tools are named mcp__<server>__<tool>.

An MCP tool's answers keep getting cut off. What should you try first?

The default cap of 25,000 tokens protects your context window. Smaller requests are usually better than a bigger cap.

Assignment

Design the MCP setup for your real test repository. Write down which servers it needs, which scope each should use and why, which credentials each needs and where they will live (never in git), and which tools should be allow, ask or deny. Then create the .mcp.json and permission rules, ask a colleague to clone the repo and confirm that the approval prompt appears and the servers connect with their own credentials.

Teach it
