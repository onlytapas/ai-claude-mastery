Three settings shape every Claude Code session: how much it can see (the context window), which brain it uses (the model), and how hard it thinks (the effort level). A fourth, the session, is the saved conversation you can come back to. Managing these well is the difference between a session that stays sharp for hours and one that gets slow, confused and expensive.

68.1What fills the context window

Everything Claude can "see" during a session sits in its context window, measured in tokens. The current Claude models have a 1-million-token window. That's large, but it fills faster than you'd think, because it holds far more than your messages:

What's in the contextExample
Claude Code's own instructionsHow to use its tools, safety rules
Your memory filesCLAUDE.md files (Chapter 77)
Tool and server descriptionsDescriptions of MCP tools, skills and subagents
The conversationYour prompts and Claude's replies
Tool resultsEvery file Claude read, every command output, every web page

Tool results are usually the biggest item. One large log file or a long test run can use more tokens than an hour of conversation.

In everyday life

The context window is like a desk. Your notes, the specification, three open reports and yesterday's test logs are all spread out on it. A bigger desk helps, but when it's covered in papers, finding the right one gets slower and mistakes creep in. Tidying the desk (compacting) or starting with a clean one (clearing) keeps the work sharp.

68.2Seeing it: /context

Type /context to see how full the window is, shown as a coloured grid with a breakdown by category and suggestions for freeing space. /context all shows more detail.

Real-world example

Two hours into investigating a flaky checkout test, Claude starts repeating ideas it already tried. You run /context and see most of the window is old test logs. That's your signal to compact with a focus, or to clear and restart with a short summary of what you've learned.

68.3Compaction: tidying the desk

Compaction replaces the conversation so far with a summary, freeing space while keeping the important points.

  • Automatic: Claude Code compacts on its own as the window fills up.
  • Manual: /compact compacts now. Add instructions to say what matters: /compact keep the failing test names, error messages and the fix we agreed.
  • Setting the threshold: /autocompact 500k (or /autocompact auto) sets how full the context gets before automatic compaction, and saves it to your user settings. For one session only, start with claude --autocompact 500k; the flag accepts auto or a value from 100k to 1M tokens.
  • From a checkpoint: the /rewind menu also offers "Summarize from here" and "Summarize up to here", to condense just part of the conversation (Chapter 67).
Summaries lose detail

A summary is shorter than the original by design. Exact error text, line numbers or a small decision can get lost. Tell /compact what to keep, and put permanent facts in CLAUDE.md, where they're reloaded every session.

When compaction "thrashes"

If you see "Autocompact is thrashing", Claude Code is compacting again and again because each new step immediately refills the window, usually because it keeps reading something huge. The documented fixes: read large files in chunks, run a focused /compact, hand the heavy reading to a subagent (its reading doesn't fill your main context; only its summary comes back), or /clear and start fresh.

68.4Clearing: a fresh desk

/clear starts a new conversation with empty context. The old conversation isn't deleted: it stays resumable, and you can label it with a name (/clear coupon-investigation). Aliases are /reset and /new.

Compact when…

  • You're still on the same task
  • The history matters, but not every detail
  • You want to keep going without losing the thread

Clear when…

  • You're switching to an unrelated task
  • Claude is stuck in a loop of failed ideas
  • The old context is misleading it

Two more helpers keep the main conversation clean:

  • /btw [question] asks a quick side question about the session without adding it to the conversation history.
  • /branch [name] copies the conversation at this point and switches you into the copy, so you can try a different direction while the original stays resumable.

Context hygiene habits

  1. One task per session; /clear between unrelated tasks.
  2. Point at specific files with @ instead of asking Claude to search everything.
  3. Ask Claude to search large logs (for example with grep) instead of pasting them.
  4. Send side research to a subagent.
  5. Only connect the MCP servers you need, since their tool descriptions take space.
  6. Keep permanent knowledge in CLAUDE.md, short and specific.

68.6Switching models

The model is chosen from these sources, highest priority first:

  1. /model <alias or name> during the session.
  2. claude --model <alias or name> at start.
  3. The ANTHROPIC_MODEL environment variable.
  4. The "model" key in settings.
  5. ANTHROPIC_DEFAULT_MODEL, the default for new sessions.
In a session and in the terminal
/model                     # opens a picker
/model sonnet              # switch to the latest Sonnet
claude --model haiku       # start a session on Haiku
claude --fallback-model sonnet,haiku   # use these if the main model is overloaded
  • /model saves your choice as the default for new sessions (it writes model to your user settings). In the picker, Enter saves it as the default, s applies it to this session only, and the left and right arrows adjust effort.
  • Option+P (Mac) or Alt+P switches model while you're writing a prompt.
  • Resumed sessions keep the model they were saved with. /status shows the current model.
  • --fallback-model takes a comma-separated chain (up to 3 models), tried in order when the main model is overloaded or unavailable. The switch lasts only for the current turn.

Which model for QA work?

TaskA sensible choice
Everyday test writing, reviews, investigationsThe default (Opus 5.5), as Anthropic recommends for most work
Quick, repetitive jobs: classifying test failures, renaming, simple summariesSonnet or Haiku: faster and cheaper
A hard root-cause investigation that Opus keeps getting wrongRaise the effort first; if it still falls short, try Fable
Big design or refactoring work where planning matters mostopusplan or plan mode with Opus

68.7Effort levels: how hard it thinks

The effort level controls how much reasoning the model does before acting. Higher effort is slower and uses more of your allowance, but helps with hard problems.

LevelUse it for
lowSimple, mechanical edits
mediumEveryday work. The Claude Code default on Opus 5.5, Sonnet 5.5 and Haiku 5.5
highTrickier debugging and design
xhighVery hard problems
maxThe hardest problems; applies to the current session only
Ways to set effort
/effort                 # slider
/effort high            # set a level
/effort status          # show the current level
/effort auto            # clear your saved level
claude --effort xhigh   # for this session
  • The left and right arrows in the /model picker also adjust effort.
  • The CLAUDE_CODE_EFFORT_LEVEL environment variable has the highest priority.
  • If a model doesn't support a level, Claude Code falls back to the highest level it does support below it.
  • Writing ultrathink in a prompt asks for deeper reasoning for that one turn. Other phrases such as "think hard" are treated as ordinary text.
  • On the current models, extended thinking can't be switched off; effort is how you control the amount. Ctrl+O shows collapsed thinking.
Defaults differ by product

Default effort depends on where you use the model. In Claude Code, Opus 5.5, Sonnet 5.5 and Haiku 5.5 default to medium; Anthropic's API documentation lists its own defaults per model (for example high for Fable 5.1). Check with /effort status rather than assuming.

68.8Sessions: saving, finding and resuming

Every conversation is saved automatically as a session, so you can stop and pick up later.

CommandWhat it does
claude -c (--continue)Reopens the most recent session in this folder
claude -r (--resume)Opens the session picker
claude -r <name or id>Resumes a specific session
claude -n <name>Starts a session with a display name
/rename <name>Renames the current session
/resume [session]Switches session from inside Claude Code
claude -c --fork-sessionResumes into a new session ID, leaving the original untouched
/branch [name]Branches the conversation at this point
claude --from-pr <number or URL>Opens sessions linked to a pull request
claude --session-id <uuid>Uses a specific session ID (must be a valid UUID); useful in scripts

In the picker: arrow keys (or j/k) to move, Enter to resume, Space to preview, / to search, Ctrl+R to rename, Ctrl+A for all projects.

Where sessions live, and how to delete them

Transcripts are stored on your computer at ~/.claude/projects/<project>/<session-id>.jsonl and kept for 30 days by default (the cleanupPeriodDays setting). To delete a project's local Claude Code data (transcripts, tasks, file history and its entry in ~/.claude.json):

Terminal
claude purge --dry-run      # show what would be deleted for this folder
claude purge                # delete it (asks for confirmation)

In print mode, --no-session-persistence stops a run from being saved at all.

Transcripts can contain sensitive data

A transcript holds everything Claude read and every command output. If a session touched secrets or customer data, treat its transcript accordingly, and consider purging it.

Manage a long session40 min · any practice repository
  1. Start with a name: claude -n context-lab. Run /status.your model, account and version.
  2. Run /context.a coloured grid showing how full the window is, mostly system instructions and memory at this point.
  3. Ask Claude to read three or four large files and summarise them, then run /context again.a noticeably fuller window, mostly from tool results.
  4. Run /compact keep only the file names and one-line summaries, then /context.much less space used.
  5. Run /model, press s on Sonnet to switch for this session only, and use the arrows to change effort. Check with /effort status.the new model and effort level.
  6. Run /clear practice-done, then /exit. Start again with claude -r.the picker lists "context-lab" and the cleared conversation, both resumable.
  7. Run /usage.your session cost or plan usage.
Common misunderstandings
"A 1-million-token window means I never need to clear."
Quality drops as the window fills with old, irrelevant material. Clear between tasks regardless of size.
"/clear deletes my conversation."
It starts a fresh context; the old conversation stays resumable.
"/model only changes this session."
/model saves your choice as the default for new sessions. Press s in the picker for this session only.
"Typing 'think hard' makes Claude think harder."
Only ultrathink is recognised. Use /effort for lasting changes.
"The biggest model is always best."
Anthropic recommends starting with Opus 5.5; use Fable only when Opus at higher effort still falls short, and smaller models for simple, high-volume jobs.

68.10Review

Key takeaways
  • The context holds instructions, memory, tool descriptions, the conversation and every tool result; /context shows it.
  • Compact (automatically, or with /compact <what to keep>) on the same task; /clear for a new one.
  • Aliases: default, fable, best, opus, sonnet, haiku, opusplan. Opus 5.5 is the recommended starting point.
  • Effort levels run from low to max; set them with /effort, --effort or the /model picker.
  • Sessions are saved locally for 30 days by default; resume with -c or -r, name with -n, delete with claude purge.
  • /usage (also /cost) shows cost and limits.
Check yourself

You're halfway through debugging one flaky test and the context is getting full. What's the best move?

Same task, so keep the thread with a focused summary. Clear is for switching tasks.

What does /model sonnet do?

Which effort level applies to the current session only and can't be saved in settings files?

max lasts for the session unless set through the environment variable.

Where are Claude Code session transcripts stored by default?

Use claude purge to delete a project's local data.

Which statement about choosing models matches Anthropic's guidance?

Pick by task: smaller models for simple, high-volume jobs; Fable for the hardest work.
