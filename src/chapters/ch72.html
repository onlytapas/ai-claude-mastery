When Claude Code misbehaves, the cause is almost always one of a few things: it isn't installed where your terminal looks, it's signed in with the wrong credentials, its context is overloaded, a setting or customisation is interfering, or the network is in the way. Testers already know how to troubleshoot: reproduce, isolate, check one variable at a time. Claude Code gives you tools for each of those steps. This chapter turns your QA instincts into a fast fix routine.

72.1The method: symptom, check, fix

1 · Describe the symptomExact error text, when it happens, what you expected
2 · Gather facts/status, claude doctor, the version
3 · IsolateDoes it happen in --safe-mode? In another folder? With /clear?
4 · Look closerDebug logs for the area: mcp, hooks, startup…
5 · Fix and verifyChange one thing, retry the exact same steps
In everyday life

A car won't start. A good mechanic doesn't replace the engine first. They check: is there fuel? Is the battery charged? Does it start with the extra gadgets unplugged? Claude Code troubleshooting is the same: start with the cheap, obvious checks, and change one thing at a time so you know what actually fixed it.

Ask Claude first

If Claude Code is running at all, the fastest first step is often to ask it: "I'm getting this error: [paste]. What does it mean and how do I check?" Claude can read its own documentation. Treat its answer as a hypothesis to test, not a verdict.

Safe mode vs bare mode: which to use?

Safe mode is the troubleshooting switch. It keeps your normal sign-in, model and permissions, but turns off everything you or your team added. If a problem disappears in safe mode, a customisation is the cause; turn things back on one at a time to find which.

Bare mode is a minimal, predictable mode designed for scripts and automation. It doesn't read your subscription login at all: authentication must come from ANTHROPIC_API_KEY or an apiKeyHelper passed through --settings. If you use it to troubleshoot and suddenly get an authentication error, that's why.

72.4Sign-in and the wrong-account trap

Claude Code can sign in several ways, and it picks between them in a fixed order. Environment variables come before your subscription login. The documented order is: cloud-provider variables, then ANTHROPIC_AUTH_TOKEN, then ANTHROPIC_API_KEY, then apiKeyHelper, then CLAUDE_CODE_OAUTH_TOKEN, then other credentials, and finally your /login subscription.

Real-world example: "my organisation has been disabled"

A tester with an active company subscription suddenly saw This organization has been disabled. The cause: months earlier they had exported an old personal ANTHROPIC_API_KEY in their shell profile for an experiment. That key was overriding the company login. The fix was unset ANTHROPIC_API_KEY and removing the line from ~/.zshrc. /status shows which credential is active; check it first.

72.9Reporting a bug in Claude Code itself

Sometimes it really is a bug. Claude Code has two built-in commands that open the same reporting dialog: /feedback and /bug (alias /share), which can include the conversation after a consent screen. Your QA skills make you exactly the kind of reporter product teams love.

A good Claude Code bug report
Title: /mcp shows "connected" but Playwright tools are missing after resume

Version: 2.1.319 (claude --version)   OS: macOS 15, zsh   Install: native
Account: Team subscription (/status)  Model: Opus 5.5

Steps to reproduce:
1. claude mcp add playwright -- npx @playwright/mcp@latest
2. Start claude, run /mcp → playwright connected, tools listed
3. Exit, then claude --continue
4. Run /mcp

Expected: Playwright tools listed after resume
Actual:   Server shows connected, tool list empty
Frequency: 4 out of 4 attempts
Isolation: also happens with --safe-mode plus only this server; not in a new session
Logs: claude --debug=mcp output attached (secrets removed)
Before you send

Debug logs and conversations can contain file contents, paths, tokens and company data. Read what you're sharing, remove secrets, and follow your company's policy on what may leave the organisation.

Troubleshooting drill40 min · any project
  1. Run claude --version and claude doctor in a normal terminal.a version number and a health summary with any warnings.
  2. Start claude and run /status. Note the active credential and model.your account and how you're signed in.
  3. Break a setting on purpose: in a practice project, add a trailing comma to .claude/settings.json. Run claude -p "say hi", then start an interactive session.the print-mode run proceeds without complaint (invalid settings are silently ignored there), while the interactive session reports the problem. Undo the change afterwards.
  4. Run /doctor inside a session.a checkup listing anything worth fixing, with offers to fix after you confirm.
  5. Start once with claude --safe-mode and run /memory and /mcp.customisations such as CLAUDE.md and MCP servers turned off.
  6. Start with claude --debug-file ./claude-debug.log, run one command, exit and skim the log.a log file with timestamped entries. Delete it afterwards if it contains anything sensitive.
  7. Write a bug report for any small oddity you found, using the template in 69.9 (you don't need to send it).
Common misunderstandings
"Reinstalling fixes everything."
Most problems are credentials, settings, context or network. Reinstalling changes none of those. Diagnose first.
"claude doctor and /doctor are the same."
claude doctor is a read-only check from the shell; /doctor is a fuller in-session checkup that can apply fixes after you confirm.
"Ctrl+L clears the conversation."
It only redraws the screen. Use /clear to start fresh.
"My subscription is used whenever I'm logged in."
An ANTHROPIC_API_KEY environment variable takes priority, and is always used with -p.

72.10Review

Key takeaways
  • Troubleshoot like a tester: describe the symptom, gather facts, isolate, look at logs, change one thing.
  • Start with /status, claude doctor and /doctor; isolate customisations with --safe-mode; dig in with --debug=area or --debug-file.
  • Most sign-in mysteries are a stale ANTHROPIC_API_KEY overriding the subscription.
  • Poor answers usually mean a crowded context: /context, then /compact or /clear.
  • Settings follow a strict precedence and must be valid JSON; invalid files are silently ignored in -p mode.
  • Interactive sessions now default to auto mode; switch modes if you want to be asked.
  • Report real bugs with /feedback or /bug, with version, steps, expected vs actual and clean logs.
Check yourself

claude won't start at all. Which tool can you still use?

Slash commands need a running session; claude doctor runs from the shell without one.

A problem disappears when you start with --safe-mode. What does that tell you?

Safe mode turns off customisations while keeping sign-in and model, so it isolates them.

You have an active company subscription but get billing or "organization disabled" errors. First thing to check?

Environment-variable credentials take priority over the subscription login.

Your new setting works interactively but not in a nightly claude -p script. A likely cause?

Print mode skips the error dialog for settings that fail validation.

Which command shows MCP-related debug output only?

The category filter applies only in the = form.

Assignment

Create a one-page "Claude Code first aid" sheet for your team: the five-step method, the ten problems your team is most likely to hit (from this chapter), and your company specifics (proxy settings, who to contact for access, approved MCP servers). Pin it in your team's wiki and ask two colleagues to use it the next time something goes wrong.

Teach it

"When Claude Code misbehaves, troubleshoot like a tester. Check /status and claude doctor, then see if the problem goes away in --safe-mode. If it does, something you added is the cause. Most sign-in mysteries are an old API key in your environment. Most bad answers are a full context, so /compact or /clear. And if it's a real bug, report it with /feedback like a good bug report."
