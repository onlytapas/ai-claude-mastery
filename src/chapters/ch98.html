Whenever Claude reads your Jira board or a test script calls GitHub, the other system needs to know two things: who is asking and what they're allowed to do. The answer is usually a long secret string called a key or a token. These secrets are like the keys to your office: whoever holds one can get in. This chapter explains the different kinds, how AI tools use them, and the simple habits that stop them leaking.

98.1Two kinds of "token" (don't mix them up)

In AI work, the word "token" means two completely different things. Mixing them up causes a lot of confusion in meetings.

AI text tokenAccess token
What it isA small chunk of text the model reads and writes (Chapter 14)A secret string that proves who you are to a system

In everyday life

It's like the word "bill". A restaurant bill and a bird's bill share a word and nothing else. When someone says "token", ask yourself: are we talking about how much text (AI tokens) or who's allowed in (access tokens)? The rest of this chapter is about the second kind.

98.2Why systems need proof of identity

When you log in to Jira in a browser, you type your email and password (and maybe a code from your phone), and the browser keeps you signed in. Programs can't do that: they can't type passwords into web forms or read codes off your phone. So systems give programs a different kind of proof.

Two separate questions are always being answered:

Authentication: "Who are you?"

Proving identity. The key or token shows the request comes from you, or from a specific robot account.

Authorisation: "What may you do?"

Permissions. Even once identified, you can only do what you've been allowed: read issues but not delete them, for example.

In everyday life

A hotel key card does both. It proves you're a guest (authentication) and it only opens your room, the gym and the lift, not other guests' rooms (authorisation). Good access tokens work the same way: they identify you and limit what you can open.

98.3API keys

An API key is the simplest kind: one long secret string that a service gives you, which you send with every request. Anthropic's API uses keys like this. You create them in the Claude Console, and they start with sk-ant-.

  • Simple: one string, copy it, use it.
  • Powerful: anyone who has it can use the service as you and run up your bill.
  • Usually all-or-nothing: many API keys don't let you limit what they can do.
Real-world example

A developer accidentally commits a file containing an API key to a public GitHub repository. Automated bots scan public code constantly for keys, and they can find and abuse them within minutes. This is why GitHub runs "secret scanning", and why many API providers work with it to detect, and in some cases automatically revoke, leaked keys. It's also why this chapter keeps saying: never put keys in code.

98.4Personal access tokens

A personal access token (PAT) is like an API key tied to your own user account, which you create yourself in the tool's settings. It lets a program act as you. The two you'll meet most in QA:

GitHub fine-grained PATAtlassian API token (Jira, Confluence)
Where you create itGitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokensid.atlassian.com → Security → API tokens
Limit what it can do?Yes: choose specific repositories and specific permissions (for example "Issues: read")Yes: "Create API token with scopes" lets you pick the app and scopes; Atlassian recommends this
ExpiryYou choose an expiry date when creating itNew tokens expire after one year by default; you can choose 1–365 days
Shown again later?No: copy it once, straight into safe storageNo: copy it once, straight into safe storage

GitHub also has older "classic" tokens with broad permissions. Prefer fine-grained tokens: they follow the principle of least privilege (91.8).

98.5OAuth: signing in without sharing your password

You've used OAuth even if you've never heard the name. Whenever a website shows "Sign in with Google", or an app asks "Allow this app to read your calendar?", that's OAuth. It lets you give an app limited access to your account without ever giving it your password.

1 · App asksClaude Code wants to use the Jira MCP server and opens your browser
2 · You sign inOn Atlassian's own page, with your normal login and two-factor code
3 · You approve"Allow access to read and write Jira issues?" These permissions are the scopes
4 · Token issuedAtlassian gives the app an access token, never your password
5 · App worksThe app sends the token with each request until it expires

OAuth usually issues two tokens:

  • An access token: short-lived, used on every request.
  • A refresh token: used quietly in the background to get a new access token when the old one expires, so you don't have to sign in again every hour.

Remote MCP servers use OAuth. When you add a hosted server such as Atlassian's or GitHub's to Claude Code, you sign in through the browser with /mcp (or claude mcp login <name> from the terminal). Claude Code stores the tokens securely and refreshes them automatically. claude mcp logout <name> removes them.

In everyday life

OAuth is like a hotel's valet key. You hand the valet a special key that starts the car and drives it, but doesn't open the boot or the glovebox. You never give them your house keys, and you can take the valet key back at any time.

98.6How a token travels: headers and bearer tokens

Every request a program sends over the web (Chapter 85) has headers: labelled lines of extra information, like the details written on the outside of an envelope. Tokens usually travel in a header called Authorization.

How tokens are attached to requests
# "Bearer" token: whoever bears (carries) this token gets access
Authorization: Bearer YOUR_TOKEN_HERE

# Atlassian API tokens use "basic" auth: your email plus the token
curl -u you@example.com:$ATLASSIAN_TOKEN https://your-site.atlassian.net/rest/api/3/myself

# Anthropic's API also accepts its key in an x-api-key header
x-api-key: $ANTHROPIC_API_KEY

A bearer token is named that way because whoever bears it gets in, like cash: no questions asked. That's why it must stay secret. For MCP servers that need a fixed token rather than OAuth, Claude Code lets you add a header when you add the server, for example --header "Authorization: Bearer ${API_KEY}" in .mcp.json (Chapter 100).

Why HTTPS matters

A token sent over plain HTTP could be read by anyone between you and the server, like a postcard. HTTPS encrypts the whole request, headers included, like a sealed envelope that only the recipient can open. Every legitimate API and remote MCP server uses https:// addresses. If you're ever asked to send a token to an http:// address that isn't on your own machine (localhost), stop and check.

Claude Code also needs proof of identity, to Anthropic. It can sign in several ways:

If ANTHROPIC_API_KEY is set in your terminal, it can take priority over your subscription login. 98.8Least privilege, expiry and rotation

Three habits make tokens far less dangerous:

  1. Least privilege. Give each token only what the job needs. A token for "read Jira issues and add comments" shouldn't be able to delete projects. For an AI agent this matters doubly, because the AI decides which actions to take.
  2. Expiry. Set an end date. A token that expires in 90 days is a much smaller risk if it leaks next year.
  3. Rotation. Regularly create a new token, switch to it and delete the old one. Do it on a schedule, whenever someone leaves the team, and immediately after any suspected leak.
Real-world example: a QA robot account

Many teams create a dedicated test account (sometimes called a service account) for automation, instead of using a person's own login. It has access only to test projects, and its tokens are stored in the CI system's secret store. If a token leaks, the damage is limited to test data, and nobody's personal account is affected. Atlassian, for example, supports service accounts with scoped tokens, created by an administrator.

98.9Where to keep secrets

A secret is anything that grants access: keys, tokens, passwords. Here's where they should and shouldn't live.

PlaceSafe?Notes
In your code or a committed config fileNoAnyone with access to the repository, now or ever, can read it. Git history keeps it even after you delete it.
Pasted into a chat with an AINoIt becomes part of the conversation, may be stored, and is sent to the model provider. Never paste secrets into Claude.
In a screenshot or ticketNoEasy to forget, easy to share.
Environment variableOKSet in your terminal, read by programs. Good for local work.
A .env file listed in .gitignoreOKA local file of variables that git is told never to commit.
Your OS keychain or a password managerGoodEncrypted storage. Claude Code uses the macOS Keychain for its own sign-in.
CI secret store (e.g. GitHub Actions secrets)GoodEncrypted, hidden in logs, and injected only when a pipeline runs.
Company secret manager (Vault, AWS Secrets Manager and similar)Best for teamsCentral, audited, easy to rotate.
Environment variables and .env files
# set a variable for this terminal session only
export GITHUB_TOKEN="paste-token-here"

# check it's set without printing the secret itself
[ -n "$GITHUB_TOKEN" ] && echo "GITHUB_TOKEN is set"

# a .env file (one per line) — and make sure git ignores it
echo 'GITHUB_TOKEN=paste-token-here' >> .env
echo '.env' >> .gitignore

# in a GitHub Actions workflow, read a stored secret
env:
  GITHUB_TOKEN: ${{ secrets.QA_BOT_TOKEN }}

Claude Code's MCP configuration can read environment variables too: .mcp.json supports ${VAR}, so the shared file contains "Authorization": "Bearer ${API_KEY}" and each person supplies their own key locally. The file can be committed safely because it contains no actual secret.

Protect secrets from the AI too

Claude Code can read files in your project. Add a deny rule so it never reads secret files, for example "deny": ["Read(./.env)", "Read(./secrets/**)"] in .claude/settings.json (Chapter 78). Then even a confused or manipulated agent can't read them.

98.10If a secret leaks

Leaks happen to everyone eventually. What matters is acting quickly and in the right order:

  1. Revoke it immediately in the tool that issued it (GitHub settings, Atlassian API tokens page, Claude Console). Revoked tokens stop working at once. Do this first, before anything else.
  2. Create a replacement with the least access needed and update wherever it's used.
  3. Check for misuse in the tool's audit or activity logs: unusual logins, changes, unexpected spend.
  4. Remove it from where it leaked. Deleting a file isn't enough if it was committed to git: the secret stays in the history. Treat it as permanently exposed, which is why step 1 comes first.
  5. Tell your security team. Most companies want to know, and it's never a sacking offence to report quickly. Hiding it is what causes real damage.
Create, store and test a token safely30 min · terminal and browser
  1. Create a GitHub fine-grained token: Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token. Give it a 7-day expiry, access to one test repository only, and read-only "Metadata" permission.a token shown once. Copy it straight into the next step; don't save it in a document.
  2. In your terminal, run export GITHUB_TOKEN="…" (paste between the quotes), then [ -n "$GITHUB_TOKEN" ] && echo set.the word "set", and no token printed.
  3. Test it: curl -s -H "Authorization: Bearer $GITHUB_TOKEN" https://api.github.com/userJSON describing your GitHub account, such as your login name. A "Bad credentials" message means the token was copied wrongly.
  4. Ask Claude Code: "Without reading any secret values, explain what the curl command I just ran did, piece by piece."an explanation of curl, the Authorization header, the bearer token and the API address. You didn't need to show Claude the token.
  5. Finish by revoking the token in GitHub settings and running the curl command again.a "Bad credentials" error. Revocation works instantly. (Atlassian alternative: create a scoped API token at id.atlassian.com and test with curl -u email:$ATLASSIAN_TOKEN https://your-site.atlassian.net/rest/api/3/myself.)
Common misunderstandings
"Tokens in AI pricing and tokens for logging in are the same thing."
Completely different. Text tokens measure text; access tokens prove identity. Only access tokens are secret.
"It's fine to paste a token into Claude so it can help me."
Never do this. Put it in an environment variable and let tools read it from there. Claude doesn't need to see the value to help.
"I deleted the file, so the leaked key is gone."
Git history keeps it. Revoke the key; deletion alone doesn't help.
"OAuth means the app has my password."
The opposite. OAuth exists so the app gets a limited token and never sees your password.
"One powerful token for everything is simpler."
Simpler to set up, much worse when it leaks. Use separate, narrow tokens per job.

98.11Review

Key takeaways
  • "Token" means two things: AI text tokens (amounts of text) and access tokens (secret proof of identity).
  • Authentication asks who you are; authorisation asks what you may do.
  • API keys are simple, powerful secrets; personal access tokens act as your account; prefer fine-grained, scoped, expiring ones.
  • OAuth grants limited access without sharing your password, using access and refresh tokens. Remote MCP servers sign in this way.
  • Tokens travel in the Authorization header over HTTPS; bearer tokens work for whoever holds them.
  • Claude Code signs in by subscription login, Console, API key, a CI token from claude setup-token, or a credential helper. Check with claude auth status.
  • Keep secrets in environment variables, ignored .env files, keychains or secret stores, never in code or chat. If one leaks, revoke it first.
Check yourself

"Our prompt uses 3,000 tokens." Which kind of token is this?

It's an amount of text, not a secret.

What does OAuth let you do?

You approve scopes and the app receives a token.

Where should a Jira API token for your automation pipeline live?

Secret stores keep it encrypted and hidden from logs.

You accidentally committed a token to the repository. What's the first thing to do?

Revoking stops it working at once. Git history keeps the old value anyway.

Claude Code is unexpectedly using API billing instead of your subscription. A likely cause?

The environment variable can take priority; unset it to return to your subscription.
