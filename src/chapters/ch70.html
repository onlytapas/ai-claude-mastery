Claude Code is one engine with several dashboards. The same agent, with the same tools, settings and project instructions, can run in a terminal, in a panel inside VS Code, inside a JetBrains IDE, in the Claude Desktop app, or in a browser on cloud machines. Picking the right surface is about comfort and the job at hand: an editor panel for reviewing diffs line by line, the terminal for the full set of commands, the web for work that should keep running without your laptop. Your settings and CLAUDE.md follow you between most of them.

In everyday life

Think of your email. You can read the same mailbox in a browser, a desktop app or on your phone. Each looks different and has slightly different buttons, but it's the same mailbox and the same messages. Claude Code is similar: the "mailbox" is your project, settings and conversation history, and each surface is a different window onto it.

All of them need a Claude account. Any paid Claude subscription (Pro, Max, Ultra, Team or Enterprise) or a Claude Console account works for the CLI, the VS Code extension and the JetBrains plugin. Some features, such as cloud sessions, Remote Control and Chrome integration, need a subscription and may be turned off by your organisation's admin.

70.2The VS Code extension

VS Code is the editor many QA engineers already use for Playwright or Cypress tests. The Claude Code extension adds a chat panel right beside your code.

Install and sign in

  1. You need VS Code 1.94.0 or later.
  2. Open the Extensions view (Cmd+Shift+X on Mac, Ctrl+Shift+X on Windows/Linux), search for "Claude Code" (publisher Anthropic, extension ID anthropic.claude-code) and click Install. The same extension works in Cursor and other VS Code-based editors, and is also on the Open VSX Registry.
  3. Open the panel: click the Spark icon in the editor toolbar (top right, visible when a file is open), the Spark icon in the Activity Bar on the left, or ✻ Claude Code in the status bar.
  4. Click Sign in and finish in your browser.
Extension and CLI are separate installs

The extension bundles its own private copy of Claude Code for its chat panel. That copy doesn't put claude on your PATH. To type claude in VS Code's integrated terminal, you also need the standalone install (Chapter 64). The extension's version number matches the Claude Code version it bundles.

You can drag the panel to the right sidebar, the left sidebar, or the editor area as a tab. When a tab has a small coloured dot on its Spark icon, blue means a permission request is waiting and orange means Claude finished while the tab was hidden.

Reviewing changes and permission modes

The current permission mode is shown at the bottom of the prompt box, and you can change it there. In Manual mode, every file edit opens a side-by-side diff of the original and the proposed change. You can accept, reject, or tell Claude what to do instead, and for smaller diffs you can accept or reject one change at a time. In Auto or Edit automatically mode, Claude edits most files without asking, so review the changes afterwards in source control.

The default changed

Since Claude Code v2.1.283, new VS Code conversations start in Auto mode, where a background classifier reviews actions instead of asking you each time (if auto mode is available on your account). If you want to approve each edit while learning, set the extension setting initialPermissionMode to manual (an alias for default), or choose Manual in the mode selector. VS Code reads this setting from your user settings only.

Extension vs CLI: what's different, and how they connect

The extension is a graphical front end to the same engine, but not everything is there. Per the documentation:

When you need a CLI-only feature, open the integrated terminal (Ctrl+`) and run claude. With the extension installed, a CLI session started there connects to VS Code automatically, so diffs open in the editor and diagnostics (lint and type errors) can be shared. From an external terminal, type /ide inside Claude Code to connect, or start with claude --ide to connect automatically when exactly one IDE is available.

The extension and the CLI share conversation history: to continue an extension conversation in the terminal, run claude --resume and pick it.

70.3JetBrains IDEs

If your team writes tests in IntelliJ IDEA, PyCharm, WebStorm, GoLand, PhpStorm or Android Studio, use the JetBrains plugin. It works differently from the VS Code extension: it doesn't bundle Claude Code. It runs the claude command in the IDE's integrated terminal and connects to it.

  1. Install the Claude Code CLI first (Chapter 64). If the plugin shows "Cannot launch Claude Code", it can't find claude on your PATH; set the full path in the plugin's "Claude command" setting.
  2. Install the "Claude Code" plugin from the JetBrains Marketplace and restart the IDE.
  3. Open it with Cmd+Esc (Mac) / Ctrl+Esc, or the Claude Code button.
FeatureWhat it gives you
Diff viewingChanges open in the IDE's own diff viewer (switch with the "Diff tool" setting in /config)
Selection contextYour current selection or tab is shared with Claude automatically, except files blocked by Read deny rules
File referencesCmd+Option+K / Alt+Ctrl+K inserts a reference such as @src/auth.ts#L1-99
DiagnosticsClaude can read the IDE's inspection results (lint and syntax errors) through a built-in tool

To connect a session running in a separate terminal, start claude in your project's root folder and type /ide. On success you'll see a message like "Connected to IntelliJ IDEA."

70.4The Claude Desktop app's Code tab

In the Claude Desktop app (macOS, Windows, and Linux in beta), Claude Code is the Code tab, next to chat. It's a good choice for people who prefer windows and buttons to a terminal, and for running several sessions side by side.

  • Start a session: under the prompt box, pick the environment (local, cloud or SSH), the project folder, the permission mode and the model.
  • Parallel sessions: + New in the sidebar (Cmd/Ctrl+N). In a git project, turn on Worktree before starting so each session gets its own copy of the files (Chapter 69).
  • Panes: arrange the chat, diff view, a browser preview of your running app, a terminal and a file editor side by side.
  • Diff review and PR monitoring: review and comment on changes, then watch the pull request through CI.
  • Move between surfaces: from the terminal, /desktop (alias /app) continues the current session in Desktop, and claude --desktop opens Desktop on the current folder (add --continue or --resume <id> to pick a session). These need macOS or x64 Windows and a subscription. In Desktop, /resume can pick up sessions started in the CLI.

Desktop's permission selector shows the same modes with friendlier names: Manual (default), Accept edits, Plan, Auto and Bypass permissions. The dontAsk mode is CLI-only.

70.5Claude Code on the web and on your phone

Claude Code on the web lives at claude.ai/code. Sessions there are cloud sessions: they run on Anthropic-managed machines (or your organisation's self-hosted environment), not your laptop. You can also start them from the Code tab in the Claude mobile app, from Desktop, or from the terminal with claude --cloud "task".

Good for

  • Long tasks that shouldn't depend on your laptop being on
  • Kicking off work from your phone
  • Fixing a failing pull request: auto-fix watches a PR and responds to CI failures and review comments (needs the Claude GitHub App on the repository)

Know the limits

  • The repository must be on GitHub to be cloned in Anthropic-hosted environments; push your branch first
  • The session works on a fresh clone, so it doesn't see files that exist only on your computer
  • Cloud usage shares your account's rate limits
  • Available on Pro, Max, Ultra and Team, and for Enterprise users with the right seat type; admins can restrict it

To bring a cloud session down to your terminal, use claude --teleport or /teleport. To steer a session that runs on your computer from your phone, use Remote Control instead (Chapter 69).

70.6Claude in Chrome

Chrome integration lets Claude Code use your real browser: open pages, click and read, sharing your browser's logged-in state. Start with claude --chrome; /chrome shows status, permissions and lets you reconnect; --no-chrome turns it off; and the /claude-in-chrome [task] skill hands Claude a browser task. Requirements: Chrome, Edge or another Chromium browser, the "Claude in Chrome" extension (v1.0.36 or later), a direct Anthropic plan and a /login sign-in. API keys and setup-token tokens keep it off. Claude pauses for logins and CAPTCHAs.

Real-world example: Chrome or Playwright?

For a quick look at a staging page while you're already signed in ("does the new banner overlap the menu on the pricing page?"), Chrome integration is handy because it uses your session. For repeatable, isolated testing that ends up as test code, use the Playwright MCP server and real Playwright tests (Chapter 102). Never point Chrome integration at production accounts or customer data you wouldn't let a script touch.

Common misunderstandings
"Installing the VS Code extension lets me type claude in any terminal."
The extension bundles a private copy. Install the standalone CLI for the terminal.
"The JetBrains plugin works without the CLI."
It runs the claude command, so the CLI must be installed and on your PATH.
"Every command works everywhere."
The extension has a subset, dontAsk is CLI-only, and cloud sessions offer only Accept edits, Plan and Auto.
"Cloud sessions can see my local .env and test data."
They work on a fresh clone from GitHub. Anything not committed and pushed isn't there.
"VS Code always asks before editing."
New conversations now start in Auto mode where available. Choose Manual if you want to approve each edit.

70.9Review

Key takeaways
  • Claude Code is one engine with several front ends: terminal, VS Code, JetBrains, Desktop, web and mobile.
  • The VS Code extension gives a chat panel with selection context, @-mentions (Option/Alt+K) and side-by-side diffs; it bundles its own copy, so install the CLI separately for the terminal.
  • The JetBrains plugin runs the installed CLI and adds IDE diffs, selection sharing and diagnostics; /ide connects an external terminal session.
  • The Desktop Code tab is good for parallel sessions with worktrees; /desktop and --desktop move sessions there.
  • Web and mobile sessions run in the cloud on a fresh GitHub clone; Chrome integration uses your real browser.
  • Commit team rules (CLAUDE.md, .claude/, .mcp.json) so every surface follows them.
Check yourself

You installed the VS Code extension, but typing claude in the integrated terminal says "command not found". Why?

The extension's copy isn't put on your PATH.

How do you connect a Claude Code session in an external terminal to your JetBrains IDE?

/ide connects; claude --ide auto-connects when exactly one IDE is available.

A cloud session can't find the .env file your tests need. What's the most likely reason?

Only what's committed and pushed is available in the clone.

You want to approve every edit Claude makes in VS Code while you learn. What do you do?

New conversations start in Auto mode where available, which doesn't ask for each edit.

Which is the best way to make sure every surface follows your team's rules?

Committed files are on disk locally and in every cloud clone.
