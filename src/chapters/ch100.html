The same MCP server can be reached from several places: Claude Code in your terminal or editor, claude.ai in the browser, the Claude desktop app, and the Claude API. Each has its own way of adding servers. In claude.ai and the desktop app, servers are called connectors and you add them through menus. In Claude Code you add them with claude mcp commands or a .mcp.json file your team shares. Knowing where each lives, and who controls it, is what lets you set up a whole QA team consistently.

In everyday life

Think of streaming-service apps. You can watch the same service on your phone, your laptop and your TV, but you sign in separately on each, and the TV at work might be locked down by IT. MCP servers are like that: one service, several "screens", each with its own sign-in and its own rules.

100.2Claude Code: adding a server

All commands below are run in a normal terminal, not inside a Claude session. They were checked against Claude Code 2.1.319's own help output.

A remote server (Streamable HTTP)

# the pattern
claude mcp add --transport http <name> <url>

# a real example from Anthropic's documentation
claude mcp add --transport http notion https://mcp.notion.com/mcp

# a server that takes a fixed API key in a header instead of OAuth
claude mcp add --transport http secure-api https://api.example.com/mcp \
  --header "Authorization: Bearer your-token"

A local server (stdio)

# the pattern: options BEFORE the name, the server's own command AFTER --
claude mcp add [options] <name> -- <command> [args...]

# a file-system server limited to one folder
claude mcp add files -- npx -y @modelcontextprotocol/server-filesystem ~/claude-lab

# a server that needs an API key in an environment variable
claude mcp add --env AIRTABLE_API_KEY=YOUR_KEY --transport stdio airtable -- npx -y airtable-mcp-server

The -- matters. Everything after it is handed to the server program unchanged; everything before it is for Claude Code. Putting --env after the -- is a common mistake.

The main options

OptionMeaning
-t, --transportstdio (the default), http or sse (deprecated)
-s, --scopelocal (the default), project or user. See 93.3.
-e, --env KEY=valueAn environment variable for a stdio server, typically a token
-H, --header "Name: value"A header sent to an HTTP or SSE server, such as an API key
--client-id, --client-secret, --callback-portFor servers that need a pre-registered OAuth app (Chapter 98)

Other ways to add servers: claude mcp add-json <name> '<json>' takes a JSON definition (and is the only way to add WebSocket servers), and claude mcp add-from-claude-desktop imports servers from the desktop app (93.7). Server names added through claude mcp may contain only letters, numbers, hyphens and underscores.

100.3Scopes: just me, my team, or everywhere

Every server you add lives in a scope that decides who gets it and where it's stored:

ScopeWho gets itStored inUse it for
local (default)Only you, only in this project~/.claude.json, under this project's pathTrying a server; servers with your personal credentials
projectEveryone who works in this repository.mcp.json at the project root, committed to gitThe team's standard servers, such as Playwright for the test repo
userOnly you, in every project~/.claude.jsonTools you use everywhere, such as your issue tracker

If two servers have the same name, Claude Code uses the closest one: local beats project, project beats user, and those beat plugin servers and claude.ai connectors.

The shared team file: .mcp.json

.mcp.json, committed in the test repository
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest"]
    },
    "test-api": {
      "type": "http",
      "url": "${API_BASE_URL:-https://staging.example.com}/mcp",
      "headers": { "Authorization": "Bearer ${TEST_API_TOKEN}" }
    }
  }
}
  • ${TEST_API_TOKEN} is filled in from each person's own environment when Claude Code starts. The secret never goes in the file, so the file is safe to commit (Chapter 98 covers storing the secret itself).
  • ${API_BASE_URL:-https://…} means "use API_BASE_URL if it's set, otherwise this default", handy for switching between staging and test environments.
  • An entry with no type is treated as stdio. An entry with a url but no type is an error.
Project servers need your approval

A .mcp.json server can start programs on your computer, so Claude Code won't connect to one until you approve it in an interactive session. Until then, claude mcp list shows it as ⏸ Pending approval. A freshly cloned repository can't approve its own servers: approval settings committed in the project are ignored until you've trusted the folder. To clear your earlier approve-or-reject choices for a project, run claude mcp reset-project-choices.

100.4Checking, signing in, using and removing

claude mcp list                  # every configured server, with a health status
claude mcp get playwright        # details for one server, including any connection problem
claude mcp remove playwright     # delete it (add -s to choose the scope)
claude mcp login jira            # OAuth sign-in from the shell (--no-browser over SSH)
claude mcp logout jira           # forget the stored sign-in

Statuses you'll see in claude mcp list:

StatusMeaningWhat to do
✔ ConnectedWorkingNothing
! Needs authenticationThe server wants you to sign inOpen /mcp in a session, or run claude mcp login <name>
✘ Failed to connectClaude Code couldn't reach or start it; details followRun claude mcp get <name> and read the Issue: line (Chapter 105)
⏸ Pending approvalA project server you haven't approvedStart claude in the project and approve it
⊘ Disabled for this projectYou switched it off in /mcpTurn it back on in /mcp

Inside a session: /mcp

Typing /mcp opens a panel listing every server (your own, the team's, plugins' and claude.ai connectors) with its status and tools. From a server's menu you can sign in, reconnect, clear its sign-in, or disable it for this project without deleting its configuration.

Using what servers offer

  • Tools: just ask. "Open the staging login page and screenshot it" uses Playwright's tools. Claude Code asks permission the first time unless a rule allows it.
  • Resources: type @ to see them, e.g. @github:issue://123.
  • Prompts: appear as commands, e.g. /mcp__github__pr_review 456.
Time limits and big results
  • Tool-call time limit: set a timeout in milliseconds on one server's entry, or MCP_TOOL_TIMEOUT for all. A call that goes quiet (no reply, no progress) for the idle window (5 minutes for remote servers, 30 for stdio by default) is stopped with an error; CLAUDE_CODE_MCP_TOOL_IDLE_TIMEOUT changes that window.
  • Long calls: a call in the main conversation that runs longer than two minutes moves to a background task, so the session isn't blocked.
  • Big results: output over 10,000 tokens triggers a warning; the default cap is 25,000 tokens (MAX_MCP_OUTPUT_TOKENS). Larger results are saved to a file Claude can read in parts.

100.5claude.ai: connectors

In claude.ai and the desktop app, remote MCP servers are called connectors. They live under Customize › Connectors.

From the Connectors directory

  1. Go to Customize › Connectors and select Discover.
  2. Search for the service, such as Jira or Google Drive, and open its page.
  3. Select Connect to Claude, sign in to the service, and approve the access it asks for.
  4. Back on the Connectors page it shows as Connected.

Each directory listing carries a label:

LabelMeaning
Verified (checkmark)Anthropic tested its tools for quality and compatibility. Not a security audit, and the developer can change tools after review.
CommunityBuilt by a third party and screened, but not reviewed in depth
CustomAdded by you or your organisation by URL; not reviewed by Anthropic

A custom connector (by URL)

Any remote MCP server can be added by its URL, even if it isn't in the directory:

  • Free, Pro, Max and Ultra plans: Customize › Connectors › Add custom connector, then enter the URL. The Free plan allows one custom connector.
  • Team and Enterprise plans: an Owner adds it under Organization settings › Connectors (Add › Custom › Web). Members then connect with their own account from Customize › Connectors. Members can't add custom connectors themselves.
  • Sign-in choices include signing each user in through OAuth, or "No sign-in" with an API key sent as a request header. The request-headers option is in beta for a limited set of organisations. Sign-in settings can't be edited later; remove and re-add the connector to change them.

Using connectors in a chat

Click + in the message box, choose Connectors, and switch each one on or off for that conversation. Under Customize › Connectors you can set individual tools to Blocked, for example a "delete" tool you never want used.

Real-world example: a QA view

A test lead connects Jira and Confluence in claude.ai and asks: "Compare the acceptance criteria in SHOP-812 with the test plan page in Confluence. List any criteria without a test." No terminal needed. Claude reads both through connectors and returns a gap list. The same lead uses Claude Code with Playwright for the part that needs a browser.

Availability varies

Which connectors you see, and whether you can add your own, depends on your plan and your organisation's settings. Owners decide which connectors a Team or Enterprise organisation offers.

100.6Your connectors inside Claude Code

If you sign in to Claude Code with a claude.ai account, the connectors you've added in claude.ai appear in Claude Code automatically. /mcp lists them in a claude.ai section. Their tools are named mcp__claude_ai_<server>__<tool> in permission rules.

  • They're not loaded when Claude Code is using a different sign-in method, such as an ANTHROPIC_API_KEY, a cloud provider like Amazon Bedrock, or a token from claude setup-token. If a connector is missing, run /status to check which method is active.
  • A server you added yourself with the same URL takes precedence, and the connector is listed as hidden.
  • To stop Claude Code loading connectors, set "disableClaudeAiConnectors": true in a settings file, or start with ENABLE_CLAUDEAI_MCP_SERVERS=false claude.
  • Organisation tool controls apply here too. A tool set to ask prompts on every call, even in auto mode. A tool set to blocked is removed before Claude sees it.

100.7The Claude desktop app

The desktop app (macOS and Windows) uses the same connectors as claude.ai, and adds two ways to run servers locally on your computer:

Desktop extensions (.mcpb)

A desktop extension is a local MCP server packaged as a single .mcpb file (an "MCP Bundle"): a zip containing the server and a manifest.json. It installs in one click, much like a browser extension, and runs on your machine over stdio, so it can reach local files and systems behind your firewall.

  1. In the desktop app, open Settings › Extensions.
  2. Drag the .mcpb file onto the page and review the preview.
  3. Select Install and confirm.

Organisations can turn extensions off or restrict which ones can be installed. If Extensions doesn't appear in Settings, they're turned off for you.

The developer configuration file

Local servers can also be added by hand in Settings › Developer › Edit Config, which opens claude_desktop_config.json:

SystemLocation
macOS~/Library/Application Support/Claude/claude_desktop_config.json
Windows%APPDATA%\Claude\claude_desktop_config.json

It uses the same mcpServers shape as .mcp.json. Restart the app after editing it.

Moving between the desktop app and Claude Code

# copy servers from the desktop config into Claude Code (macOS and WSL only)
claude mcp add-from-claude-desktop
claude mcp add-from-claude-desktop --scope user     # make them available in every project

# the other direction: run Claude Code itself as a stdio MCP server
claude mcp serve

The import shows a list to choose from, skips servers whose names contain spaces or other unsupported characters, and adds a numeric suffix (such as server_1) if a name already exists. claude mcp serve prints nothing when it starts: it's waiting for a client. To use it from the desktop app, add an entry with "command": "claude" and "args": ["mcp", "serve"] (use the full path from which claude if needed). The connecting app is then responsible for asking you before each tool call.

100.8The Claude API: the MCP connector

Developers building their own apps on the Claude API (Part XI) can attach remote MCP servers to a request directly, without writing an MCP client. The feature is in beta and needs a beta header.

Shape of a request (from Anthropic's documentation)
curl https://api.anthropic.com/v1/messages \
  -H "Content-Type: application/json" \
  -H "X-API-Key: $ANTHROPIC_API_KEY" \
  -H "anthropic-version: 2026-10-21" \
  -H "anthropic-beta: mcp-client-2025-11-20" \
  -d '{
    "model": "claude-opus-5-5",
    "max_tokens": 1000,
    "messages": [{"role": "user", "content": "What tools do you have available?"}],
    "mcp_servers": [
      { "type": "url", "url": "https://example-server.modelcontextprotocol.io/sse",
        "name": "example-mcp", "authorization_token": "YOUR_TOKEN" }
    ],
    "tools": [ { "type": "mcp_toolset", "mcp_server_name": "example-mcp" } ]
  }'
  • mcp_servers says where each server is and how to authenticate; a matching mcp_toolset in tools says which of its tools to enable (all, an allowlist, or a denylist).
  • Only tools are supported (not resources or prompts), and the server must be reachable over the internet. Local stdio servers can't be used.
  • A newer beta header, mcp-client-2026-09-15, adds the ability to pin a server's tool list during a conversation.
  • Your code must obtain the OAuth token itself; the API doesn't run a browser sign-in. Chapter 98 explains how.

Common misunderstandings
"I added it in claude.ai, so it's in Claude Code too."
Only if Claude Code is signed in with that same claude.ai account. With an API key or cloud provider, connectors aren't loaded.
"Putting the token in .mcp.json is fine; it's a private repo."
Never commit secrets. Use ${VARIABLE} references and keep the value in each person's environment or a secrets manager.
"The server is in .mcp.json, so why isn't it connecting?"
Project servers need approval in an interactive session first. Look for ⏸ Pending approval.
"Verified means safe."
Verified means Anthropic tested quality and compatibility. It isn't a security audit. Review scopes and block tools you don't need.
"The API connector can use my local Playwright server."
The API connector reaches only public remote servers, and only their tools.

100.11Review

Key takeaways
  • MCP appears in Claude Code (servers), claude.ai and the desktop app (connectors and extensions), and the API (the MCP connector, beta).
  • Claude Code: claude mcp add with --transport http for remote or -- command for local; options go before the name.
  • Scopes: local (you, this project), project (team, in .mcp.json), user (you, everywhere). Project servers need approval.
  • Check with claude mcp list/get, manage in /mcp, sign in with /mcp or claude mcp login.
  • claude.ai connectors come from the directory (Verified/Community) or by URL (Custom); on Team/Enterprise, Owners add them.
  • Desktop extensions (.mcpb) install local servers in one click; add-from-claude-desktop and mcp serve bridge the desktop app and Claude Code.
  • Organisations control connectors, individual tools, managed server lists and extensions.
Check yourself

You want everyone who clones the test repository to get the Playwright server. Which scope?

Project scope is stored in .mcp.json at the repository root, which you commit.

What's wrong with claude mcp add airtable -- npx -y airtable-mcp-server --env KEY=abc?

Claude Code's options must come before the name; everything after -- belongs to the server.

You're on a Team plan and want a custom connector by URL in claude.ai. Who adds it?

On Team and Enterprise, Owners add connectors for the organisation.

Your claude.ai connectors don't appear in Claude Code. What should you check first?

Connectors load only when the active sign-in is a claude.ai subscription login.

Which statement about the API's MCP connector is true?

Remote servers only, tools only, beta; your code supplies the token.

Assignment

Design your QA team's MCP setup on one page. List each tool your team uses (Jira, Confluence, GitHub, a test database, Playwright and so on), choose the surface for each (claude.ai connector, Claude Code project server, personal server, or desktop extension), and say who adds it and where its credentials live. Then write the .mcp.json for your test repository with ${VARIABLE} placeholders and no secrets, and have a colleague review it.

Teach it

"MCP servers can be used from four places. In claude.ai and the desktop app they're called connectors: you pick them from a directory or add a URL, and on company plans an Owner adds them. In Claude Code you use claude mcp add: HTTP for remote services, a command for local ones. Choose a scope: local for you, project to share with the team through .mcp.json, user for everywhere. Check with claude mcp list and /mcp. Developers can attach remote servers to API calls too. And never put a token in a shared file."
