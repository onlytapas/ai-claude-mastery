Before you start: Chapter 52: you can open a terminal and recognise the prompt. This chapter uses three commands lightly: pwd (show where I am), ls (list what's here) and cd (move). Chapter 54 covers them in full.

Every file and folder on a computer has an address called a path. On macOS and Linux all addresses start from a single top folder, the root, written /, and folders inside folders are joined with more slashes, like /Users/alex/Documents/report.pdf. You can give an address in full from the root (absolute) or starting from where you are now (relative), and a few shorthands, ~, . and .., mean "home", "here" and "one level up". Once you can read paths, most terminal errors and most of what Claude Code reports about your project make sense. Small details, such as capital letters, spaces and a leading dot, change what a path points to.

53.1The filesystem is a tree

A file is a named piece of stored data: a document, a photo, a test script, a log. A directory is a container for files and other directories. "Directory" and "folder" mean the same thing; terminal documentation tends to say directory, the desktop says folder. The way the OS organises all of them is called the filesystem.

Folders inside folders form a tree. Computer people draw it upside down: the single starting point, the root, is at the top, and everything branches down from it.

Part of a Mac's filesystem (simplified)
/                               # the root: top of everything
├── Applications                # installed apps
├── System                      # macOS itself (don't touch)
├── Users

│   └── alex                    # alex's home folder
│       ├── Desktop

│       └── projects
│           └── shop-tests
│               ├── package.json
│               └── tests
│                   └── login.spec.ts
├── bin                         # basic commands like ls and cp
├── tmp                         # temporary files
└── usr                         # more programs and their files
In everyday life

Think of a library. The building is the root. Inside are floors, on each floor are rooms, in each room are shelves, and on each shelf are books. To tell someone where a book is, you give the route from the entrance: "Building / Floor 2 / Science room / Shelf 4 / Biology Basics". A path is exactly that kind of route.

53.2Your home folder and ~

Each person who logs in gets a home directory: a personal folder for their documents, downloads and settings. On a Mac it's /Users/ followed by your user name. Because you use it constantly, every Unix shell gives it a one-character nickname: ~ (the tilde, usually next to the 1 key or Shift+`).

Terminal (macOS, real output, name changed)
echo ~                # what does ~ stand for?
/Users/alex
echo ~/Documents      # ~ works at the start of longer paths too
/Users/alex/Documents
ls ~                  # list my home folder
Desktop
Documents
Downloads
Library
Movies
Music
Pictures
Public

The shell replaces ~ with your real home path before running the command, so echo simply prints the result. Your home folder will contain more than this, depending on what you've installed. When a new terminal opens, it starts in your home folder, which is why the prompt shows ~.

On Windows the home folder is C:\Users\alex. PowerShell also understands ~ and $HOME; Command Prompt uses %USERPROFILE%. Documentation for Claude Code writes paths like ~/.claude/settings.json; on Windows that means %USERPROFILE%\.claude\settings.json.

Your Desktop may not be on your disk

If iCloud Drive's "Desktop & Documents Folders" option (or OneDrive's folder backup on Windows) is turned on, those folders sync to the cloud and files may be stored online until opened. That's usually fine, but for code projects and test runs, a plain folder such as ~/projects avoids slow syncing and surprise conflicts.

53.3Absolute and relative paths

At every moment your shell is "standing" in one folder, called the current or working directory. The command pwd ("print working directory") tells you which:

Terminal (macOS, real output, name changed)
pwd
/Users/alex

There are two ways to write the address of a file:

Absolute path

The full route from the root. Always starts with / (or ~, which expands to one). It means the same thing no matter where you're standing.

/Users/alex/projects/shop-tests/tests/login.spec.ts

Relative path

The route from where you are now. Never starts with /. Its meaning depends on your working directory.

Standing in /Users/alex/projects: shop-tests/tests/login.spec.ts

In everyday life

An absolute path is a full postal address: "12 High Street, Leeds, LS1 4AB, UK". Anyone anywhere can find it. A relative path is directions from where you're standing: "second door on the left". Perfect if you're in the right corridor, useless if you're not.

How the shell turns a relative path into an absolute one:

Working directory/Users/alex/projects
Relative path typedshop-tests/tests
Shell joins them with //Users/alex/projects/shop-tests/tests
Resultthe folder it uses

Reading a path is just reading the folder names left to right, each / meaning "go inside":

PieceMeaning
/Start at the root
Users/go into the Users folder
alex/go into alex's home folder
projects/shop-tests/tests/then three more folders down
login.spec.tsthe file itself (the last name in a path may be a file or a folder)
Real-world example

A Playwright run fails in CI with Error: ENOENT: no such file or directory, open 'fixtures/users.json'. That's a relative path. It worked on your laptop because you ran the tests from the project folder. The CI job ran them from a different folder, so the same relative path pointed nowhere. The fix is either to run from the right folder or build the path from the test file's own location. Recognising "this is relative, so it depends where I'm standing" turns a mysterious error into a two-minute fix.

Why Claude Code cares

Claude Code treats the folder you start it in as its working directory, and works freely inside it while asking before going outside (Chapter 65). So cd into your project before typing claude. Its messages and permission prompts often show paths; reading them tells you exactly which file it wants to touch.

53.4Dot and dot-dot: here and up

Two special names exist in every folder:

NameMeansExample

..The folder one level up (the parent)cd .. = go up one; ls .. = list the parent
../..Two levels upcd ../..
../reportsUp one, then into a sibling folder called reportsls ../reports

A real session, moving around a practice folder (paths shortened to /Users/alex for readability):

Terminal (macOS, real output)

pwd

Notice that cd prints nothing when it works: the change shows up in the prompt and in pwd. On a Mac, pwd after cd /tmp prints /tmp, though /tmp is actually a shortcut to /private/tmp; pwd -P shows the real location.

Under the hood: why does every folder contain . and ..?

In Unix filesystems, a directory is itself a small table that maps names to the stored files. Every directory's table contains two extra entries created automatically: . points to the directory itself and .. points to its parent. The root's .. points back to the root, so cd .. at / keeps you at /. You can see the two entries with ls -a (next section). The ./ in ./run-tests.sh matters for a different reason: for safety, the shell doesn't look in the current folder for programs to run unless you say so explicitly (Chapter 56 explains the PATH).

53.5Hidden files: names that start with a dot

On macOS and Linux, any file or folder whose name begins with . is a hidden file. Finder and ls don't show it by default. It isn't secret or protected; it's just kept out of the way. Most hidden files are settings ("dotfiles").

Terminal (macOS, real output)
ls                     # normal listing
logs
notes.txt
reports
test-plan.md
ls -a                  # -a = all, including hidden
.
..
.secret-config
logs
notes.txt
reports
test-plan.md

With -a you see three extra lines: . and .. (53.4) and the hidden file .secret-config. Hidden files you'll meet constantly:

NameWhat it is
~/.zshrcYour zsh settings, run each time a terminal opens (Chapter 56)
.git/The folder where Git stores a project's entire history (Chapter 61)
.gitignoreThe list of files Git should not track

.claude/, ~/.claude/Claude Code's project and personal settings, skills and agents (Chapter 78)
.github/GitHub settings, including CI workflows
.DS_StoremacOS's record of how Finder displays a folder; harmless clutter
Seeing hidden files outside the terminal

In a Mac Finder window, press Cmd+Shift+. to show or hide them. On Windows, hidden is a file property rather than a naming rule: in File Explorer use View → Show → Hidden items, and in PowerShell use Get-ChildItem -Force. Windows tools still respect dot-names like .gitignore and .env because the programs that use them were written for Unix first.

Hidden is not safe

A .env file full of credentials is "hidden" only from casual listings. Any program you run, including an AI agent, can read it. Keeping secrets out of the folders you hand to tools is covered in Chapter 98.

53.6File extensions: the bit after the last dot

A file extension is the ending after the final dot in a file name: report.pdf, login.spec.ts, results.xml. It's a label that tells you and the system which kind of content to expect and which app should open it. In login.spec.ts the extension is .ts (TypeScript); .spec is part of the name, a testing convention for "this is a test file".

ExtensionKind of contentWhere you meet it in QA
.txt, .logPlain textNotes, server and test-runner logs
.mdMarkdown: text with light formattingREADMEs, CLAUDE.md, test plans
.csvComma-separated tableTest data, exported results
.jsonStructured data (Chapter 85)API responses, package.json, settings
.yml / .yamlStructured settingsCI pipelines (GitHub Actions)
.xmlStructured dataJUnit test reports, Maven pom.xml
.js, .ts, .py, .javaSource codeTest scripts and automation
.shShell script (Chapter 57)Helper scripts to run suites
.htmlWeb pagePlaywright and Allure reports

The extension is a convention, not a guarantee. Renaming photo.jpg to photo.txt doesn't turn the picture into text. The file command looks at the content itself:

Terminal (macOS, real output)
file notes.txt reports
notes.txt: ASCII text
reports:   directory

Here file was given two names (you can give many). It reports that notes.txt really contains plain text (ASCII is the basic English character set), and that reports, which has no extension at all, is a directory. Folders rarely have extensions; plenty of files don't either (Makefile, Dockerfile, LICENSE).

Show extensions on your desktop

Both Finder and File Explorer can hide extensions, which is how invoice.pdf.exe can masquerade as a PDF. Turn them on: Finder → Settings → Advanced → "Show all filename extensions"; Windows File Explorer → View → Show → "File name extensions". The terminal always shows full names.

53.7Upper and lower case

Is Readme.txt the same file as readme.txt? It depends on the system, and the difference is a classic source of "works on my machine" bugs.

SystemCase-sensitive?What that means
Linux (and therefore most CI runners and Docker containers)YesReadme.txt and readme.txt are two different files that can sit side by side
macOS (default APFS format)No, but case-preservingIt remembers how you typed the name, but treats both spellings as the same file
Windows (NTFS)No, but case-preservingSame as macOS by default

Real output from a Mac shows the "same file" behaviour:

Terminal (macOS, real output)
touch Readme.txt        # create an empty file called Readme.txt
ls readme.txt           # ask for it in lower case
readme.txt
touch README.TXT        # try to create a third spelling
ls
Readme.txt
...

On the Mac, ls readme.txt finds the file even though it's spelled differently, and touch README.TXT doesn't create a new file: there's still only Readme.txt. On Linux the same ls readme.txt would fail with "No such file or directory", and touch README.TXT would create a second file. Commands themselves are case-sensitive everywhere in Unix shells: LS is not ls.

Real-world example

A developer renames loginPage.ts to LoginPage.ts but a test still says import { LoginPage } from './pages/loginPage'. Every test passes on their Mac, because the Mac treats the two names as the same file. The Linux CI runner can't find loginPage.ts and the whole suite fails to start. The lesson for testers: when something passes locally but fails only in CI with "not found", check the capitals.

Safe naming habit

Use lower case, digits and hyphens for anything you create in projects: login-tests, run-2026-11-09.log. No spaces, no capitals that could be mistyped, no special characters. Many teams write this into their conventions, and it avoids every problem in this section and the next.

53.8Spaces and special characters: quoting

The shell splits what you type into words at every space. That's how it tells a command from its arguments (Chapter 54). So a name with a space in it looks like two names:

Terminal (macOS, real output)
ls -l test plan.md
ls: plan.md: No such file or directory
ls: test: No such file or directory

The shell gave ls two separate names, test and plan.md, and neither exists. There are three ways to keep a space inside one name:

Terminal (macOS, real output)
ls -l "test plan.md"     # double quotes
-rw-r--r--@ 1 alex  staff  0 Nov  9 14:45 test plan.md
ls -l 'test plan.md'     # single quotes
-rw-r--r--@ 1 alex  staff  0 Nov  9 14:45 test plan.md
ls -l test\ plan.md      # backslash before the space
-rw-r--r--@ 1 alex  staff  0 Nov  9 14:45 test plan.md

All three work. (The long line of output is the detailed listing from ls -l, explained in Chapter 54.)

FormWhat it doesUse it when
"…" double quotesKeeps spaces together; still expands $VARIABLESMost of the time
'…' single quotesKeeps everything exactly as typed; no expansion at allText containing $ or other special characters you want left alone
\ backslash"Treat the next character as ordinary"One or two awkward characters; Tab completion adds these for you

The mistake can also create a mess. mkdir My Reports without quotes makes two folders, My and Reports (real result, checked while writing this chapter). And zsh's reply to cd My Reports is the puzzling cd: string not in pwd: My, because zsh's cd has a special meaning for two words; bash says cd: My: No such file or directory. Both mean "you forgot the quotes".

Two shortcuts that quote for you

Tab completion: type cd My and press Tab; the shell writes My\ Reports/ with the backslash in place. Drag and drop: drag a file or folder from Finder into the Terminal window and its full, correctly escaped path is typed for you. Both are faster and safer than typing long paths by hand.

Characters that cause trouble in names: spaces, * ? [ ] $ & ; | < > ( ) ' " \ ! and # all have special meanings to the shell (Chapters 55–57). / can never be part of a name on macOS or Linux because it separates folders. Windows additionally forbids \ : * ? " < > | in names.

Walk the tree25 min · your own computer, Terminal
  1. Open a terminal and type pwd./Users/yourname on a Mac, /home/yourname on Linux or WSL.
  2. Type echo ~.the same path as step 1: ~ is your home.
  3. Type ls /, then ls /Users (Linux/WSL: ls /home).the root folders listed in 53.1; then your own user name plus Shared on a Mac (and any other accounts on the machine).
  4. Type cd /tmp, then pwd./tmp. The prompt now shows tmp instead of ~.
  5. Type cd ~/Documents (absolute, via the tilde), then pwd./Users/yourname/Documents.
  6. Type cd .., then pwd.you're back in your home folder.
  7. Type cd Documents (relative this time), then cd ../Downloads, then pwd./Users/yourname/Downloads: up one, then across into a sibling.
  8. Type cd on its own, then ls, then ls -a.a few normal folders, then a longer list beginning . and .. and including hidden names such as .zshrc (if present) and .Trash.
  9. Type file ~/.zshrc (if ls -a showed it) or file /bin/ls.ASCII text for your settings file, or a description of a "Mach-O" executable (Mac program) for /bin/ls.
  10. Make a test folder with a space: mkdir "/tmp/My Reports". Then type cd /tmp/My and press Tab, then Enter, then pwd.Tab completes to /tmp/My\ Reports/; pwd prints /tmp/My Reports.
  11. Go back and try it wrong: cd, then cd /tmp/My Reports.zsh: cd: string not in pwd: /tmp/My; bash: cd: /tmp/My: No such file or directory. Add quotes and it works.

Troubleshooting: No such file or directory → check spelling, capitals and spaces; press Tab to let the shell complete it. Operation not permitted when listing Desktop, Documents or Downloads on a Mac → macOS privacy controls; allow Terminal in System Settings → Privacy & Security → Files and Folders (or Full Disk Access) if you trust it. Windows PowerShell: pwd, cd and ls work there too, but paths look like C:\Users\yourname, and ls -a must be Get-ChildItem -Force. The /tmp/My Reports folder is harmless; temporary files in /tmp are cleared automatically over time.

Common misunderstandings
"A path starting with a folder name is the same wherever I run it."
Only absolute paths (starting with / or ~) mean the same everywhere. Relative paths depend on your working directory.
"Hidden files are protected or encrypted."
A leading dot only hides a file from normal listings. Any program can read it.
"The extension decides what a file is."
It's a label. The content decides. file shows what's really inside.
"If it works on my Mac, file names are fine."
macOS ignores case by default; Linux CI doesn't. A wrong capital can pass locally and fail in the pipeline.
"Folder and directory are different things."
Same thing, two words. Terminals and documentation tend to say directory.

53.9Review

Key takeaways
  • All files form one tree starting at the root / (each drive letter on Windows). A path is the route through the tree.
  • ~ is your home folder: /Users/you on macOS, /home/you on Linux, C:\Users\you on Windows.
  • Absolute paths start at the root and work from anywhere; relative paths start from your working directory (pwd).
  • . is here, .. is the parent folder.
  • Names starting with a dot are hidden (ls -a shows them); .env, .git and .claude matter a lot.
  • Linux is case-sensitive; macOS and Windows normally aren't. Use quotes or Tab completion for names with spaces, and prefer lower-case-with-hyphens names.
Check yourself

You're in /Users/alex/projects. Which absolute path does ../Documents point to?

.. goes up from projects to /Users/alex, then into Documents.

Which of these is an absolute path?

~ expands to the full home path, so it starts from the root. The others depend on where you are.

Why doesn't ls show your project's .env file?

The leading dot is purely a display convention. The file is still readable by any program.

Tests pass on a Mac but fail in Linux CI with "Cannot find module './pages/loginPage'". The file is called LoginPage.ts. What's the likely cause?

The Mac's default filesystem treats both spellings as one file; Linux treats them as different.

What does mkdir My Reports (no quotes) do?

The shell splits at the space, so mkdir receives two names. Quote the name or use a backslash.
