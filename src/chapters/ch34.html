Eight families of models dominate most conversations at work: Anthropic's Claude, OpenAI's GPT, Google's Gemini, xAI's Grok, Meta's Muse (and the older Llama), DeepSeek, Mistral and Alibaba's Qwen. On paper they look more alike every year. Several flagship models now accept around a million tokens of input, most read images, and most can call tools. They differ more in price, in openness, and in where you're allowed to run them. This chapter lines them up side by side using only facts we checked on 9 November 2026. It doesn't declare a winner, because the right model depends on your task, and only your own tests (Chapter 36) can settle that.

34.1Comparing families fairly

A model family is a set of models from one maker that share a name, a design lineage and usually an API. "Claude" is a family. Inside it are tiers (Fable, Opus, Sonnet, Haiku) and versions (5.1, 5.5). When someone says "Claude is better than GPT", they're comparing families. That's usually too vague to be useful. A small, cheap model from one family can lose to the top model of another and still be the right choice for a high-volume job.

In everyday life

Comparing car makers is like this. "Is Toyota better than Volvo?" has no answer until you say which models and what for. A city runabout and a seven-seat estate from the same maker are built for different jobs. You compare a specific car against a specific need: price, boot space, running costs, where you can get it serviced.

These are the dimensions this chapter uses. Each one is something you can check on a vendor's page, not a matter of taste:

Big is not the same as good

A million-token window means the model accepts that much text. It doesn't promise it will use every part equally well, and every token you send is billed. Chapter 20 explains why answers can get worse as the context fills up. For a 200 MB log file, a cheap filtering step (grep, or RAG) before the model usually beats pasting everything in.

Why a "token" is a different size in each family

Each family uses its own tokenizer, the component that cuts text into pieces before the model reads it. The same paragraph can become 100 tokens for one model and 130 for another. Anthropic states that Claude models from 4.7 onwards use a newer tokenizer that produces "approximately 30% more tokens for the same text" than the older one. So "1M tokens" in two families is not exactly the same amount of English, and a price per million tokens isn't directly comparable either (section 34.5). The only fair comparison is to send the same real input to both and read the token counts each API reports. The harness in Chapter 36 does exactly that.

Real-world example

A QA team wants an assistant that watches a 40-second screen recording of a failed checkout and writes the bug report. Of the documented inputs above, only Gemini 4 Argon lists video directly. Three things change the real bill more than the list price:

  1. Tokens per task. Different tokenizers, plus reasoning ("thinking") tokens that are billed as output, mean two models can use very different numbers of tokens for the same job.
  2. Discounts. Anthropic's Batch API is 50% off, and prompt caching makes repeated input much cheaper (an Opus 5.5 cache read is $0.20 per MTok instead of $4). Other vendors have similar schemes with different rules.
  3. Long-prompt tiers. Some prices jump above a threshold (Haiku 5.5 above 100K tokens, Grok above 200K). A log-analysis job can quietly cross that line.
Cloud prices can differ

The same Claude model is available on Amazon Bedrock, Google Cloud and Microsoft Foundry, and Anthropic notes that these platforms set their own prices. If your company buys through a cloud contract, the price list that matters is the one in that contract.

34.6Agentic and coding strength: what can honestly be said

This is the comparison everyone wants and the one that's hardest to make honestly. Every launch post claims top scores on some benchmark. Those claims are self-reported, picked by the vendor, and often measured with different settings (Chapter 33). One widely used coding benchmark, SWE-bench Verified, was dropped by OpenAI in February 2026, which cited contamination and flawed tasks. Opinion · this textbook's authors

For coding and agent work, the harness around the model (how it reads files, runs tests, asks permission and recovers from errors) often matters as much as the model itself. A strong model in a weak harness can lose to a slightly weaker model in a good one. That's one reason to compare complete set-ups on your own repository rather than models on a leaderboard. This is a judgement, not a measured fact.

Why independent leaderboards still disagree

Even independent leaderboards differ, for three reasons. First, settings: a model run at a high effort level with a long time budget can score very differently from the same model on default settings. Second, scaffolding: agent benchmarks such as Terminal-Bench test a model inside a particular harness, and changing the harness changes the score. Third, task mix: a benchmark of Python bug fixes says little about writing Playwright tests in TypeScript against your company's design system. A leaderboard is a decent way to build a shortlist. It's a poor way to make the final choice.

34.7Openness and where each family can run

For many companies this column decides everything else. If security policy says no customer data leaves the building, only open-weight models are in scope, whatever the benchmarks say (Chapter 32).

API only (proprietary)

Claude, GPT, Gemini, Grok and Muse Spark. You send data to the vendor or to a cloud platform that hosts the model. Claude is offered through Anthropic's API and also on Amazon Bedrock, Google Cloud and Microsoft Foundry, which lets a company use an existing cloud contract and region. Gemini runs on Google's own cloud. GPT is served by OpenAI and Microsoft Azure.

Downloadable (open weights)

DeepSeek V4 (MIT), Mistral Large 4 (custom open-weight licence), many Qwen3.8 models (often Apache 2.0), Meta's Muse Glimmer (Apache 2.0) and Llama, and OpenAI's gpt-oss. You can run them on your own hardware. Read each licence: "open weights" doesn't always mean "use however you like". The largest ones (V4-Pro at 1.6T parameters) need serious server hardware.

Common misunderstandings
"The model with the biggest context window is the most capable."
Context size is how much it can read, not how well it reasons. Several flagships share the same 1M figure.
"Cheaper per token means cheaper per task."
Tokenizers differ and reasoning tokens are billed as output. Measure the cost of a real task.
"Meta is the open-weights company."
That was true in the Llama era. Since April 2026 Meta's main Muse models are proprietary, with some open releases such as Muse Glimmer.
"Open weights means open source."
You get the trained numbers, not necessarily the training data or code, and the licence can restrict use (Chapter 32).
"The launch post says it's best at coding, so it is."
Launch benchmarks are self-reported and chosen by the vendor. Use them to build a shortlist, then test.

34.8Review

Key takeaways
  • Compare specific models against a specific need, not families in general.
  • As of 9 November 2026, Claude, GPT, Gemini 4 Argon and Mistral Large 4 all list context windows of about 1M tokens; Grok 4.7 lists 500K.
  • Gemini 4 Argon documents the widest set of inputs (text, image, audio, video, PDF).
  • Prices range from $0.50 to $50 per million output tokens. Tokenizers, thinking tokens, caching, batch discounts and long-prompt tiers change the real bill.
  • Openness often decides first: DeepSeek, Mistral, many Qwen models, Muse Glimmer, Llama and gpt-oss can run in-house; Claude, GPT, Gemini, Grok and Muse Spark can't.
  • No family is "the best". Shortlist from tables like these, then test on your own tasks.
