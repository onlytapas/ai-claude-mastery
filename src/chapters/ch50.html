Every new chat with an AI starts from almost nothing, so people waste time re-explaining who they are and how they like answers. Claude has several ways to carry context forward. Memory saves lasting facts about you and your work. Chat search lets Claude look back through earlier conversations. Instructions are standing rules you write yourself. Projects and skills add context for particular kinds of work. Incognito chats go the other way: nothing is saved to history or memory. Knowing which is which lets you get consistent answers without telling Claude more than you mean to.

In everyday life

Think of starting at a new team. Memory is what a good colleague picks up about you over the weeks ("she prefers tables; she's on the payments squad"). Chat search is them scrolling back through the team channel. Instructions are the note you pinned to your desk ("British spelling, short answers, ask before assuming"). A project is the folder for one client. A skill is the team's how-to page for writing bug reports. Incognito is a conversation in a corridor that nobody writes down.

50.2How memory works today

Memory lets Claude keep useful context about you, such as your role, preferences and ongoing projects, and apply it in new chats. As of 9 November 2026, Anthropic describes it this way:

  • It's stored as topics. Memory is a set of individual topics that update as you chat. (An earlier version wrote a daily summary instead; Anthropic calls that the legacy experience.)
  • Claude saves on its own, or when asked. You can say "remember that our regression suite runs on Thursdays" and it will.
  • It's on by default for Free, Pro, Max and Ultra. On Team and Enterprise, the organisation's Owners decide whether memory is available (section 50.7).
  • Sensitive topics are separate. Memory about sensitive topics needs its own opt-in.

Chat search is a different feature

Chat search lets Claude look through your past conversations when that would help, and it shows each search as a tool call so you can see it happened. When Claude uses an earlier chat, citations link to the original conversation. Chat search needs a paid plan (Pro, Max, Ultra, Team or Enterprise). It works across your non-project chats, and within each project separately. You can turn it off with the Search and reference chats setting.

Memory

A short, curated set of facts. Always available to new chats. You can read and edit it. Small and cheap.

Chat search

Looks up whole past conversations on demand. Finds details memory never saved. Uses more context when it runs.

Real-world example

A tester has spent a month asking Claude about the checkout service. Memory holds: "Works as a QA engineer on the checkout team; uses Playwright with TypeScript; release train every two weeks; prefers test cases as tables." When she asks "write negative tests for the new voucher field", Claude already writes Playwright-flavoured tables. When she asks "what edge cases did we list for gift cards last sprint?", chat search finds the earlier conversation and links to it.

50.3Seeing, editing and controlling memory

As of 9 November 2026 the controls are in Settings > Your Claude. Select Manage next to Your memory. Older layouts and some help pages use different names, so look for "memory" if the path has moved.

Deleting a chat doesn't delete what was learned from it

In the current memory system, deleting a conversation does not remove memory entries that were created from it. If you shared something you regret, delete the chat and check your memory topics for anything that came from it. On mobile, the per-chat memory switch locks once you send the first message, so decide before you type.

Moving memory in and out

Anthropic describes an experimental option to import memories from other AI assistants, or export Claude's memory for backup or migration. Treat imported text as data to review: read what came in and delete anything that's wrong or private before relying on it. Your full data export (Chapter 51) also includes memory.

Why memory is "topics" and not a transcript

A language model has no built-in memory between conversations: each chat starts with whatever text is placed in its context window. "Memory" features are a layer around the model. Some text about you is stored, and the relevant parts are added to the context of new chats.

Storing short topics rather than whole transcripts keeps that added text small, so it doesn't crowd out your actual question, and it lets you inspect and edit exactly what is being carried forward. Chat search is the complementary approach: instead of saving facts up front, it retrieves past conversations when they seem relevant, which is a form of retrieval-augmented generation. Chapter 88 covers this design space for developers, and Claude Code's file-based approach is in Chapter 77.

50.4Project memory: keeping work separate

Each project has its own memory. Inside a project, Claude uses that project's memory plus your general account memory, but not other projects' memory. New memories made in a project are saved to that project.

There's one subtlety: if your account memory is on, Claude can also refer to a project's memories outside that project. To seal a project off completely, turn off Use account memory on the project's page.

Account memoryYour role, general preferences
Project A memoryCheckout service details, used inside Project A
Project B memoryClient X's portal, used inside Project B
Real-world example: consultancy testers

A test consultant works for two clients who must never see each other's details. She creates one project per client and turns off Use account memory in both. Memory learned while testing Client A's mobile app stays in that project; nothing about it can surface in Client B's chats or in her general chats. She also keeps a rule in each project's instructions: "Never mention other clients or projects."

50.5Instructions, skills and the question of styles

Instructions for Claude (account-wide)

This is a block of text you write that applies to every conversation. As of 9 November 2026: select your initials at the lower left, then Settings > Your Claude, and find Instructions. Older layouts call it "Instructions for Claude" under Account, and older guides call the same idea "profile preferences". Anthropic notes that global instructions used in Claude Cowork are now part of this setting.

Good instructions are short, specific and about how you work, not about one task. Compare:

Weak

Instructions
I am a tester. Be helpful and
accurate. Give good answers.

Tells Claude nothing it wouldn't do anyway.

Stronger

Instructions
I'm a QA engineer (web and API testing,
Playwright + TypeScript, Jira).
- Use British spelling.
- Lead with the answer, then the detail.
- Put test cases in a table: ID, title,
  steps, expected result, priority.
- If requirements are ambiguous, list
  the questions before writing tests.
- Say clearly when you're unsure or a
  fact may be out of date.

Keep personal and sensitive details out of instructions. They're applied everywhere, including incognito chats (section 50.6), and they're unnecessary for good answers.

Project instructions and skills

Project instructions apply only inside one project (Chapter 47). Skills are packaged instructions, and sometimes scripts, that Claude uses when a task calls for them (Chapter 80 shows how to build them). Anthropic's personalisation help page now lists exactly three features: account instructions, project instructions and skills. It describes skills as the way to adjust tone and format or add specialised know-how on demand.

What about styles?

Styles were a claude.ai feature that let you choose how Claude writes: preset styles and custom ones you could create by describing a style or giving writing samples. Press coverage at the time reports they launched in late 2024 with presets such as Formal, Concise and Explanatory.

Status unconfirmed as of 9 November 2026

We couldn't confirm that styles are still a current feature. On 9 November 2026, Anthropic's help articles on configuring styles returned "not found", the original announcement page also returned "not found", and the current personalisation article doesn't mention styles. However, the incognito-chat help article still says Claude can access "custom styles" in incognito chats. So styles may have been retired, renamed, or still exist for some accounts or interfaces. If you see a style selector in your interface, it works as described above. If you don't, use account instructions for standing preferences and a skill for a specific format or voice.

Not the same as Claude Code output styles

Claude Code has a separate feature called output styles that changes how Claude Code behaves in the terminal. It's documented and current, and covered in Chapter 84. Don't confuse the two when searching for help.

50.6Incognito chats

An incognito chat is a temporary conversation that isn't saved to your chat history or to memory. It's available on all plans, and Anthropic says incognito chats aren't used for model training.

To start one (web, as of 9 November 2026): outside a project, select the ghost icon at the upper right of a new chat. The chat shows a black border and an Incognito chat label. Close it with the x at the upper right; once closed, it can't be reopened.

Incognito doesIncognito does not
Keep the chat out of your history and out of chat searchDelete it immediately: chats are kept for 30 days by default (longer on Enterprise if the organisation's retention setting says so)
Ignore your existing memory, and add nothing to itIgnore your instructions: Claude can still see your profile information and preferences
Leave it out of your monthly recapWork inside projects (it isn't available there)
Give you a clean slate for a one-off questionHide it from your organisation: on Team and Enterprise, Owners can find incognito chats in data exports, and Enterprise includes them in the Compliance API

Anthropic's help page also notes that in the newer Claude interface, incognito chats open in the previous chat interface, so Claude can't create files or run code in them. An incognito chat can't be turned into a normal one later.

Incognito or "Memory off"?

Inside a project, use the per-chat Memory switch instead (section 50.3): the chat isn't added to memory but stays in your history. Outside projects, incognito is the stronger choice when you don't want the chat in your history at all.

Incognito is not a privacy shield for work data

Incognito changes what Claude remembers and what appears in your history. It doesn't change your company's rules about what data you may paste into an AI tool. Production customer data, credentials and secrets stay out of every chat, incognito or not (Chapter 127).

50.7Team and Enterprise: who controls memory

On work accounts, the organisation decides. As of 9 November 2026:

  • Owners and Primary Owners turn memory on or off for the whole organisation in Organization settings > Capabilities.
  • Whether a member's memory starts on depends on when the organisation was created: Anthropic says organisations created on or after 31 October 2026 start with memory on (unless the member had turned it off before), older ones start with it off until each member turns it on. Some organisation types (HIPAA-enabled, government platform, Claude for Teachers) don't start with memory on.
  • Owners can't turn memory on for one person, and can't see or edit anyone's memories.
  • Turning memory off for the organisation permanently deletes all users' memory data.
  • Memory entries are included in standard conversation exports, and a custom retention period for chats also applies to memory (except project memory) in the newer interface.
Opinion · this book's authors

For QA teams, memory is most useful for stable facts (your stack, your formats) and least useful for things that change every sprint. A quick monthly look at your memory topics, deleting anything stale like "current release is 4.2", keeps answers sharp. Put team-wide rules in a shared project or a skill instead of hoping everyone's memory learns them.

Common misunderstandings
"Deleting a chat removes everything Claude learned from it."
In the current memory system, memory entries made from a chat stay until you delete them yourself.
"Incognito means nobody can ever see the chat."
It's kept for at least 30 days, and on Team and Enterprise, Owners can access incognito chats through data exports.
"Incognito chats ignore my instructions."
They ignore memory, but Claude can still see your profile information and preferences.
"My admin can read my memories."
Owners can switch memory on or off for the organisation but can't view or edit individual memories. (Memory entries are, however, included in standard exports.)
"Styles are the way to set my tone."
Styles may no longer exist. Account instructions and skills are the documented ways to shape tone and format.

50.8Review

Key takeaways
  • Memory saves lasting facts as editable topics; chat search (paid plans) looks up whole past chats on demand.
  • See and edit memory in Settings > Your Claude (as of 9 November 2026). Pause keeps memories; Reset deletes them permanently.
  • Each project has its own memory; turn off "Use account memory" to fully isolate one.
  • Account instructions apply to every chat; keep them short, about how you work, and free of sensitive details.
  • Styles could not be confirmed as current; use instructions and skills instead if you don't see them.
  • Incognito keeps a chat out of history and memory, but it's retained for 30 days and isn't hidden from your organisation.
Check yourself

You told Claude something private in a chat, then deleted the chat. What else should you do?

Deleting a conversation doesn't remove memory entries generated from it in the current system.

You test for two clients and want nothing from one to appear in the other's chats. What's the best set-up?

Projects keep their own memory; turning off account memory seals them. Incognito isn't available inside projects. The instruction adds a second safeguard.

Which statement about incognito chats is true?

Incognito ignores memory and history, is kept for 30 days by default, isn't available in projects, and still applies your profile information.

What's the difference between memory and chat search?

Memory stores topics you can read and edit; chat search retrieves whole earlier chats and needs a paid plan.

You can't find the styles menu. What should you use to make every answer lead with a summary and use tables for test cases?

Styles couldn't be confirmed as current. Instructions apply to every chat, and skills package detailed formats. Output styles are a Claude Code feature.

Assignment

Draft a "personal Claude setup" for your role: (1) account instructions of no more than ten lines; (2) a list of three facts you'd want memory to hold and three you would never want it to hold; (3) a plan for projects, saying which work gets its own project and whether account memory is on; (4) a rule for when you'll use incognito. Use it for a week, then review your memory topics and rewrite anything that made answers worse.

Teach it

"Claude has a few ways to remember. Memory saves short facts about you, and you can read and edit them under Settings, Your Claude. Chat search lets it look back at old chats on paid plans. Instructions are your standing rules, like 'tables for test cases, British spelling'. Projects have their own memory, so client work stays separate. Incognito chats don't go into history or memory, but they're still kept for 30 days and your admin can export them, so it's not a place for secrets. And styles may have been retired; use instructions or skills instead."
